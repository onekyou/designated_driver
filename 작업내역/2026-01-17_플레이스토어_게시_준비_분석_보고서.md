## HIGH (게시 전 수정 필요)

### 4. usesCleartextTraffic = true
**위치:** `call_detector/app/src/main/AndroidManifest.xml`
```xml
android:usesCleartextTraffic="true"
```
**위험:** HTTP 평문 통신 허용 - 중간자 공격에 노출

### 5. allowBackup = true
**영향 앱:** call_detector, driver_app
```xml
android:allowBackup="true"
```
**위험:** 사용자 데이터가 백업으로 노출 가능 (adb backup 공격)

### 6. Exported BroadcastReceiver 보안 취약
**영향 앱:** call_detector, call_manager
```xml
<receiver android:name=".CallReceiver" android:exported="true">
```
**위험:** 외부 앱이 가짜 인텐트로 전화 정보 주입 가능

### 7. Exported CallScreeningService
**영향 앱:** call_detector, call_manager
**위험:** 다른 앱이 전화 스크리닝 서비스에 바인드 가능

### 8. 민감한 권한 사용 정당화 부족

### mediaPlayback 상세 분석
**결론: 완전히 불필요하며 제거해도 앱 로직에 영향 없음**

- AndroidManifest.xml: `dataSync|mediaPlayback` 선언
- CallManagerService.kt (라인 66): `ServiceInfo.FOREGROUND_SERVICE_TYPE_DATA_SYNC`만 사용
- RingtoneManager는 import만 되어 있고 서비스에서 사용 안 함
- 알림 소리는 DashboardScreen과 FCM에서 재생 (mediaPlayback 타입 불필요)

### Phase 4: Firestore Security Rules 강화

**현재 문제점:**
```javascript
// 현재 규칙 (위험)
match /provinces/{provinceId} {
  allow read: if true;  // 누구나 읽기 가능
}

match /{path=**}/designated_drivers/{docId} {
  allow read: if isAuthenticated();  // 로그인된 모든 사용자가 모든 기사 정보 접근
}
```

**수정 계획:**
```javascript
// 개선된 규칙
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // 헬퍼 함수
    function isAuthenticated() {
      return request.auth != null;
    }

    function isOfficeStaff(provinceId, cityId, officeId) {
      // 해당 사무실 직원인지 확인
      return exists(/databases/$(database)/documents/provinces/$(provinceId)/cities/$(cityId)/offices/$(officeId)/staff/$(request.auth.uid));
    }

    // provinces - 회원가입 시에만 읽기 허용
    match /provinces/{provinceId} {
      allow read: if true;  // 사무실 선택을 위해 필요 (최소 정보만 노출)
      allow write: if false;  // 쓰기 금지

      match /cities/{cityId} {
        allow read: if true;
        allow write: if false;

        match /offices/{officeId} {
          allow read: if true;
          allow write: if false;

          // 콜 - 해당 사무실 직원만 접근
          match /calls/{callId} {
            allow read: if isAuthenticated();  // TODO: isOfficeStaff로 강화
            allow create: if isAuthenticated();
            allow update: if isAuthenticated();
          }

          // 기사 - 해당 사무실 직원만 접근
          match /designated_drivers/{driverId} {
            allow read: if isAuthenticated();  // TODO: isOfficeStaff로 강화
            allow write: if isAuthenticated();
          }
        }
      }
    }

    // 고객 포인트 - 본인 데이터만 접근
    match /customerPoints/{docId} {
      allow read: if isAuthenticated();
      allow write: if isAuthenticated();
    }
  }
}
```

**단계적 강화 계획:**
1. **1단계 (즉시)**: 쓰기 권한 제한
2. **2단계 (테스트 후)**: 읽기 권한을 사무실 단위로 제한
3. **3단계 (최종)**: 역할 기반 접근 제어 (RBAC)

**검증 방법:**
1. Firebase 에뮬레이터에서 규칙 테스트
   ```bash
   firebase emulators:start --only firestore
   ```
2. 각 앱에서 데이터 접근 테스트
3. 다른 사무실 데이터 접근 시 권한 거부 확인
4. 비인증 사용자 접근 차단 확인
