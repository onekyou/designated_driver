## 2. 백그라운드 복귀 문제 해결

### 2.1. 문제 설명

**증상:**
1. **간단한 백그라운드 복귀 (앱이 메모리에 살아있을 때):**
   - 앱을 홈 버튼으로 백그라운드로 보냄
   - 다시 앱으로 돌아올 때 웰컴/스플래시 화면으로 돌아감
   - 예상: MainNavigation 화면 유지

2. **앱 재시작 (Android가 프로세스를 종료했을 때):**
   - 프로필 설정 완료 후 앱 사용
   - 백그라운드에서 Android가 앱 프로세스 종료
   - 다시 앱으로 돌아올 때 프로필 설정 화면으로 돌아감
   - 예상: 이미 프로필이 있으므로 MainNavigation으로 바로 이동

---

### 2.2. 해결 방법

#### 문제 1: 간단한 백그라운드 복귀 (✅ 해결됨)

**원인:**
- `DesignatedCustomerApp`이 매번 `AppInitializer`를 home으로 설정
- 초기화가 완료되어도 앱 상태를 추적하지 않음

**해결 방법:**
```dart
// 전역 초기화 상태 Provider 추가 (Line 15)
final appInitializedProvider = StateProvider<bool>((ref) => false);

// DesignatedCustomerApp의 build 메서드 수정 (Lines 41-58)
class DesignatedCustomerApp extends ConsumerWidget {
  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final isInitialized = ref.watch(appInitializedProvider);
    final authState = ref.watch(authNotifierProvider);
    final attributionState = ref.watch(attributionNotifierProvider);

    Widget home;
    // 초기화가 완료되고 인증/Attribution이 있으면 MainNavigation으로
    if (isInitialized &&
        authState.hasValue && authState.value != null &&
        attributionState.hasValue && attributionState.value != null) {
      home = const MainNavigation();
    } else {
      home = const AppInitializer();
    }

    return MaterialApp(
      title: '대리운전 고객',
      theme: AppTheme.lightTheme,
      home: home,
    );
  }
}

// _AppInitializerState에서 초기화 완료 시 상태 업데이트 (Line 124)
ref.read(appInitializedProvider.notifier).state = true;
```

**테스트 결과:** ✅ 앱이 메모리에 있을 때 백그라운드 복귀 정상 작동

#### 문제 2: 앱 재시작 시 프로필 설정 화면 복귀 (✅ 해결됨)

**원인:**
- `appInitializedProvider`는 메모리 내 상태 (StateProvider)
- 앱 프로세스가 종료되면 `false`로 리셋됨
- 재시작 시 다시 전체 초기화 과정을 거침
- Firestore 프로필 체크 실패 → 프로필 설정 화면으로 이동

**해결 방법:**
```dart
// _AppInitializerState._initialize() 메서드 수정 (Lines 79-96)
Future<void> _initialize() async {
  try {
    // ✅ 먼저 SharedPreferences에서 저장된 전화번호 확인
    final storage = StorageService();
    final savedPhoneNumber = await storage.getString("phoneNumber");

    if (savedPhoneNumber != null && savedPhoneNumber.isNotEmpty) {
      // 전화번호가 저장되어 있으면 이미 프로필이 있음
      // → 초기화 과정 스킵하고 바로 MainNavigation으로 이동
      debugPrint("[Initialize] 저장된 전화번호 발견: $savedPhoneNumber");
      if (mounted) {
        Navigator.of(context).pushReplacement(
          MaterialPageRoute(
            builder: (context) => const MainNavigation(),
          ),
        );
      }
      return;  // 여기서 종료
    }

    // 전화번호가 없으면 정상적인 초기화 프로세스 진행
    // 1. 익명 인증
    setState(() => _statusMessage = '인증 중...');
    await _handleAuthentication();

    // 2. Attribution 매칭
    setState(() => _statusMessage = '사무실 정보 확인 중...');
    final attribution = await _handleAttribution();

    // ... (나머지 초기화 코드)
  } catch (e, stackTrace) {
    // 에러 처리
  }
}

// _checkProfile 메서드에서 전화번호 저장 (Lines 218-224)
if (doc.exists) {
  final phoneNumber = doc.data()?['phoneNumber'] as String?;
  if (phoneNumber != null) {
    final storage = StorageService();
    await storage.setString('phoneNumber', phoneNumber);
  }
  // ... lastActiveAt 업데이트
  return true;
}
```

**로직 흐름:**
1. 앱 시작 → `_initialize()` 호출
2. SharedPreferences에서 `phoneNumber` 확인
3. **phoneNumber 있음** → 이미 프로필이 있음 → MainNavigation으로 바로 이동 ✅
4. **phoneNumber 없음** → 신규 사용자 → 정상적인 초기화 프로세스 진행

**저장 시점:**
- `_checkProfile()` 메서드에서 Firestore 프로필이 확인되면 전화번호를 SharedPreferences에 저장
- 이후 앱 재시작 시 이 값을 사용하여 초기화 스킵

**파일 위치:** `designated_customer_flutter/lib/main.dart`

## 7. 주요 기술 개념

### 7.1. Riverpod State Management
- **StateProvider**: 간단한 상태 관리 (appInitializedProvider)
- **ConsumerWidget**: Provider를 읽을 수 있는 Widget
- **ref.watch()**: Provider 값 구독
- **ref.read()**: Provider 값 1회 읽기

### 7.2. SharedPreferences (Persistent Storage)
- 앱 재시작 후에도 데이터 유지
- StorageService로 래핑하여 사용
- 프로필 유무 판단에 전화번호 저장

### 7.3. Firebase
- **Anonymous Auth**: 전화번호 없이 임시 인증
- **Firestore**: 프로필 데이터 저장/조회
- **Path**: `regions/{regionId}/offices/{officeId}/customers/{uid}`

### 7.4. Flutter Navigation
- **Navigator.pushReplacement()**: 현재 화면을 새 화면으로 교체
- **MaterialPageRoute**: 화면 전환 라우트

### 7.5. App Lifecycle
- **Background/Foreground**: 앱이 메모리에 살아있음, 상태 유지
- **Process Death**: Android가 메모리 부족 시 앱 프로세스 종료
- **Cold Start**: 프로세스가 완전히 새로 시작됨

## 9. 문제 해결 가이드

### 문제: 앱이 다시 웰컴 화면으로 돌아감

**체크리스트:**
1. SharedPreferences에 phoneNumber가 저장되어 있는가?
   ```bash
   adb shell "run-as com.designated.designated_customer_flutter cat /data/data/com.designated.designated_customer_flutter/shared_prefs/FlutterSharedPreferences.xml"
   ```

2. `_initialize()` 메서드에서 savedPhoneNumber 확인 로그가 출력되는가?
   ```
   [Initialize] 저장된 전화번호 발견: {phoneNumber}
   ```

3. Firestore 프로필 문서가 존재하는가?
