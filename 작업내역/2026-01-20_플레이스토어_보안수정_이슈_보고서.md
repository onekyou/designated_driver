## 1. 현재 상황 요약

### 1.1 발생한 문제
- call_detector 앱에 보안 수정 적용 후 **기기 설치 실패**
- 오류: `INSTALL_FAILED_VERIFICATION_FAILURE: Install not allowed`
- Samsung 기기 (SM-A325N, SM-G996N) 모두에서 발생

### 1.2 현재 앱 상태

| 앱 | compileSdk | targetSdk | allowBackup | usesCleartextTraffic | 설치 |
|---|---|---|---|---|---|
| call_manager | 36 | 36 | false | 없음 | ✅ 정상 |
| driver_app | 36 | 36 | false | 없음 | ✅ 정상 |
| call_detector | **35** | **35** | **true** | **true** | ✅ 정상 |

**call_detector만 이전 상태로 복구한 상태입니다.**

## 3. 원인 분석

### 3.1 의심되는 원인들

| 변경사항 | 의심도 | 이유 |
|---------|--------|------|
| `targetSdk 36` | **높음** | Android 15의 엄격한 앱 검증 정책 |
| `compileSdk 36` | **높음** | 위와 동일 |
| `allowBackup="false"` | 중 | 앱 서명 검증에 영향 가능 |
| `usesCleartextTraffic` 제거 | 낮음 | 네트워크 설정이라 설치와 무관할 가능성 |

### 3.2 call_detector만 문제인 이유 (추정)

call_detector에만 있는 특수 설정:
1. **Sentry 플러그인** - 소스 코드를 APK에 포함 (`includeSourceContext = true`)
2. **Firebase Crashlytics 플러그인** - 추가 메타데이터 포함
3. **다른 Gradle 플러그인 버전** - `libs.versions` 사용 vs 직접 버전 지정

call_manager/driver_app은 이러한 플러그인이 없어서 동일한 수정에도 문제가 없었을 수 있음.

### 3.3 Samsung 기기 특수성

- Samsung One UI의 **Auto Blocker** 기능이 디버그 APK 검증을 강화
- Android 15 (API 36) 타겟팅 시 더 엄격한 검증 트리거 가능성
- 이전에 작동했던 것은 targetSdk 35였기 때문일 수 있음

## 4. 테스트 안전성 평가

### 현재 상태에서 테스트해도 되는가?

**✅ 기능 테스트는 안전합니다.**

| 항목 | 위험도 | 설명 |
|------|--------|------|
| 앱 기능 동작 | 없음 | 보안 설정은 기능에 영향 없음 |
| Firebase 연동 | 없음 | 정상 작동 |
| 앱 간 통신 | 없음 | 정상 작동 |
| 데이터 보안 | **낮음** | usesCleartextTraffic=true는 HTTP 허용 (현재 HTTPS만 사용 중이라 실질적 위험 없음) |
| 백업 데이터 | **낮음** | allowBackup=true는 기기 백업 시 앱 데이터 포함 (민감 데이터 노출 가능성) |

### 주의사항
- 프로덕션 배포 전에는 반드시 보안 수정 필요
- 현재 상태는 **개발/테스트 용도로만** 사용 권장

## 5. 해결 방안

### 방안 A: 원인 정확히 파악 (권장)
1. targetSdk만 35로 유지, 나머지 보안 수정 적용
2. 빌드 테스트
3. 성공 시 targetSdk 36이 원인으로 확정

### 방안 B: call_detector만 예외 처리
- call_detector: targetSdk 35 유지
- call_manager, driver_app: targetSdk 36 유지
- Play Store는 targetSdk 35도 허용 (2024년 기준)

### 방안 C: Sentry 플러그인 제거 후 테스트
1. Sentry 플러그인 비활성화
2. targetSdk 36으로 빌드 테스트
3. 성공 시 Sentry + targetSdk 36 조합이 원인

### 방안 D: 릴리스 빌드로 테스트
- 디버그 빌드 대신 릴리스 빌드(서명된 APK)로 테스트
- Samsung 보안 정책이 디버그 APK만 차단하는 경우 해결 가능
