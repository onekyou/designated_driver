        Log.e(TAG, "❌ [FCM] 콜 상태 로컬 업데이트 실패", e)

## 현재 상황 및 잔여 문제

### 테스트 결과
✅ **작동함**: 처음 배차 시 내부 호출 목록에 목적지 표시됨
❌ **작동 안 함**: 다시 배차했을 때 작동하지 않음

### 가능한 원인

#### 1. 새 콜 배정 시 타이밍 문제
**시나리오**:
```
1. 새 콜 배정 (ASSIGNED 상태) → destination 없음
2. FCM 수신 → 로컬 DB에 destination = null 저장
3. 기사가 운행 시작 (IN_PROGRESS) → destination 입력
4. FCM 수신 → BUT, 로컬 DB의 해당 콜이 이미 존재하여 업데이트가 제대로 안 됨?
```

#### 2. DAO의 updateCallStatus와 updateDestinationInfo 충돌
**문제**:
```kotlin
// updateCallStatusFromFCM에서:
callDao.updateCallStatus(callId, newStatus, null)  // 먼저 상태만 업데이트

// 그 다음:
if (departure != null || destination != null) {
    callDao.updateDestinationInfo(callId, departure, destination)  // 목적지 업데이트
}
```

- 두 개의 별도 UPDATE 쿼리 실행
- 동시성 문제 가능성?
- 트랜잭션 없음

#### 3. Room DB Flow 갱신 실패
**가능성**:
- `callDao.updateDestinationInfo()`가 실행되어도 Flow가 emit하지 않음
- UI가 Flow를 다시 구독하지 않음

#### 4. FCM 메시지 타입 확인 필요
**확인 필요**:
- `CALL_STATUS_UPDATE`가 모든 상태 변경 시 전송되는가?
- `ASSIGNED` → `ACCEPTED` → `IN_PROGRESS` 각각에서 FCM이 오는가?

#### 5. 로컬 DB의 departure/destination 필드명 불일치
**CallEntity (Room DB)**:
- 필드명이 `departure`, `destination`인가?
- 아니면 `departure_set`, `destination_set`인가?

**확인 필요**:
```kotlin
@Entity(tableName = "calls")
data class CallEntity(
    ...
    val departure: String? = null,      // 이 필드명이 맞나?
    val destination: String? = null,    // 이 필드명이 맞나?
    ...
)
```
