### 2. 단일 페이지 클라이언트 라우팅 구현
**파일:** `customer_app/landing/app/page.tsx`

**이유:**
- Dynamic route `[regionId]/[officeId]`는 `generateStaticParams` 필요
- 하지만 FingerprintJS는 클라이언트에서만 작동 (`'use client'` 필요)
- 두 개를 함께 쓸 수 없어서 클라이언트 라우팅 방식 선택

**구현 방식:**
```typescript
useEffect(() => {
  const path = window.location.pathname
  const parts = path.split('/').filter(p => p)
  if (parts.length >= 2) {
    setRegionId(parts[0])
    setOfficeId(parts[1])
  }
}, [])
```

**장점:**
- 새 사무실 추가 시 재배포 불필요
- SEO 불필요 (QR 코드로만 접근)
- 파일 크기 작음

### 6. QR 코드 화면 표시 구현
**문제:** QR 코드 관리 페이지에 QR 이미지가 안 보임 (다운로드는 됨)

**해결:**
1. **ViewModel 수정** (`AttributionManagementViewModel.kt`):
   - `qrCodeBitmap` StateFlow 추가
   - `loadOfficeSettings()` 시 QR URL로 Bitmap 생성

2. **Screen 수정** (`AttributionManagementScreen.kt`):
   - `qrCodeBitmap` 파라미터 추가
   - `Image(bitmap = qrCodeBitmap.asImageBitmap())` 표시

```kotlin
// ViewModel
private val _qrCodeBitmap = MutableStateFlow<Bitmap?>(null)
val qrCodeBitmap = _qrCodeBitmap.asStateFlow()

// loadOfficeSettings()에서
if (settings.qrCode.isNotEmpty()) {
    withContext(Dispatchers.Default) {
        val bitmap = QRCodeGenerator.generateQRCodeBitmap(settings.qrCode, 512)
        _qrCodeBitmap.value = bitmap
    }
}

// Screen
if (qrCodeBitmap != null) {
    Image(
        bitmap = qrCodeBitmap.asImageBitmap(),
        contentDescription = "QR 코드",
        modifier = Modifier.fillMaxSize()
    )
}
```

## 미해결 문제 ⚠️

### 문제: "잘못된 접근입니다. 올바른 QR 코드를 스캔해주세요" 메시지

**증상:**
- QR 코드 스캔 → 랜딩페이지 열림
- "앱 다운로드" 버튼 클릭 → "잘못된 접근입니다" 메시지 표시

**원인 추정:**
1. **URL 파싱 실패:** `window.location.pathname`이 예상과 다른 값일 수 있음
2. **Firebase Hosting Rewrite 문제:** `/regionId/officeId` → `/index.html` 전달 안 됨
3. **Next.js Static Export 문제:** 클라이언트 라우팅이 제대로 작동 안 함

**디버깅 추가:**
```typescript
console.log('Current pathname:', path)
console.log('Parsed parts:', parts)
console.log('Setting regionId:', parts[0], 'officeId:', parts[1])
```

**확인 필요:**
1. 실제 QR 코드 URL이 정확한지 (Firebase Console에서 확인)
2. 모바일 브라우저 콘솔 로그 (Chrome Remote Debugging)
3. Firebase Hosting에서 실제 요청 로그 확인

### 3. Attribution 시스템 테스트
현재는 랜딩페이지 접근 실패로 핑거프린트 수집도 안 됨.

**정상 플로우:**
1. QR 스캔 → 랜딩페이지 로드
2. FingerprintJS로 디바이스 정보 수집
3. Firebase `regions/{regionId}/offices/{officeId}/attributions` 저장
4. 고객이 앱 다운로드 → 앱에서 같은 핑거프린트 생성
5. Attribution 매칭 (콜매니저에서 확인)
