# FCM 데이터 메시지 시스템 자동 처리 교훈

**작업일**: 2025년 1월 12일

**문제**: data-only FCM 메시지인데 시스템이 자동으로 알림을 띄우는 현상  

---

## 🎯 핵심 발견사항

### 실제 원인: 메시지가 "알림 메시지"로 분류되고 있었음
우리가 data-only로 보낸다고 생각했지만, 실제로는 다음 이유들로 **알림 메시지로 판정**되고 있었음:

1. **숨겨진 notification 블록 존재**
2. **예약 키 사용으로 인한 자동 해석**
3. **중간 게이트웨이/SDK의 payload 변형**

---

## 📚 전문가 분석에서 배운 핵심 교훈

### 1. FCM 메시지 분류 규칙의 이해

#### ✅ 진짜 data-only 메시지
```typescript
const message = {
  data: {
    type: 'TRIP_STARTED',
    title: '제목',     // 일반 키 이름은 문제없음
    body: '내용',      
  },
  android: {
    priority: 'high',
  },
  tokens: ['...'],
};
```

#### ❌ 알림으로 오해받는 케이스들
```typescript
// 1. notification 블록이 어딘가에 포함된 경우
{
  notification: { ... },  // 최상위
  android: { notification: { ... } },  // 안드로이드 하위
}

// 2. 예약 키 사용
{
  data: {
    "gcm.notification.title": "제목",  // 예약 키!
    "google.something": "값",          // google.* 접두사
  }
}

// 3. 서드파티 서비스가 변형한 경우
// SNS, 마케팅 툴 등이 data-only를 알림+데이터로 변경
```

### 2. Android 13+ 변화의 정확한 이해

#### POST_NOTIFICATIONS 런타임 권한
```
❌ 잘못된 이해: "FCM 메시지 분류가 바뀌었다"
✅ 올바른 이해: "앱이 직접 띄우는 알림의 표시 권한이 필요해졌다"
```

- **메시지 분류 규칙**: 변경 없음 (알림=OS 표시, 데이터=앱 콜백)
- **변경된 것**: 앱이 직접 생성하는 알림의 표시 권한
- **onMessageReceived() 호출**: 권한과 무관하게 데이터 메시지면 호출됨

### 3. 시스템 자동 알림의 정체

#### 언제 시스템이 자동으로 알림을 띄우는가?
1. **알림 메시지로 분류된 경우** (앱이 백그라운드일 때)
2. **예약 키가 포함된 데이터 메시지**
3. **Firebase 콘솔이나 서드파티 서비스 경유 메시지**

#### 우리 상황 분석
```
현상: data-only인데 시스템이 알림 표시 + onMessageReceived() 미호출
진단: 실제로는 "알림 메시지"로 분류되고 있음
원인: 메시지 구조에 숨겨진 notification 요소나 예약키 존재 가능성
```

## 🚨 주의사항 및 함정들

### 1. "data-only"라는 착각
```
❌ 착각: "data 필드만 있으니까 data-only다"
✅ 현실: "시스템이 알림으로 판정하면 notification 처리됨"

해결: 실제 전송되는 JSON과 수신되는 로그를 모두 확인
```

### 2. Android 버전별 차이
```
Android 13+: POST_NOTIFICATIONS 권한 필요
Android 12+: 알림 트램펄린 제약
Android 8+:  채널 기반 알림

각 버전별로 다른 동작 가능성 고려 필요
```

### 3. 제조사별 FCM 처리 차이
```
삼성, 샤오미, OPPO: 자체 최적화로 FCM 동작 변경 가능
Doze/App Standby: HIGH priority여도 지연 가능성
화웨이: Google Play 서비스 없음
```

### 4. 개발 vs 프로덕션 환경 차이
```
개발: Firebase 콘솔 테스트 → 항상 알림 메시지
프로덕션: 서버 직접 전송 → data-only 가능

환경별로 다른 결과 가능성 주의
```

### 2. FCM 메시지 구조 검증
```typescript
// 전송 전 검증 함수
function validateDataOnlyMessage(message: any) {
    // notification 필드 존재 검사
    if (message.notification || message.android?.notification) {
        throw new Error('notification 필드 발견!');
    }
    
    // 예약키 검사
    for (const key in message.data) {
        if (key.startsWith('gcm.') || key.startsWith('google.')) {
            throw new Error(`예약키 사용: ${key}`);
        }
    }
    
    return true;
}
```
