## 데이터 흐름 정리

### Firestore 데이터 구조
```
calls/{callId}/
  ├── departure_set: "용문면 212-3"      ← 기사가 입력한 출발지
  ├── destination_set: "시장"            ← 기사가 입력한 목적지
  ├── fare_set: 15000                    ← 기사가 입력한 요금
  ├── departure: null                    ← 사용 안 함
  ├── destination: null                  ← 사용 안 함
  └── fare: 15000                        ← 정산 시 사용
```

### FCM 메시지 흐름

1. **기사가 운행 시작 버튼 클릭**
   - Driver App → Firestore: `departure_set`, `destination_set`, `fare_set` 저장
   - Firestore → Cloud Functions: `onCallStatusChanged` 트리거

2. **Cloud Functions → FCM 전송 (2종류)**

   **A. CALL_STATUS_UPDATE** (내부호출목록용)
   ```json
   {
     "type": "CALL_STATUS_UPDATE",
     "callId": "xxx",
     "status": "IN_PROGRESS",
     "departure": "용문면 212-3",
     "destination": "시장",
     ...
   }
   ```

   **B. STATUS_CHANGE** (팝업용)
   ```json
   {
     "type": "STATUS_CHANGE",
     "callId": "xxx",
     "statusText": "운행 시작",
     "departure": "용문면 212-3",
     "destination": "시장",
     "fare": "15000"
   }
   ```

3. **Call Manager → 로컬 DB 업데이트 및 UI 표시**
   - CALL_STATUS_UPDATE → `updateCallStatusFromFCM()` → `updateDestinationInfo()` → `departure_set`, `destination_set` 업데이트 → 내부호출목록 표시
   - STATUS_CHANGE → `handleStatusChange()` → 팝업 알림 표시

## 참고 사항

### 필드 네이밍 규칙
- `_set` 접미사: 기사가 운행 시작 시 입력한 값 (변경 불가)
- 일반 필드: 시스템이 관리하거나 정산 시 사용

### FCM 메시지 타입
- `CALL_STATUS_UPDATE`: 콜 상태 변경 시 전송, 내부호출목록 업데이트용
- `STATUS_CHANGE`: 운행 시작/완료 시 전송, 팝업 알림용
- `DRIVER_STATUS_UPDATE`: 기사 상태 변경 시 전송, 기사 카드 업데이트용

### 토큰 저장 위치
- `regions/{regionId}/offices/{officeId}/managerTokens/{tokenId}`
- 각 문서에 `fcmToken` 필드 포함
