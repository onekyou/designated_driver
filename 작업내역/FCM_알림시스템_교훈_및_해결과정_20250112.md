# FCM 알림 시스템 구현 교훈 및 해결 과정

**작업일**: 2025년 1월 12일  
**목표**: 공유콜은 큰 알람소리, 운행상태는 기본 알림음으로 분리  
**결과**: ✅ 성공적으로 해결  

---

## 🎯 최종 해결책 요약

### 구현 방식
- **공유콜 알림**: FCM + 명시적 알람소리 (기존 유지)
- **운행상태 알림**: Firestore 리스너 + 기본 알림음 (새로 구현)

### 핵심 원리
1. **FCM 이중처리 문제**: FCM 메시지가 앱과 시스템에서 동시 처리되어 원하지 않는 소리 발생
2. **Firestore 리스너 활용**: 실시간 데이터 변경 감지로 FCM 없이도 알림 구현 가능
3. **명시적 소리 설정**: 채널 설정보다 개별 알림의 명시적 소리 설정이 더 확실함

## 🔍 문제 분석 과정

### 1단계: 초기 문제 상황
```
문제: 운행 시작/완료 알림이 기본 알림음 대신 벨소리로 재생
현상: 공유콜(정상) vs 운행상태(문제)
```

### 2단계: 시도한 해결방법들 (모두 실패)
1. **Android 채널별 설정 분리**
   ```kotlin
   when (channelId) {
       STATUS_CHANGE_CHANNEL_ID -> {
           Triple(
               NotificationCompat.PRIORITY_DEFAULT,
               NotificationCompat.CATEGORY_STATUS,
               NotificationCompat.DEFAULT_VIBRATE or NotificationCompat.DEFAULT_LIGHTS
           )
       }
   }
   ```
   **결과**: ❌ 벨소리 지속

2. **FCM 우선순위 변경**
   ```typescript
   android: {
       priority: "normal" as const,  // high → normal
   }
   ```
   **결과**: ❌ 벨소리 지속

3. **FCM 데이터 키 변경**
   ```typescript
   // alertTitle, alertMessage → notificationTitle, notificationMessage
   data: {
       notificationTitle: "🚗 운행이 시작되었습니다",
       notificationMessage: `${driverName} - ${tripSummary}`,
   }
   ```
   **결과**: ❌ 벨소리 지속

4. **채널 소리 무음 테스트**
   ```kotlin
   setSound(null, null)  // 채널을 무음으로 설정
   ```
   **결과**: ❌ 여전히 벨소리 재생 → **시스템이 우리 채널을 무시함을 확인**

### 3단계: 근본 원인 발견
- **FCM 메시지 이중 처리**: 앱에서 처리 + Android 시스템에서 자동 처리
- **시스템 자동 처리**: 특정 조건에서 높은 우선순위로 해석되어 벨소리 재생
- **채널 설정 무시**: 시스템 처리 시 앱의 채널 설정이 적용되지 않음

## 💡 핵심 교훈

### 1. FCM vs Firestore 리스너 선택 기준

| 방식 | 장점 | 단점 | 적합한 사용처 |
|------|------|------|--------------|
| **FCM** | • 앱이 종료되어도 알림<br>• 푸시 알림 표준<br>• 다양한 플랫폼 지원 | • 시스템 자동처리로 제어 어려움<br>• 이중처리 위험<br>• 소리 제어 복잡 | • 긴급 알림 (공유콜)<br>• 외부 트리거 알림 |
| **Firestore 리스너** | • 완전한 제어 가능<br>• 실시간 동기화<br>• 앱 내 상태와 일관성 | • 앱이 활성화되어야 작동<br>• 배터리 사용량 증가 | • 앱 내 상태 알림<br>• 세밀한 제어가 필요한 알림 |

### 2. 알림 소리 제어 방법

#### ❌ 실패한 방법들
```kotlin
// 1. 채널 소리 설정만으로는 불충분
NotificationChannel().apply {
    setSound(Settings.System.DEFAULT_NOTIFICATION_URI, audioAttributes)
}

// 2. FCM priority 변경만으로는 해결 안됨
android: { priority: "normal" }

// 3. 채널 카테고리/우선순위만으로는 한계
.setPriority(NotificationCompat.PRIORITY_DEFAULT)
.setCategory(NotificationCompat.CATEGORY_STATUS)
```

#### ✅ 성공한 방법
```kotlin
// 명시적 소리 설정 (개별 알림에서)
NotificationCompat.Builder(context, channelId)
    .setSound(Settings.System.DEFAULT_NOTIFICATION_URI)  // 명시적 설정
    .setDefaults(NotificationCompat.DEFAULT_VIBRATE or NotificationCompat.DEFAULT_LIGHTS)
```

### 3. 디버깅 핵심 포인트

#### 로그 분석 순서
1. **FCM 수신 확인**: `onMessageReceived()` 호출 여부
2. **시스템 처리 확인**: FCM 메시지 수신 후 추가 로그 발생 여부
3. **리스너 작동 확인**: Firestore 리스너 트리거 여부
4. **시간 조건 확인**: `isRecentStatusChange` 등 조건문 통과 여부

#### 필수 로그 패턴
```kotlin
// 1. 리스너 트리거 확인
Log.d(TAG, "📞 Firestore listener triggered: ${changes.size} changes")

// 2. 문서 변경 상세 추적
Log.d(TAG, "📞 [DEBUG] Processing document change: ${dc.type}, docId: ${doc.id}")

// 3. 상태 변경 감지
Log.d(TAG, "📞 [DEBUG] 상태 체크 - Current: ${status}, Previous: ${previousStatus}")

// 4. 조건 통과 여부
Log.d(TAG, "🚗 Trip started - Is recent: $isRecentStatusChange")

// 5. 알림 호출 추적
Log.d(TAG, "🔔 [NOTIFICATION] 알림 호출 시작")
```

## 🚨 주의사항 및 함정

### 1. FCM 시스템 자동처리 함정
```
⚠️ FCM 메시지가 data-only라고 해서 시스템이 처리하지 않는 것이 아님
⚠️ 특정 키나 조건에서 시스템이 자동으로 알림을 생성할 수 있음
⚠️ 앱의 채널 설정이 시스템 자동처리 시 적용되지 않을 수 있음
```

**해결책**: 중요하지 않거나 소리 제어가 필요한 알림은 FCM 대신 Firestore 리스너 사용

### 2. 시간 기반 필터링 함정
```kotlin
// 이런 로직은 디버깅을 어렵게 만듦
val isRecentStatusChange = (statusChangeTime > appStartTime - POPUP_TIME_THRESHOLD_MS)
if (isRecentStatusChange) {  // 이 조건 때문에 팝업이 안 나올 수 있음
    showPopup()
}
```

**해결책**: 디버깅 시에는 시간 조건을 임시로 비활성화하여 로직 흐름 확인

### 3. 로그 필터링 함정
```bash
# 잘못된 필터링으로 로그를 놓칠 수 있음
adb logcat -s MyApp  # TAG가 다르면 안 보임

# 정확한 필터링
adb logcat -s DashboardViewModel
# 또는
adb logcat | grep -i dashboard
```

### 4. 알림 생성 함수
```kotlin
private fun showTripStatusNotification(title: String, content: String, bigText: String, notificationId: Int) {
    // 채널 생성 (기본 알림음 설정)
    val channel = NotificationChannel(channelId, "운행 상태 알림", NotificationManager.IMPORTANCE_DEFAULT).apply {
        setSound(Settings.System.DEFAULT_NOTIFICATION_URI, audioAttributes)
    }
    
    // 알림 생성 (명시적 소리 설정)
    val notification = NotificationCompat.Builder(context, channelId)
        .setSmallIcon(R.drawable.ic_launcher_foreground)
        .setContentTitle(title)
        .setContentText(content)
        .setSound(Settings.System.DEFAULT_NOTIFICATION_URI)  // 명시적 설정
        .build()
        
    notificationManager.notify(notificationId, notification)
}
```
