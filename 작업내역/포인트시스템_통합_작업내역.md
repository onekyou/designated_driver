# 포인트 시스템 통합 작업내역

## 작업 일자
2025-11-08

## 작업 개요
포인트 시스템의 등급 정의가 고객앱과 기사앱에 중복되어 있고, 값도 달라서 혼란을 야기했습니다.
**고객앱의 등급 정의를 기준**으로 통일하여 일관성을 확보했습니다.

---

## 문제점 분석

### 1. 등급 정의 중복
- **고객앱** (CustomerGrade.kt): 3%, 5%, 7%, 9% (4등급)
- **기사앱** (DriverViewModel.kt): 1%, 2%, 3%, 4%, 5% (5등급) - 하드코딩

→ 등급이 2곳에 정의되어 있고, 값도 달라서 유지보수 어려움

### 2. UI에 하드코딩
- **CallHistoryViewModel.kt**: 1%, 2%, 3%, 5% 하드코딩
- **CallHistoryScreen.kt**: 1%, 2%, 3%, 5% 하드코딩

→ CustomerGrade.kt와 다른 값 사용 (3-9% vs 1-5%)

### 3. 실제 포인트 적립 처리
- **기사앱**이 실제 포인트를 적립 (DriverViewModel.processCustomerPoints)
- 하지만 고객앱과 다른 적립률 사용 (1-5% vs 3-9%)

---

## 해결 방법

### 원칙
**"고객 등급은 고객앱에만 정의"**
- 고객앱 CustomerGrade.kt를 유일한 진실의 원천으로 설정
- 기사앱은 고객앱의 등급 기준을 따름

### 적용한 등급 체계 (고객앱 기준)

| 등급 | 아이콘 | 적립률 | 기준 |
|------|--------|--------|------|
| 브론즈 | 🥉 | 3% | 0회 이상 |
| 실버 | 🥈 | 5% | 10회 이상 |
| 골드 | 🥇 | 7% | 30회 이상 |
| VIP | ⭐ | 9% | 50회 이상 |

## 영향 범위

### 1. 기존 고객 데이터
**Firebase `customerPoints` 컬렉션**:
- `grade` 필드: "BRONZE", "SILVER", "GOLD", "VIP"
- PLATINUM, DIAMOND 등급 데이터가 있다면 VIP로 자동 변환됨

**마이그레이션 필요 여부**:
- ❌ 불필요: 기존 데이터는 그대로 유지
- ✅ 하위 호환성: CustomerGrade.fromString("PLATINUM") → VIP 자동 변환 (라인 74)

### 2. 포인트 적립
**변경 전**:
- 브론즈 고객이 30,000원 이용 → 300포인트 적립 (1%)

**변경 후**:
- 브론즈 고객이 30,000원 이용 → 900포인트 적립 (3%)

**⚠️ 주의**: 적립률이 3배 증가하므로 기존 고객에게 유리

### 3. 등급 승급
**변경 전**:
- 20회 이용 → GOLD
- 50회 이용 → PLATINUM
- 100회 이용 → DIAMOND

**변경 후**:
- 30회 이용 → GOLD
- 50회 이용 → VIP (최고 등급)

**⚠️ 주의**:
- 20~29회 고객: GOLD → SILVER 강등
- 50~99회 고객: PLATINUM → VIP 변경
- 100회 이상 고객: DIAMOND → VIP 변경

## 향후 개선 사항 (선택)

### Firebase에 pointRate 저장
**현재 구조**:
```
customerPoints/
  ├─ grade: "GOLD"
  └─ currentPoints: 5000
```

**개선 구조**:
```
customerPoints/
  ├─ grade: "GOLD"
  ├─ pointRate: 0.07  ← 추가
  └─ currentPoints: 5000
```

**장점**:
- 고객앱에서 등급 변경 시 pointRate도 함께 저장
- 기사앱은 Firebase에서 pointRate 읽어오기만 하면 됨
- 등급 로직이 고객앱에만 존재

**단점**:
- Firebase 구조 변경 필요
- 고객앱 수정 필요 (등급 업데이트 시 pointRate 저장)
- 기존 데이터 마이그레이션 필요

**우선순위**: 낮음 (현재 구조로도 충분)

## 주의사항

### 1. 적립률 증가
- 기존 1-5% → 3-9%로 증가
- 포인트 지출이 3배 증가할 수 있음
- 비즈니스 모델 검토 필요

### 2. 등급 기준 변경
- GOLD: 20회 → 30회 (더 어려워짐)
- 20~29회 고객이 SILVER로 강등될 수 있음
- 고객 안내 필요

### 3. 고객앱과 기사앱 동시 업데이트
- 두 앱을 동시에 배포해야 함
- 한쪽만 업데이트 시 불일치 발생 가능
