## 1. 콜디텍터 (Call Detector)

### CRITICAL (즉시 해결 필요)

#### 1.1 FCM 알림 시스템 미구현
- **문제**: 콜디텍터에 `MyFirebaseMessagingService`가 없음
- **영향**: 콜매니저로 콜 알림 전달 불가. 콜디텍터에서 콜 생성해도 콜매니저가 모름
- **위치**: 앱 전체
- **해결**: Cloud Functions에서 콜 생성 시 FCM 발송하거나, 콜디텍터에 FCM 서비스 추가

#### 1.2 배차 팝업 중복 (역할 혼동)
- **문제**: 콜디텍터 내 `DispatchActivity`에서 직접 배차 가능
- **영향**: 매뉴얼에서는 콜매니저가 배차 담당인데, 콜디텍터에서도 배차 가능 → 역할 혼동
- **위치**: `CallDetectorService.kt` L763-770, `DispatchActivity.kt`
- **해결**: 콜디텍터는 콜 생성만 담당, 배차는 콜매니저로 일원화

#### 1.3 Firebase 업로드 실패 시 임시 ID 문제
- **문제**: Firebase 업로드 실패 → `temp_` prefix 임시 ID 생성 → 이 ID로 배차 시도
- **영향**: Firebase에 해당 문서 없으므로 배차 update 실패. 기사가 콜 못 받음
- **위치**: `CallDetectorService.kt` L775-787
- **해결**: 업로드 실패 시 재시도 로직 또는 사용자에게 실패 알림

### HIGH (우선 해결 권장)

#### 1.4 권한 체크 후 서비스 조기 중단
- **문제**: `onCreate()`에서 권한 없으면 즉시 `stopSelf()` 호출
- **영향**: `startForegroundService()` 호출했는데 즉시 중단 → Android 12+에서 문제
- **위치**: `CallDetectorService.kt` L69-77

#### 1.5 Race Condition (staticSavedNumber)
- **문제**: IDLE 상태 후 1초 대기 중 새 전화 오면 정보 섞임
- **영향**: 빠른 연속 호출 시 전화 정보 손실 또는 혼합
- **위치**: `CallReceiver.kt` L105-119

#### 1.6 공유콜 생성 후 검증 없음
- **문제**: `shared_calls` 저장 후 성공 로그만 남김. FCM 발송 여부 확인 불가
- **영향**: 마감 시 공유콜이 다른 사무실에 전달 안 될 수 있음
- **위치**: `CallDetectorService.kt` L892-941

#### 1.7 마감 시 SMS 발송 비활성화
- **문제**: SMS 발송 코드 전체 주석 처리, FCM 대체라고 했지만 FCM도 미구현
- **영향**: 마감 시 고객에게 아무 응답 없이 전화 끊김
- **위치**: `CallDetectorService.kt` L833-859

#### 1.8 CallScreeningService 초기화 타이밍
- **문제**: IDLE 이벤트 처리 시 `latestIncomingNumber`가 아직 clear 안 됨
- **영향**: 연속 전화 시 이전 번호 정보가 남아있을 수 있음
- **위치**: `CallReceiver.kt` L114-116

### MEDIUM

- 연락처 조회 권한 없을 때 고객 이름 공백 표시
- Full-Screen Intent 권한 체크 불완전
- 앱 회원 조회 시 Firestore 예외 처리 없음
- 디버그 로그가 프로덕션에서도 출력
- 권한 과다 (SYSTEM_ALERT_WINDOW + USE_FULL_SCREEN_INTENT 모두 선언)

## 2. 콜매니저 (Call Manager)

### CRITICAL (즉시 해결 필요)

#### 2.1 Firestore 리스너 누수 (Memory Leak)
- **문제**: `onCleared()` 메서드 없음. 리스너 정리 안 됨
- **영향**: 메모리 누수, 앱 장시간 사용 시 성능 저하
- **위치**: `DashboardViewModel.kt` L242-246
- **해결**: ViewModel의 `onCleared()`에서 모든 리스너 정리

#### 2.2 낙관적 업데이트 실패 처리 없음
- **문제**: 로컬 DB 먼저 업데이트 후 Firebase 업데이트. Firebase 실패 시 불일치
- **영향**: 배차 정보가 로컬은 업데이트되지만 서버는 안 됨
- **위치**: `CallRepository.kt` L315-334
- **해결**: Firebase 실패 시 retry 또는 로컬 DB rollback

### HIGH (우선 해결 권장)

#### 2.3 FCM 토큰 저장 Race Condition
- **문제**: 2-Phase Commit 방식인데 앱 재시작 시 불완전 상태 가능
- **영향**: `managerTokens`가 저장 안 되면 FCM 알림 못 받음
- **위치**: `MyFirebaseMessagingService.kt` L184-213

#### 2.4 공유 콜 필터링 NPE 위험
- **문제**: `CLAIMED` 상태에서 `claimedOfficeId`가 null이면 NPE
- **영향**: 앱 크래시
- **위치**: `DashboardViewModel.kt` L313-374
- **해결**: null 체크 강화

#### 2.5 삭제된 콜 목록 100개 초과 시 전체 초기화
- **문제**: 101번째 삭제부터 이전 삭제 기록 모두 손실
- **영향**: 이미 삭제한 콜이 다시 표시될 수 있음
- **위치**: `CallRepository.kt` L68-75
- **해결**: LRU 캐시 또는 타임스탬프 기반 정리

#### 2.6 포그라운드 상태 판별 오류
- **문제**: `runningAppProcesses`는 API 26+에서 자신 프로세스만 반환
- **영향**: 포그라운드/백그라운드 판별 부정확
- **위치**: `MyFirebaseMessagingService.kt` L1063-1073

#### 2.7 1시간 필터로 오래된 콜 사라짐
- **문제**: 1시간 이상 된 콜 필터링
- **영향**: ASSIGNED 상태인데 1시간 이상 걸린 콜은 화면에서 사라짐
- **위치**: `CallRepository.kt` L86-95

### MEDIUM

- Timestamp 형식 불일치 (Firestore Timestamp vs Long 혼용)
- 운행 완료 팝업 중복 표시 가능성
- 알림 채널 버전 하드코딩 (v3)
- SharedPreferences 비동기 업데이트 지연
- 기사 OFFLINE 상태에서도 배차 가능
- 콜디텍터에서 생성한 콜(`fromCallDetector == true`) 팝업 안 됨

### LOW

- DEBUG 로그 과다
- 개발용 `println()` 로그 미제거

## 3. 기사앱 (Driver App)

### CRITICAL (즉시 해결 필요)

#### 3.1 상태 전환 불일치
- **문제**: 매뉴얼과 코드의 상태값 불일치
  - 매뉴얼: `WAITING → ASSIGNED → ACCEPTED → IN_PROGRESS → AWAITING_SETTLEMENT → COMPLETED`
  - 코드: `PREPARING` 상태 사용 (매뉴얼에 없음)
  - `CANCELLED_BY_DRIVER`, `HOLD` 상태는 Constants에 미정의
- **영향**: 다른 앱/Cloud Functions와 상태 동기화 실패
- **위치**: `DriverViewModel.kt` L328-465
- **해결**: 상태값 정규화 및 Constants 정리

### HIGH (우선 해결 권장)

#### 3.2 FCM 수신 시 상태 검증 없음
- **문제**: `callId`만으로 배차 팝업 표시. Firestore에서 콜 상태 미확인
- **영향**: 이미 수락/진행 중인 콜에 대해 다시 팝업 표시
- **위치**: `MyFirebaseMessagingService.kt` L76-112

#### 3.3 포인트 중복 처리 가능성
- **문제**: 트랜잭션 시작 전 중복 체크. Race condition 존재
- **영향**: 동일 콜에 포인트 2회 적립 가능
- **위치**: `DriverViewModel.kt` L1021-1043
- **해결**: 트랜잭션 내에서 중복 체크

#### 3.4 Cloud Function 실패 시 정산 데이터 고아 상태
- **문제**: 정산 저장 후 Cloud Function이 `settlementSessions` 생성 가정. 실패 시 처리 없음
- **영향**: 기사는 정산 완료로 보이지만 콜매니저에서 확인 불가
- **위치**: `DriverViewModel.kt` L607-647

#### 3.5 포인트 적립률 하드코딩
- **문제**: 적립률이 코드에 고정 (BRONZE 3%, SILVER 5% 등)
- **영향**: 운영 중 적립률 변경 불가
- **위치**: `DriverViewModel.kt` L1060-1066
- **해결**: Firestore에서 동적 로드

#### 3.6 네트워크 오류 시 UI 상태 불일치
- **문제**: 로컬 UI 먼저 업데이트 후 Firestore 업데이트. 실패 시 불일치
- **영향**: 사용자에게 혼란 (콜 수락했다고 보이지만 서버는 안 됨)
- **위치**: `DriverViewModel.kt` L328-403

### MEDIUM

- AWAITING_SETTLEMENT 상태에서 기사 상태 미설정
- CallInfo 모델 필드 null 체크 부족
- 결제 방법 하드코딩된 문자열 ("현금", "외상" 등)
- 요금 0원 운행 가능
- SharedPreferences 키 분산 관리
- Trip History 타임스탬프 동기화 문제
- performFirestoreUpdate() 에러 처리 너무 광범위

### LOW

- 과도한 로그 출력 (스택 트레이스 포함)
- rejectCall() 메서드 미구현
- TripPreparationScreen 객체 재생성

## 4. 앱 간 연동 문제

### 4.1 FCM 알림 체계 불완전
```
매뉴얼 기대:
콜디텍터 → Firebase 저장 → Cloud Functions → FCM → 콜매니저

현재 상태:
콜디텍터 → Firebase 저장 (끝)
콜매니저는 Firestore 리스너로만 감지
```

### 4.2 콜 상태 정의 불일치
| 상태 | 콜디텍터 | 콜매니저 | 기사앱 | 매뉴얼 |
|------|----------|----------|--------|--------|
| WAITING | O | O | O | O |
| ASSIGNED | O | O | O | O |
| ACCEPTED | X | O | O | O |
| PREPARING | X | X | O | X |
| IN_PROGRESS | O | O | O | O |
| AWAITING_SETTLEMENT | X | O | O | O |
| COMPLETED | O | O | O | O |
| HOLD | X | X | O | X |
| CANCELLED_BY_DRIVER | X | X | O | X |

### 4.3 배차 플로우 중복
- 콜디텍터의 `DispatchActivity`와 콜매니저의 배차 기능 중복
- 두 곳에서 배차 가능 → 데이터 불일치 위험

## 5. 현장 테스트 시 주의사항

### 5.1 필수 확인 항목

1. **콜디텍터 → 콜매니저 연동**
   - 콜디텍터에서 전화 감지 후 콜매니저에 실시간 표시되는지 확인
   - 콜매니저가 백그라운드일 때도 알림 오는지 확인

2. **콜매니저 → 기사앱 연동**
   - 배차 후 기사앱에 FCM 알림 오는지 확인
   - 기사앱이 백그라운드/종료 상태일 때 알림 확인

3. **상태 동기화**
   - 기사가 콜 수락 → 콜매니저에 상태 변경 반영되는지
   - 운행 시작/완료 시 콜매니저에 상태 변경 반영되는지

4. **정산 플로우**
   - 운행 완료 후 정산 팝업 표시되는지
   - 정산 완료 후 콜매니저에서 확인 가능한지

### 5.2 예상 문제 시나리오

1. **콜 감지했는데 콜매니저에 안 뜸**
   - 원인: FCM 미구현, Firestore 리스너 문제
   - 대응: 콜매니저 앱 재시작, 네트워크 확인

2. **배차했는데 기사앱에 알림 안 옴**
   - 원인: FCM 토큰 미등록, 기사 상태 문제
   - 대응: 기사앱 재로그인, FCM 토큰 확인

3. **정산 완료했는데 콜매니저에서 확인 안 됨**
   - 원인: Cloud Function 실패, 네트워크 문제
   - 대응: Firestore 콘솔에서 직접 확인

4. **연속 전화 시 정보 섞임**
   - 원인: Race condition, staticSavedNumber 문제
   - 대응: 전화 간격 5초 이상 유지

## 6. 권장 조치 우선순위

### 즉시 (테스트 전)
1. 콜디텍터 ↔ 콜매니저 간 FCM 연동 확인 또는 Firestore 리스너 안정성 확인
2. 기사앱 상태값 정규화 (PREPARING, HOLD 등 정리)
3. 포인트 중복 처리 방지 (트랜잭션 내 체크)

### 테스트 중 모니터링
1. Firestore 콘솔에서 콜 상태 변경 확인
2. Firebase 콘솔에서 FCM 전송 로그 확인
3. 각 앱 로그캣에서 에러 확인

### 테스트 후
1. 발견된 문제 기록 및 우선순위 재정렬
2. 메모리 누수 등 장기 사용 문제 확인
