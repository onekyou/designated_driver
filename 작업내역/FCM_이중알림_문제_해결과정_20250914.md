# FCM 이중알림 문제 해결과정

**작성일**: 2025-01-14
**상태**: 이중 알림 시스템 원인 분석 중
**진행률**: 토큰 관리 문제 해결 완료, 알림 형태 차이 문제 분석 중

## 현재까지 해결된 문제들

### ✅ 1. FCM 토큰 관리 문제 완전 해결
- **문제**: "FCM 토큰 없음" 및 "Requested entity was not found" 오류
- **원인**: MyFirebaseMessagingService가 앱 시작 시 호출되지 않아 토큰 동기화 안됨
- **해결**: MainActivity에 자동 토큰 복구 로직 추가
  - `validateAndRefreshTokenIfNeeded()` 함수로 토큰 유효성 검증
  - 무효 토큰 감지 시 `deleteToken()` 후 새 토큰 자동 생성
  - 모든 기기에서 자동 작동하는 범용 솔루션

### ✅ 2. 두 기기 모두 FCM 알림 수신 확인
- **SM-G996N** (정상 기기): 알림 정상 수신
- **SM-A325N** (문제 기기): 토큰 복구 후 알림 정상 수신

## 현재 발견된 새로운 문제

### 🚨 이중 알림 시스템 존재
**증상**:
- 재빌드 기기: 단순 알림 (일반 소리)
- 이전 기기: 긴급 알림 (긴급 소리)
- **두 알림의 형태가 다름** = 이중 알림이 존재한다는 증거

**분석된 원인**:
1. **NotificationChannel 설정 차이**
   - SHARED_CALL_CHANNEL: `IMPORTANCE_HIGH` (일반)
   - NEW_CALL_CHANNEL: `IMPORTANCE_MAX` (긴급)

2. **가능한 이중 알림 소스**:
   - Firebase SDK 자동 알림 + 커스텀 알림
   - super.onMessageReceived() 호출로 인한 중복 처리
   - 다른 FirebaseMessagingService 존재 가능성

## 현재까지 시도한 해결방법

### ✅ 완료된 수정사항
1. **SHARED_CALL_CHANNEL을 IMPORTANCE_MAX로 변경**
   ```kotlin
   NotificationChannel(
       SHARED_CALL_CHANNEL_ID,
       "공유콜 알림 (긴급)",
       NotificationManager.IMPORTANCE_MAX
   )
   ```

2. **setBypassDnd(true) 추가**로 방해금지 모드 우회

3. **상세한 디버깅 로그 추가**
   - MainActivity: FCM 토큰 생성 과정 추적
   - MyFirebaseMessagingService: 메시지 수신 과정 추적

## 현재 분석 중인 상황

### 🔍 이중 알림 소스 조사
1. **Firebase Functions 메시지 구조 확인**
   - ✅ `notification` 필드 제거됨 (자동 알림 방지)
   - ✅ `data` 필드만 사용

2. **프로젝트 내 FCM 서비스 검색**
   - ✅ MyFirebaseMessagingService 1개만 존재
   - ✅ AndroidManifest에 중복 서비스 없음

3. **미확인 사항들**:
   - super.onMessageReceived() 호출 여부
   - Firebase SDK의 백그라운드 자동 알림 생성
   - NotificationChannel 캐시 문제

## 다음에 해야 할 작업들

1. **super.onMessageReceived() 제거 테스트**

   ```kotlin
       // 커스텀 처리만 수행
   }
   ```

2. **NotificationManager 로그 분석**
   - 알림이 몇 개 생성되는지 확인
   - 어떤 소스에서 생성되는지 추적

3. **Firebase Console 테스트 메시지**로 직접 확인

### 우선순위 2: 알림 채널 완전 초기화
1. **기존 채널 강제 삭제**
   ```kotlin

   ```

2. **새 채널 ID로 재생성**
