# 포인트 정산 시스템 수정 및 비용 최적화 작업내역

**작업 날짜**: 2025-10-29
**작업 내용**: 고객앱 포인트 정산 시스템 버그 수정, 콜매니저 N+1 문제 해결, Firebase 비용 최적화 분석

---

## 1. 문제 상황

### 주요 이슈
1. **기사앱에서 포인트 사용 시 고객 잔액에서 차감되지 않음**
2. **콜매니저의 회원현황 카드에 포인트 정보가 반영되지 않음**
3. **고객앱의 포인트 카드 내역에 거래 기록이 표시되지 않음** (미해결)

### 사용자 요구사항
- 포인트 사용 방법: "포인트" (전액) 또는 "현금+포인트" (현금만 입력, 포인트 자동 계산)
- 기사앱, 콜매니저, 고객앱이 유기적으로 연동되어야 함

**핵심 로직 (getCustomerList 예시)**:
```kotlin
val customersWithPoints = snapshot.documents.mapNotNull { doc ->
    val customer = doc.toObject(CustomerInfo::class.java)?.copy(id = doc.id)
    customer?.let {
        // ✅ customerPoints 컬렉션에서 실제 포인트 조회
        val pointsDoc = db.collection("regions")
            .document(regionId)
            .collection("offices")
            .document(officeId)
            .collection("customerPoints")
            .document(it.phoneNumber)
            .get()
            .await()

        Log.d(TAG, "🔍 고객 ${it.phoneNumber}: customerPoints 존재=${pointsDoc.exists()}")

        if (pointsDoc.exists()) {
            val points = pointsDoc.getLong("currentPoints")?.toInt() ?: 0
            val earned = pointsDoc.getLong("totalEarned")?.toInt() ?: 0
            val used = pointsDoc.getLong("totalUsed")?.toInt() ?: 0
            val calls = pointsDoc.getLong("totalCalls")?.toInt() ?: 0
            val grade = pointsDoc.getString("grade") ?: "BRONZE"

            Log.d(TAG, "✅ 포인트 병합: ${it.phoneNumber} - 현재=${points}P, 적립=${earned}P, 사용=${used}P, 콜=${calls}회")

            it.copy(
                currentPoints = points,
                totalEarned = earned,
                totalUsed = used,
                totalCalls = calls,
                customerGrade = grade
            )
        } else {
            Log.w(TAG, "⚠️ customerPoints 없음: ${it.phoneNumber}")
            it
        }
    }
}
```

**효과**:
- customerPoints 데이터를 customers 데이터와 병합하여 반환
- 디버깅을 위한 상세 로그 추가
- 콜매니저 UI에서 실시간 포인트 잔액 표시 가능

**현재 시스템**:

```
콜매니저 배차 → Firestore 업데이트 → Cloud Function 트리거
                                    ↓
                              FCM으로 데이터 포함 알림 전송
                                    ↓
                              기사앱이 FCM 수신 시에만 UI 업데이트
```

**기대 효과**:
- 리스너 제거로 Firestore 읽기 98% 감소
- $414 → $8 (83% 절감)
- 총 월 비용: $554.85 → $91.43

## 9. 주요 학습 내용

### 9.1 기술적 인사이트

1. **실시간 리스너의 숨은 비용**
   - 리스너는 데이터 변경이 없어도 주기적으로 읽기 발생
   - 대규모 시스템에서는 FCM + 온디맨드 쿼리가 더 효율적

2. **Firestore의 컬렉션 분리 전략**
   - 자주 변경되는 데이터(포인트)는 별도 컬렉션 관리
   - 조인이 필요한 경우 클라이언트에서 병합

3. **N+1 문제의 실제 영향**
   - 100명 고객 조회 시 101번의 쿼리 발생
   - 대규모에서는 비용과 성능에 직접적 영향

### 9.2 프로젝트 관리 교훈

1. **데이터 흐름 추적의 중요성**
   - 3개 앱이 유기적으로 연동되는 시스템에서는 전체 흐름 파악 필수
   - 로그 기반 디버깅이 효과적

2. **비용 예측의 필요성**
   - 초기에는 보이지 않던 비용이 스케일업 시 폭발적 증가
   - 리스너, 무료 할당량, 실제 사용 패턴 고려 필수
