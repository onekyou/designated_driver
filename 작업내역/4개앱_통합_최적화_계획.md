## 2-2. Firebase Batch Write 도입

### ⏸️ 대기: 비용 문제 발생 시 진행
- **파일**: `call_detector/app/src/main/java/com/designated/calldetector/CallDetectorService.kt`
- **라인**: 700-773 (createNormalCall 메서드)
- **현재 문제**: customerInfo 조회 (1 read) + 콜 생성 (1 write) = 2회 작업
- **개선 효과**: Batch 사용 시 1회 작업으로 통합

**현재 코드**:
```kotlin
// 1 read
val customerDoc = db.collection("regions/$regionId/offices/$officeId/customerInfo")
    .document(phoneNumber)
    .get()
    .await()

// 1 write
val documentReference = db.collection(targetPath).add(callData).await()
```

**개선 코드**:
```kotlin
val batch = db.batch()

// customerInfo 업데이트 (있으면)
if (customerInfoExists) {
    val customerRef = db.collection("regions/$regionId/offices/$officeId/customerInfo")
        .document(phoneNumber)
    batch.update(customerRef, "lastCallTimestamp", FieldValue.serverTimestamp())
}

// 콜 생성
val callRef = db.collection(targetPath).document()
batch.set(callRef, callData)

// 1회 Batch Commit
batch.commit().await()
```

**비용 분석**:
- **현재**: 하루 500통화 × (1 read + 1 write) = 500 reads + 500 writes
  - 월간: 15,000 reads + 15,000 writes
  - 비용: 무료 범위 내 ($0)
- **개선 후**: 하루 500통화 × 1 batch = 500 batch operations
  - 월간: 15,000 batch operations
  - 비용: 무료 범위 내 ($0)
  - **실제 비용 절감 효과**: 거의 없음 (현재 규모)

**결론**: 현재는 수정 불필요, 월 10만 통화 이상 시 고려

**테스트 체크리스트** (수정 후):
- [ ] 전화 수신 → Firebase 저장 정상 확인
- [ ] 네트워크 오류 시 재시도 확인
