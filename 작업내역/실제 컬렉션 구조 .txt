  ⚠️ 발견된 문제점

  1. 회원가입 프로세스 문제 확인

  - 현재 4명의 관리자가 기존 사무실을 선택해서 가입한 상태
  - 각 사무실마다 1명씩 관리자가 배정됨
  - 문제: 새 관리자가 가입할 때 새 사무실을 만들 수 없고, 기존 사무실을 선택해야 함
  - 해결: 지역 선택 → 새 사무실 이름 입력 방식으로 변경 필요

  2. 데이터 구조 혼란

  - point_transactions가 최상위와 사무실 하위 양쪽에 존재
  - offices가 최상위에도 존재 (구버전 데이터일 가능성)

  3. settings 컬렉션 부족

  - 대부분의 사무실에 settings 컬렉션이 없음
  - QR 코드, 랜딩페이지 URL 등이 설정되지 않은 상태

● 네, 매우 도움이 됩니다! 이제 상황이 명확해졌습니다.

  정리된 상황

  1. 최상위 offices: 테스트용 → 삭제 예정 ✅
  2. 최상위 point_transactions: 사무실간 공유콜 포인트 거래 ✅ (정상)
  3. settings 없는 이유: 기존 계정들은 수동 생성 → 최근에 자동 생성 로직을 추가함 ✅

  핵심 문제

  SignUpViewModel.kt가 사무실 선택 방식으로 구현된 이유를 이제 알겠습니다:
  - 초기에는 사무실을 먼저 만들고, 관리자가 기존 사무실을 선택해서 가입하는 방식이었음
  - 하지만 이제는 회원가입 시 새 사무실을 생성하는 방식으로 변경해야 함

  수정 방향

  변경 전 (현재):
  1. 지역 선택
  2. 해당 지역의 사무실 목록 조회
  3. 사무실 선택
  4. 회원가입 → admins에 등록

  변경 후 (필요):
  1. 지역 선택
  2. 새 사무실 이름 입력
  3. 회원가입 → admins에 등록 + regions/{regionId}/offices/에 새 사무실 생성
  4. settings/attribution에 QR 코드, 랜딩페이지 URL 자동 생성 (이미 구현됨)
