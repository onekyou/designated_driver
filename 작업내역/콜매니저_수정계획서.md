# 일반관리자용 콜매니저 완성 계획서

## 1. 개요

### 1.1 목적
- **일반관리자(사무실 관리자)** 전용 기능에 집중한 실용적 콜매니저 구축
- 손님앱과의 완벽한 연동 및 사무실별 독립적인 손님 관리
- 포인트 및 등급 시스템 통합 (조회 중심)
- 회원 매칭 결과 확인 및 기본 통계 제공
- **총관리자 기능은 별도 앱에서 구현 예정** (KPI 모니터링, 정책 설정 등)

### 1.2 수정 범위
- 기존 기능 유지 + 신규 기능 추가
- 하위 호환성 보장 (기존 데이터 마이그레이션 불필요)
- 점진적 업데이트 가능한 구조

### 1.3 권한 체계
**현재 앱은 일반관리자(OFFICE_MANAGER) 전용으로 구축**
```kotlin
// 현재 앱에서는 OFFICE_MANAGER 기능만 구현
enum class UserRole {
    OFFICE_MANAGER   // 사무실 관리자 (현재 앱 대상)
    // HEAD_MANAGER, SUPER_ADMIN → 차후 별도 앱에서 구현
}
```

### 1.4 핵심 변경사항
- **회원가입 시 QR 코드 자동 생성** (1회성, 이후 읽기 전용)
- **일반관리자 실무 기능 중심** (고급 관리 기능 제외)
- **초대코드 기능 제거** (불필요)
- **랜딩 페이지 URL 자동 설정** (편집 불가)
- **"어트리뷰션" → "회원관리" 용어 변경** (이해하기 쉽게)

```javascript
// 손님 데이터 접근 규칙
match /regions/{regionId}/offices/{officeId}/customers/{customerId} {
  // 해당 사무실 관리자만 읽기/쓰기
  allow read, write: if isOfficeAdmin(officeId);

  // 손님 본인은 자신의 데이터만 읽기
  allow read: if request.auth.uid == customerId;
}

// 어트리뷸션 데이터 보안
match /regions/{regionId}/offices/{officeId}/attributions/{attributionId} {
  // 관리자만 읽기 가능
  allow read: if isOfficeAdmin(officeId);
  // 수정/삭제 불가 (무결성 보장)
  allow write: if false;
}

// 재귀속 요청 보안
match /regions/{regionId}/offices/{officeId}/reattributions/{reattributionId} {
  // 관리자만 생성/수정 가능
  allow read, write: if isOfficeAdmin(officeId);
}

// 감사 로그 보안 (읽기 전용)
match /regions/{regionId}/offices/{officeId}/auditLogs/{logId} {
  allow read: if isOfficeAdmin(officeId);
  allow write: if false; // 생성은 Cloud Functions에서만
}

// 포인트 트랜잭션 보안
match /regions/{regionId}/offices/{officeId}/pointTransactions/{transactionId} {
  // 관리자만 생성 가능
  allow create: if isOfficeAdmin(officeId);
  // 수정/삭제 불가 (이력 보존)
  allow update, delete: if false;
```

```
Firebase Firestore 구조:
regions/{regionId}/offices/{officeId}/

└── systemSettings/   ← 총관리자 전용 (전역 설정)
```

#### 2. 실시간 연동 시나리오

**시나리오 A: 임계값 변경**
1. 총관리자가 사무실 A의 매칭 임계값을 70점 → 80점으로 변경
2. 일반관리자 앱의 회원관리 화면에서 변경된 임계값 자동 반영
3. 새로운 매칭부터 80점 기준으로 처리

**시나리오 B: 정책 변경 알림**
1. 총관리자가 포인트 적립률 변경 (3% → 5%)
2. 해당 사무실 일반관리자에게 푸시 알림 전송
3. 일반관리자 앱에서 새 정책 확인 가능

**시나리오 C: 고객 이동 승인**
1. 고객이 사무실 A → 사무실 B로 이동 요청
2. 총관리자가 이동 내역 검토 후 승인/거부
3. 승인 시 두 사무실 관리자에게 자동 알림
