# FCM 공유콜 알림 버튼 문제 분석 및 해결 방향

**작업 날짜**: 2025년 1월 11일  
**문제**: FCM 메시지가 onMessageReceived() 호출 없이 자동 작은 알림으로 표시되는 현상  
**목표**: 수락/취소 버튼이 있는 큰 알림으로 표시  

---

## 📋 현재 상황 요약

### ✅ 확인된 사실들
1. **FCM 자동 알림 생성**: `FCM-Notification:205526507` 태그로 시스템이 자동 생성
2. **onMessageReceived() 미호출**: 서비스 onCreate()만 호출됨
3. **알림 권한**: Android 13+ POST_NOTIFICATIONS = "allow" 상태
4. **채널 설정**: shared_call_fcm_channel (importance=5, 긴급) 정상
5. **백그라운드 vs 포그라운드**: 백그라운드에서만 작은 알림, 포그라운드에서는 알림 없음

### 🔧 시도한 해결책들
1. ✅ Cloud Functions에서 notification 필드 완전 제거
2. ✅ `notificationTitle`/`notificationBody` → `alertTitle`/`alertMessage` 변경 (예약키 회피)
3. ✅ Android 매니페스트 `android:exported="false"` 설정
4. ✅ 알림 채널 재생성 및 중요도 최대 설정
5. ✅ Firebase 초기화 로그 추가 및 확인

### ❌ 여전히 지속되는 문제
- FCM SDK가 메시지를 notification 메시지로 분류
- `FCM-Notification:*` 태그로 시스템 자동 알림 생성
- 커스텀 알림 버튼 동작하지 않음

## 🎯 전문가 답변 분석

### 첫 번째 전문가 답변 (Korean Expert)
**핵심 진단**: 
> "메시지가 실질적으로 알림 메시지로 분류되어 OS가 FCM-Notification:* 태그로 자동 표시"

**주요 원인 가설**:
- 숨은 notification 블록 또는 gcm.notification.*/google.* 예약 키 사용
- 중간 게이트웨이/SDK의 payload 변형
- Firebase 콘솔이나 서드파티 서비스 경유로 인한 자동 변환

**제안 해결책**:
1. HTTP v1 "순수 data-only" 직접 테스트
2. 서버 로그에서 최종 전송 JSON 확인
3. adb logcat으로 메시지 분류 검증

### 두 번째 전문가 답변 (International Expert)
**핵심 결론**:
> "Firebase Admin SDK는 절대로 data-only를 notification으로 변환하지 않음. FCM-Notification 태그는 서버에서 notification 객체가 포함되어 왔다는 확실한 증거"

**명확한 팩트**:
- Admin SDK는 개발자 제공 Message 객체를 충실히 변환할 뿐
- `android.priority: "high"`는 메시지 종류 변경과 무관
- 문제는 100% Functions 코드 로직에 있음

**제안 진단법**:
1. HTTP v1 API 직접 호출로 Admin SDK 우회 테스트
2. Functions 코드에서 숨겨진 notification 객체 철저 검색
