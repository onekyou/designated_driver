## 🔍 분석 과정

### 1단계: 초기 가설 검증
**가설**: "onMessageReceived가 호출되지 않는다"
- ✅ MyFirebaseMessagingService onCreate 호출됨
- ❌ onMessageReceived는 실제로는 호출되고 있었음
- 🔍 **포그라운드 조건에서 early return**으로 인해 알림 생성 안됨

### 2단계: 포그라운드 문제 해결
**수정**: 포그라운드에서 공유콜 허용
```kotlin
// 기존: SHARED_CALL_CANCELLED_POPUP만 허용
// 수정: NEW_SHARED_CALL, SHARED_CALL_CANCELLED_POPUP, SHARED_CALL_CLAIMED 허용
```
**결과**: 포그라운드에서도 공유콜 알림 작동 ✅

### 3단계: super.onMessageReceived() 처리
**수정**: `super.onMessageReceived(remoteMessage)` 제거 후 다시 복원
**결과**: 이중 알림 발생 확인

### 4단계: Firebase Functions 분석
- ✅ **메시지 전송 성공**: FCM 로그 확인됨
- ✅ **메시지 구조 정상**: data-only 구조, alertTitle/alertMessage 사용
- ✅ **토큰 일치**: 정상 전송됨

### 5단계: 최종 원인 파악
**핵심 발견**: 내 수정으로 인해 이중 알림이 생성됨

## 🚨 최종 결론

### 원인 분석
**수정 전 상태** (다른 기기):
- Firebase SDK의 자동 알림 처리만 작동
- onMessageReceived가 포그라운드 조건으로 차단됨
- **결과**: 긴급 알림 하나만 표시 ✅

**수정 후 상태** (현재 기기):
1. `super.onMessageReceived()` → Firebase SDK 자동 알림 생성 (첫 번째)
2. 포그라운드 조건 완화 → 커스텀 알림도 생성 (두 번째)
3. **결과**: 이중 알림 발생 ❌

### 이중 알림 발생 메커니즘
```
FCM 메시지 수신
    ↓
super.onMessageReceived() → 시스템 자동 알림 (기본 아이콘, 일반 소리)
    ↓
포그라운드 조건 통과 → 커스텀 알림 (커스텀 아이콘, 긴급 소리)
    ↓
이중 알림 완성
```

## 🛠️ 해결 방안

### 방안 1: 원래 상태로 복원 (권장)
```kotlin
// 포그라운드 조건을 원래대로 되돌림
val shouldProcessInForeground = messageType == "SHARED_CALL_CANCELLED_POPUP"
```
**장점**: 즉시 해결, 기존 동작과 일치
**단점**: 포그라운드에서 일부 공유콜 알림 안 보임

### 방안 2: super.onMessageReceived() 제거
```kotlin
override fun onMessageReceived(remoteMessage: RemoteMessage) {
    // super.onMessageReceived(remoteMessage) 제거
    // 커스텀 처리만 수행
}
```
**장점**: 완전한 제어 가능
**단점**: 예상치 못한 부작용 가능성

### 방안 3: 조건부 super 호출
```kotlin
// 공유콜이 아닐 때만 super 호출
if (messageType != "NEW_SHARED_CALL") {
    super.onMessageReceived(remoteMessage)
}
```
**장점**: 선택적 제어
**단점**: 복잡성 증가
