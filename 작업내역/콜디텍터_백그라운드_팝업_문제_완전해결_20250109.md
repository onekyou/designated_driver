# 콜디텍터 백그라운드 팝업 문제 완전 해결

**작업일자**: 2025-01-09  
**작업자**: Claude Code  
**작업목표**: 콜디텍터가 백그라운드 상태에서도 즉시 배차 팝업을 생성하도록 개선  

## 🔴 문제 상황

### 초기 증상
1. **포그라운드**: 통화 종료 시 즉시 배차 팝업 생성 ✅
2. **백그라운드**: 배차 팝업 생성 실패, FCM 알림만 표시 ❌
3. **콜매니저와의 차이**: 콜매니저는 백그라운드에서도 즉시 팝업 생성

### 근본 원인
- **Android 10+ 백그라운드 Activity 실행 제한**
- 백그라운드 Service에서 Activity를 직접 실행할 수 없음
- `startActivity()` 호출은 성공하지만 실제로 Activity가 시작되지 않음

## 🔧 시도한 해결 방법들 (실패)

### 1. MainActivity 경유 방식 (실패)
```kotlin
Service → MainActivity → DispatchActivity
```
- **문제**: MainActivity도 백그라운드에서 실행되지 않음
- **로그**: `startActivity 호출 완료!` 나타나지만 onCreate 호출 안됨

### 2. Intent 플래그 조정 (실패)
```kotlin
FLAG_ACTIVITY_NEW_TASK
FLAG_ACTIVITY_CLEAR_TOP
FLAG_ACTIVITY_SINGLE_TOP
FLAG_ACTIVITY_REORDER_TO_FRONT
FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS
```
- **문제**: Android 10+ 플래그 추가해도 백그라운드 제한 우회 불가

### 3. Full-Screen Intent 방식 (부분 성공)
```kotlin
NotificationCompat.Builder()
    .setFullScreenIntent(pendingIntent, true)
```
- **문제**: 알림이 나타나서 사용자가 원하는 방식 아님
- 사용자 요구: 알림 없이 바로 팝업 생성

### 4. WindowManager 오버레이 방식 (잘못된 이해)
```kotlin
WindowManager.addView(overlayView, layoutParams)
```
- **문제**: 임시 TextView 팝업이 아닌 기존 DispatchActivity 필요

## ✅ 최종 해결 방법

### 핵심 발견: 콜매니저와의 차이점
- **콜매니저**: `SYSTEM_ALERT_WINDOW` 권한 활용
- **콜디텍터**: 권한은 있었지만 활용하지 못함

### 구현 방법
```kotlin
// CallDetectorService.kt
private fun showOverlayPopup(...) {
    // 1. SYSTEM_ALERT_WINDOW 권한 확인
    if (Settings.canDrawOverlays(this)) {
        // 2. 권한이 있으면 DispatchActivity 직접 실행
        val dispatchIntent = Intent(this, DispatchActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_NEW_TASK or 
                   Intent.FLAG_ACTIVITY_CLEAR_TOP or
                   Intent.FLAG_ACTIVITY_SINGLE_TOP or
                   Intent.FLAG_ACTIVITY_EXCLUDE_FROM_RECENTS
            
            // Intent extra 이름 통일 (중요!)
            putExtra("EXTRA_PHONE_NUMBER", phoneNumber)
            putExtra("EXTRA_CONTACT_NAME", contactName)
            // ...
        }
        startActivity(dispatchIntent)
    } else {
        // 3. 권한이 없으면 Full-Screen Intent 폴백
        showFullScreenIntentNotification(...)
    }
}
```

### Intent Extra 이름 불일치 문제 해결
- **이전 (잘못됨)**: `putExtra("phoneNumber", ...)`
- **수정 (올바름)**: `putExtra("EXTRA_PHONE_NUMBER", ...)`

## 📋 필요한 권한 설정

### AndroidManifest.xml
```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
```

### 사용자 권한 승인 필요
1. **설정** → **앱** → **콜디텍터**
2. **권한** → **다른 앱 위에 표시**
3. **허용**으로 변경

## 💡 핵심 교훈

### 1. Android 백그라운드 제한 이해
- Android 10+에서는 백그라운드 Activity 실행이 매우 제한적
- `startActivity()` 성공 ≠ Activity 실제 실행

### 2. SYSTEM_ALERT_WINDOW 권한의 중요성
- 백그라운드에서 UI를 표시하는 가장 강력한 방법
- 사용자 승인 필요하지만 승인 후 제약 없음

### 3. Intent Extra 이름 일치의 중요성
- 송신측과 수신측의 Extra 키 이름이 정확히 일치해야 함
- 불일치 시 데이터 전달 실패로 팝업 생성 안됨

## 🔍 트러블슈팅 가이드

### 문제: 백그라운드에서 팝업이 안 뜸
1. **SYSTEM_ALERT_WINDOW 권한 확인**
   - 설정에서 권한 승인 여부 확인
   - `Settings.canDrawOverlays(context)` 로그 확인

2. **Intent Extra 이름 확인**
   - Service에서 putExtra 키 이름
   - Activity에서 getStringExtra 키 이름
   - 정확히 일치하는지 확인

3. **로그 체크 포인트**
   - `showOverlayPopup 시작` 로그 확인
   - `SYSTEM_ALERT_WINDOW 권한 확인됨` 로그 확인
   - `DispatchActivity onCreate 시작` 로그 확인
