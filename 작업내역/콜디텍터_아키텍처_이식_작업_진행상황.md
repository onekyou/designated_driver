# 콜디텍터 아키텍처 이식 작업 진행상황

**작업일자**: 2025-09-08  
**작업자**: Claude Code  
**작업목표**: 콜매니저의 올바른 아키텍처를 콜디텍터에 이식하여 중복 팝업 문제 해결

## 🎯 작업 배경 및 목표

### 현재 문제점
1. **중복 팝업 발생**: 콜디텍터와 콜매니저에서 동시에 배차 팝업이 생성됨
2. **잘못된 아키텍처**: 콜디텍터가 백그라운드 서비스에서 직접 DispatchActivity 실행 시도
3. **SecurityException**: 백그라운드에서 Activity 직접 실행으로 인한 오류
4. **알림 폴백**: SecurityException 발생 시 notification으로 폴백하여 이중 알림 생성

### 올바른 아키텍처 (콜매니저 방식)
```
Service → MainActivity → ViewModel → UI (팝업)
```

### 잘못된 아키텍처 (현재 콜디텍터)
```
Service → DispatchActivity (직접 실행) → SecurityException → Notification 폴백
```

## 📊 현재 시스템 분석 결과

### Firestore 리스너 현황
- **콜매니저**: 2개 리스너 (DashboardViewModel, SettlementViewModel)
- **콜디텍터**: 0개 리스너 (생성만 함)
- **기사앱**: 3개 리스너 × 5명 = 15개 리스너
- **총합**: 17개 Firestore 리스너 동시 운영

### 데이터 흐름 확인
1. **배차시**: 콜디텍터 → 기사앱 + 콜매니저 **동시 전달**
2. **보류시**: 콜디텍터 → 콜매니저**만** 전달  
3. **공유콜**: 완전히 구현되어 운영 중

### 상태 보고 체계
- 거의 모든 비즈니스 상태가 Firestore를 통해 콜매니저에 실시간 보고됨
- 기사의 콜 수락, 운행 시작/완료, 정산 등 모든 상태 변화 실시간 동기화

2. **Intent 플래그**: `FLAG_ACTIVITY_NEW_TASK`, `FLAG_ACTIVITY_CLEAR_TOP` 등 정확한 플래그 사용
3. **Notification 권한**: Android 13+ 알림 권한 명시적 요청 필요

### 데이터 일관성
1. **fromCallDetector 플래그**: 중복 알림 방지 위해 필수
2. **상태 동기화**: Firestore 리스너를 통한 실시간 상태 동기화 유지
3. **트랜잭션 사용**: 동시성 문제 방지

### 테스트 시나리오
1. **기본 시나리오**: 콜 수신 → 팝업 1개만 표시되는지 확인
