# 관리자 직접운행 시뮬레이션 시나리오

## 목적
`manager-direct-drive` 브랜치에서 추가된 직접운행 기능이 기존 실기사 정산 플로우와 충돌하지 않고, 대기/외상/일일/전체 탭에 올바르게 합류하는지 검증.

## 전제
- 브랜치: `manager-direct-drive`
- 테스트 기기: S21+ (R3CR312MB1L) = 콜매니저 + driver_app, S22 (R5CT41TJZFP) = call_detector + driver_app
- 실기사 2명 로그인 (D1: S21+, D2: S22)
- 사무실: 테스트 사무실 1곳
- 로그캣 3개 준비 (콜매니저 / 기사앱 2대 / CF emulator or logs)

---

## 시나리오 1: 회귀 테스트 (실기사만)

**목표**: 직접운행 기능 추가로 기존 실기사 정산 로직에 회귀 없음 확인.

1. 실기사 D1에게 현금 콜(20,000), 이체 콜(15,000), 외상 콜(30,000), 현금+포인트 콜(25,000 중 현금 20,000) 4건 배차 → 완료
2. 실기사 D2에게 현금 콜(18,000), 이체 콜(22,000) 2건 배차 → 완료
3. **전체 탭 확인**
   - 총매출 = 130,000
   - 이체 = 37,000
   - 미수금 = 30,000
   - 기사 납입, 실수입 숫자 검증
4. **대기 탭 확인**
   - 이체 3건(D1·D2·D1) + 외상 1건(D1) = 총 4건
   - 외상 자동 등록 **안** 됨 (외상 탭 비어있음)
5. **대기 탭에서 "이체 확인" 3건 + "외상 등록" 1건 처리**
6. **외상 탭**에 1건 추가 확인, 금액 정확(30,000)
7. **업무 마감** → 일일 탭에 세션 카드 1개 등장 (총 6건 / 130,000원)
8. 세션 카드 클릭 → 상세에 [직접] 태그 **없음** 확인

**PASS 기준**: 회귀 v3 이전 동작과 동일 + 외상 자동 등록 안 됨.

---

## 시나리오 2: 직접운행만 있는 날

**목표**: 실기사 운행 0건, 관리자 직접운행만 있는 날 마감 동작.

1. 콜매니저에서 새 호출 생성 또는 전화감지 콜 → "직접운행" 버튼 → 다이얼로그
2. **현금 콜**: 고객명 "김씨", 전화 "01012345678", 출발 "서울역", 도착 "강남역", 요금 20,000, 현금
3. **이체 콜**: 고객명 "박씨", 출발 "부산", 도착 "대구", 요금 30,000, 이체
4. **외상 콜**: 고객명 "이씨", 전화 "01099998888", 출발/목적지 입력 필수 검증
   - 출발지 빈 칸 → "완료" 버튼 비활성화 확인
   - 채우면 활성화
   - 요금 15,000, 외상 저장
5. **전체 탭 확인**
   - 전체 운행 3건
   - 총매출 = 65,000, 총수입 = 65,000 (100%)
   - "직접운행 매출: 65,000원" 노란색 줄 등장
   - 기사 납입/이체/미수금 = 0 (실기사 없음)
   - 실수입 = 65,000
6. **대기 탭 확인**
   - 이체 1건 + 외상 1건 = 2건
   - 현금 콜은 대기 탭에 없음
   - 모두 "관리자: 이체/외상" 표시
7. **대기 처리**: 이체 확인, 외상 등록(이씨 이름 확정)
8. **외상 탭**에 이씨 15,000 확인
9. **업무 마감**
   - 버튼 활성화 상태 확인 (실기사 0건이어도)
   - 확인 다이얼로그 → 완료 (직접운행 3건)
   - CF `finalizeSettlementAndNotifyDrivers` 스킵(로그로 확인)
   - `clearAllTrips()` 실행 → Room에 SessionEntity + 직접운행 3건 SettlementEntity(sessionId) 저장
   - office 문서 `settlementLastCleared` 갱신 확인 (Firestore 콘솔)
10. **일일 탭 확인**
    - 세션 카드 1개, "총 3건 / 65,000원", **"직접운행 3건" 노란색 뱃지**
    - 카드 클릭 → DateDetailDialog 제목 "(직접운행 3건 포함)"
    - 각 행 `[직접]` 태그 + "관리자 · 김씨/박씨/이씨 …" 노란색
11. **마감 후 전체·대기 탭**: 직접운행 리스트 비어야 함 (officeLastCleared 필터 즉시 반영)

**PASS 기준**: 실기사 0건이어도 마감 가능, 일일/상세 화면에 직접운행 명확히 구분 표시.

## 시나리오 3: 실기사 + 직접운행 혼합

**목표**: 두 유형이 같은 날 공존할 때 집계·마감·재필터 모두 올바른지.

1. D1에 현금 콜 25,000 배차/완료
2. 직접운행 현금 콜 20,000 처리
3. D2에 외상 콜 40,000 배차/완료
4. 직접운행 외상 콜 15,000 처리 (고객/출발/목적지 입력)
5. **전체 탭 확인**
   - 총 4건
   - 총매출 = 100,000
   - 총수입 = (25,000+40,000)×60% + 20,000+15,000 = 39,000 + 35,000 = 74,000
   - 직접운행 매출 = 35,000 (별도 줄)
   - 미수금 = 40,000 (실기사 외상만, 대기 처리 전)
6. **대기 탭**
   - 실기사 외상 1건(D2 · 40,000)
   - 직접운행 외상 1건(관리자 · 15,000) + 직접운행 이체 0건
   - 총 2건
7. 둘 다 "외상 등록" 처리 → 외상 탭에 2건
8. **기사별 탭 확인**
   - 실기사 2명만 노출, **"관리자" 행 없음**
9. **업무 마감**
   - CF 실기사 알림 2명에게 전송
   - clearAllTrips → 실기사 trips markFinalized + 직접운행 trips 추가 insert
10. **일일 탭 세션 카드**: 총 4건 / 100,000원 / 직접운행 2건 뱃지
11. 상세 다이얼로그: 4행 중 2행에 `[직접]` 태그, 2행은 실기사명

**PASS 기준**: 혼합 시 숫자 정합성, 기사별 탭 격리, 일일 카드 뱃지 정확.

---

## 시나리오 4: 외상 이중 등록 방지

**목표**: 외상 자동 등록 제거 후 이중 계산 발생 안 함 확인.

1. D1에 외상 콜 20,000 배차 → 완료
2. **즉시 외상 탭 확인**: 비어있음 (자동 등록 안 됨)
3. 대기 탭 → "외상 등록" 클릭 → CreditDialog에서 이름/전화 입력 → 저장
4. 외상 탭 확인: 1건, 20,000원 (두 배 30,000/40,000이 아님)
5. 같은 고객에 추가 외상 콜 10,000 발생 시 외상 탭 같은 row에 30,000으로 증액되는지 (전화번호 매칭)

**PASS 기준**: 외상 금액이 두 번 등록되지 않고, 같은 고객은 전화번호 기준 누적.

---

## 시나리오 5: 직접운행 취소/WAITING 유지

**목표**: 직접운행 다이얼로그를 열고 취소해도 콜이 WAITING 상태 유지.

1. WAITING 콜 → 직접운행 → 다이얼로그 오픈
2. 요금 입력 후 "취소" 클릭
3. 콜 상태 WAITING 유지 확인
4. 다시 직접운행 또는 기사배정 가능

**PASS 기준**: 취소 시 상태 불변.

---

## 시나리오 6: 기존 마감 후 직접운행 신규 발생

**목표**: 업무 마감 후 새 직접운행 콜이 다음 세션에 올바르게 누적되는지.

1. 시나리오 2~3 중 하나로 마감 완료 → 일일 탭에 세션 카드 존재
2. 새 직접운행 현금 콜 10,000 처리
3. 전체 탭에 1건 / 10,000원 표시 (이전 마감된 건은 안 보임)
4. 대기 탭은 비어있음 (현금)
5. 추가 이체 콜 5,000 처리
6. 대기 탭에 1건
7. 다시 업무 마감 → 일일 탭에 **두 번째 세션 카드** 등장 (직접운행 2건 뱃지)

**PASS 기준**: 마감 이후 신규 직접운행이 이전 세션과 분리되어 누적.

---

## 시나리오 7: 앱 재시작/복원

**목표**: 콜매니저 재시작 후 상태 유지.

1. 직접운행 1~2건 처리 후 마감 전에 콜매니저 강제 종료
2. 재실행
3. 전체 탭에 직접운행 매출 복원 확인 (Firestore 리스너 재구독)
4. 대기 탭 직접운행 항목 복원
5. 마감 → 일일 탭 세션 카드 정상 생성

**PASS 기준**: 재시작 후 데이터 손실 없음.

## 공통 관찰 포인트

- **FCM**: 직접운행은 기사앱에 `call_assigned` 안 감 (배차 트랜잭션 안 탐) — 로그캣에서 확인
- **Presence 타임아웃**: 직접운행 콜이 `checkAssignedTimeout`에 안 걸림 (assignedDriverId=MANAGER이지만 Presence에 없음 → CF 분기 아직 없음. 영향 점검)
- **Firestore 비용**: office 문서 실시간 리스너 1개 추가 → 무시할 수준
- **백업**: 직접운행 데이터도 Room settlements에 포함되니 백업/복원에 자동 포함

## 로그캣 관찰 명령

```bash
ADB="$ANDROID_HOME/platform-tools/adb"
$ADB -s R3CR312MB1L logcat -s CallManager_FCM,DashboardViewModel,SettlementViewModel
$ADB -s R5CT41TJZFP logcat -s CallDetector,DispatchActivity,DriverApp
```

## CF 배포 상태
- `onCallCompletedUpdateSettlement` (handledByManager 가드) — 배포됨
- `finalizeSettlementAndNotifyDrivers` — 무수정, 기존 그대로

## Known Limitations
- `checkAssignedTimeout`·presence 관련 CF가 MANAGER 특수처리 없음 (직접운행은 배차 트랜잭션 안 타서 ASSIGNED 상태가 안 되므로 실질 영향 없음)
- 일일 탭 세션 카드의 이월금 계산은 실기사만 대상 (직접운행은 driverShare=0 이라 의도한 동작)
- 손님앱 FCM 연동 phase2로 분리
