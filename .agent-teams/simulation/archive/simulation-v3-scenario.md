# 3차 코드 시뮬레이션 시나리오 매트릭스 (350콜)

## 시뮬레이션 규칙
- 보안 이슈는 패스 (SEC-* 무시)
- 이미 수정 완료된 25건의 코드 변경이 반영된 상태로 시뮬레이션
- 이전 시뮬레이션 오탐 패턴 숙지 필수 (아래 참조)
- 5명 기사 (D1~D5), 3명 픽업기사, 3대 전화기
- Call Detector 독립 앱 3대 + Call Manager 내장 Detector 1대 = 총 4곳에서 콜 수신 가능
- Call Manager가 독립 Detector + 내장 Detector 모두 총괄

## 배차 담당 배분
- 독립 Call Detector (3대 폰): 콜 감지 + 직접 배차
- Call Manager (내장 Detector): 콜 감지 + 직접 배차 + 모든 콜 총괄 관리
- 번갈아가며 배차 (홀수콜: Detector, 짝수콜: Manager)

## 오탐 방지 필독 사항 (이전 시뮬레이션에서 확인됨)

### 1. Firestore 트랜잭션 직렬화
- `runTransaction` 내에서 같은 문서를 읽고 쓰는 두 동시 요청은 Firestore가 자동 직렬화함
- 따라서 "동시 배차 레이스 컨디션" 등의 지적은 transaction.get()을 확인할 것
- 멱등성 키 + 트랜잭션 = 이중 처리 방지됨

### 2. Detector 3대 = 3대 별도 폰
- 각 Detector는 별도 물리 폰에서 실행됨
- static 변수, 인스턴스 변수는 폰 간 공유되지 않음
- cross-device 경합은 Firestore 레벨에서만 발생

### 3. 이미 수정된 건 재지적 금지
- CROSS-01 (기사 상태 통일) -> 수정 완료
- CROSS-07 (rejectCall 구현) -> 수정 완료
- BUG-D11 (공유콜 취소) -> 수정 완료
- BUG-D12 (포인트 CF 일원화) -> 수정 완료
- STL-01~09 (정산 관련) -> 수정 완료
- NEW-11 (이중배차 방지 트랜잭션) -> 수정 완료
- NEW-15 (ASSIGNED 타임아웃) -> 수정 완료
- CUST-01~04 (Customer FCM/포인트) -> 수정 완료
- 전체 25건 수정 완료 목록은 CLAUDE.md / MEMORY.md 참조
