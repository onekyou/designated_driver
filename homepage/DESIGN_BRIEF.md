# 콜마당 홈페이지 디자인 의뢰서

---

## 1. 서비스 소개

**콜마당**은 지방 대리운전 사무실을 위한 **올인원 관리 플랫폼**입니다.

대리운전 사무실 사장님이 손님 전화를 받고, 기사를 배차하고, 정산까지 하는 과정을 4개 앱으로 통합 관리합니다. 카카오T 대리, 로지콜 같은 중앙 플랫폼과 달리 **수수료 0%, 고객 데이터는 사무실 소유**라는 독립형 모델입니다.

### 앱 구성 (4종)
| 앱 | 대상 | 핵심 기능 |
|---|------|----------|
| **콜 매니저** | 관리자 (사장님) | 대시보드, 원클릭 배차, 자동 정산, 운영 통계 |
| **콜 디텍터** | 서브 전화기 | 수신 전화 자동 감지 → 통화 종료 후 자동 배차 팝업 |
| **기사 앱** | 대리기사 | 콜 수신 알림, 운행 이력, 수익 자동 저장 |
| **콜마당 (손님앱)** | 손님 | QR 스캔 → 사무실 연결, 포인트 자동 적립 |

### 핵심 차별점
- **배차 8번 클릭 → 1번**: 통화 종료 후 자동 감지 → 원클릭 배차 완료
- **QR 손님 귀속**: 기사가 QR을 보여주면 손님이 사무실에 영구 각인 (다른 곳으로 이탈 방지)
- **수수료 0%**: 건당 수수료 없이 월 구독만. 데이터는 사장님 소유
- **일반 전화도 자동 배차**: 앱 없이 전화로 부르는 손님도 동일한 시스템으로 관리

## 3. 홈페이지 목표

> **"호기심만 갖게 해도 성공"**

이 홈페이지는 온라인에서 직접 전환(가입)을 만드는 것이 아닙니다. **방문 영업의 사전 어필 도구**입니다.

- 사장님이 카톡으로 받은 링크를 **모바일로 30초~1분 훑어볼 때** 호기심이 생겨야 합니다
- "이거 뭔데? 한번 들어볼까?" 정도의 반응이면 성공
- 이후 직접 방문하여 상세 설명 → 신청서 작성

### 전환 목표
- **1차**: 호기심 확보 (방문 수락)
- **2차**: 신청서 제출 (signup.html)

## 4. 타겟 페르소나

| 항목 | 내용 |
|------|------|
| **직업** | 지방 대리운전 사무실 사장님 |
| **연령대** | 40~50대 |
| **기술 친숙도** | 스마트폰은 매일 쓰지만, 앱/웹 서비스에는 보수적 |
| **현재 업무 방식** | 수기 + 카카오톡 + 엑셀로 기사 배차 및 정산 |
| **페인포인트 1** | 운전 중에도 전화기를 놓지 못함. 배차 한 번에 8번 클릭 |
| **페인포인트 2** | 명함도 돌리고 쿠폰도 주지만, 손님은 이리저리 옮겨다님 (귀속 불가) |
| **브라우징 환경** | **모바일 위주** (카톡 링크 → 폰 브라우저) |
| **심리적 장벽** | "또 프로그램 깔라는 거 아니야?", "수수료 떼는 거 아니야?" |

## 6. 현재 페이지 구조 및 콘텐츠

### index.html (메인 랜딩)

```
[Nav] 콜마당 로고 + "지역대리운전 관리 플랫폼" + 서비스소개 / 관리자로그인 / 무료신청하기

[섹션1: Hero] — 네이비 배경
  좌: "통화가 끝나면 배차가 시작됩니다"
      "통화 후 기사배차까지 8번의 클릭, 콜마당은 단 1번에 해결합니다"
      CTA: "지금 무료 신청하기" + "서비스 알아보기"
  우: 인터랙티브 비교 데모 (클릭하면 커서 애니메이션으로 기존 8번 vs 콜마당 1번 시연)
      ※ 클릭 전 오버레이: "원클릭이면 배차 끝" 텍스트 + 재생 버튼
      ※ 의도적으로 클릭해야 시작 (다음 섹션 영상의 사운드 재생 트리거 역할)

[섹션2: 감성 공감] — 흰 배경
  "도로 위 수많은 위험들"
  "하지만 운전중에도 전화기를 놓지 못한채 손님을 지켜온 당신"
  메인 광고 영상 (스크롤 진입 시 사운드와 함께 자동 재생)
  "지금 모신 손님은 다음에도 전화할까요?"

[섹션3: QR 각인 + 앱 소개] — 흰 배경
  좌: "단 한번의 QR이 만드는 각인 / 이후, 누구도 데려갈 수 없는 손님"
      "실시간 배차현황 알림, 등급별 포인트 자동 적립 및 혜택"
  우: 앱 아이콘 카드 4종 (손님앱, 기사앱, 콜매니저, 콜디텍터)
  하단: "앱은 물론 일반전화까지도 자동배차"
       CTA: "무료 신청하기"

[섹션4: 비교표] — 네이비 배경
  "그래서, 프로그램 설치하고 수수료 내라고?"
  기존 플랫폼 vs 콜마당 비교:
    수수료: 건당 25% vs 0%
    고객 데이터: 플랫폼 소유 vs 사장님 소유
    해지 시: 고객 정보 소실 vs 유지
    단골 관리: 불가능 vs 자동 CRM 구축
  최종 CTA: "지금 무료 신청하기"

[Footer] — 딥 네이비 배경
  개인정보처리방침 / 계정삭제 안내 (아코디언)
  사업자 정보
```

## 8. 내부 디자인 검토 결과 요약

자체 검토에서 도출된 주요 이슈입니다. 전문 디자인 관점에서 재평가 및 추가 발견을 기대합니다.

### 강점
- "8번 → 1번" 숫자 비교가 직관적
- 인터랙티브 비교 데모가 창의적 (업계에서 드문 접근)
- 골드 + 네이비 색상 체계 일관적
- 비교표가 핵심만 압축

### 도출된 디자인 이슈

| 우선순위 | 이슈 | 상세 |
|---------|------|------|
| **높음** | 모바일 전환 동선 부재 | CTA가 최상단/최하단에만 있음. 모바일 Sticky CTA 없음 |
| **높음** | 데모 시작 오버레이가 약함 | 클릭 전 빈 회색이었음 → "원클릭이면 배차 끝"으로 개선 중 |
| **높음** | 모바일 데모 영역 과대 | hero-demo min-height:540px이 모바일에서 긴 스크롤 유발 |
| **중간** | 섹션 여백 불규칙 | padding-top이 140/100/100/60px, inline margin-top 60/80/85px 혼재 |
| **중간** | 배경색 전환 과다 | navy→white→크림→navy→black (5톤) → 3톤으로 축소 시도 중 |
| **중간** | nav hover 색상 반전 | 스크롤 중 의도치 않게 발동. 모바일 터치 잔류 문제 |
| **낮음** | 신뢰 요소 부재 | 파일럿 전이므로 고객 후기/도입 사례 없음 (현 단계에서 불가) |

### 현재 진행 중인 개선 (index_v3.html)
- 데모 오버레이 텍스트 교체
- nav hover 효과 제거
- 모바일 Sticky CTA 추가
- 섹션 중간 CTA 추가
- 배경색/여백 통일
- 모바일 데모 높이 최적화

## 9. 의뢰 범위

### 필수
- 메인 랜딩 페이지 (index.html) 디자인 개선
- 신청 페이지 (signup.html) 디자인 개선
- 모바일 최적화 (타겟의 주 브라우징 환경)

### 선택
- features.html 디자인 정비 및 nav 연결 여부 판단
- 전체 에셋(스크린샷, 아이콘) 리터칭/교체 필요 여부 판단

### 제약
- **상세 기능/포지션 노출 최소화**: 경쟁사에 노출되면 안 됨. 호기심을 자극하되 전략을 드러내지 않는 수준
- **기술 스택**: 순수 HTML/CSS/JS (프레임워크 도입 불필요). Firebase Hosting
- **인터랙티브 데모**: 이미 구현 완료. 디자인만 개선하면 됨
- **Social Proof**: 파일럿 전이므로 고객 후기 불가. 다른 방식의 신뢰 요소 제안 환영
