# 콜캐치 권한 우회 = 연락처 확보 (녹음 파일명) — 파싱은 선택적 확장 레이어 (2026-06-03 발견, 6/4 중심 정정, 실측 GREEN)

**상태**: ✅ 단말 실측 완료(S21+). 아키텍처 타당성 GREEN.
**★ 중심 (6/4 본인 정정)**: 이 발견의 알맹이는 *파싱이 아니라* **연락처 정보를 `READ_CALL_LOG` 없이 얻는 것**. 콜캐치의 존재 이유 자체가 연락처 확보였고 그게 사이드로드 감옥의 원인. 삼성 녹음 **파일명에 번호가 박혀 있어** `READ_MEDIA_AUDIO`(일반 권한)로 읽으면 끝 → 콜캐치 권한 통째 우회 + Play 정식 배포. **STT→AI 14필드 파싱은 그 위에 얹는 확장 레이어**(폭넓은 확장성 — 자동 티켓·사후 검색·손님 이력 — 주지만 권한 우회의 핵심 아님).
**중요도**: ★★★ 본인 "우리 프로젝트에 획기적인 전환". 배포 차원 해제(사이드로드 감옥 → Play 정식 배포)가 진짜 무게.
**관련**: [[ptt_implementation_2026-06-02]](같은 manager-direct-drive 트랙), CLAUDE.md §콜매니저 §콜디텍터(콜캐치 권한), `memory/callmadang_master_2026-04-27.md`(식당 4중 노드·OS 비전)

## 1. 핵심 전환 — "콜을 가로채지 말고, 끝난 녹음(블랙박스)에서 번호를 읽는다"

- **콜캐치(라이브 전화 감지)의 문제권한** = `READ_CALL_LOG`. Android 10+ 에서 `PHONE_STATE` 의 `EXTRA_INCOMING_NUMBER` 를 얻으려면 필수인데, Google Play **Call Log 권한그룹 제한**(기본 전화/비서 앱만) → 콜매니저·콜디텍터 **사이드로드 전용**의 근본 원인. **콜캐치의 목적 자체가 "걸려온 번호 확보"** 였음.
- **우회 (알맹이)**: 삼성이 자동 녹음한 파일의 **파일명에 번호+시각이 박혀 있음** → `READ_MEDIA_AUDIO`(일반 권한, 또는 SAF)로 읽어 **번호 추출**. 정규식 한 줄, STT·AI·`READ_CALL_LOG` 전부 0. **"번호+타임스탬프+음성파일"** = 통화기록 권한 없이 *오디오 딸린 통화 이력* 재구성.
- **6/4 중심 정정 (본인)**: 파싱이 중심이 아님. **연락처(번호)가 권한 우회의 알맹이.** 파싱은 확장 레이어.
- **파일명 번호의 한계 (정직)**: 미지 발신자(신규 손님)=raw 번호 ✓(배차 케이스 대부분) / 저장 연락처=이름(예 `보람푸드`,`양평군청`)→번호 대신 이름. 저장연락처 raw 번호는 파일명만으론 못 얻음(소수).
- **블랙박스 정합 (6/4)**: 모든 통화가 블랙박스로 남으면 **정보 유실 0** → 파싱이 *"캡처(놓치면 끝)"* 에서 *"사후 검색·편의"* 로 강등. 통화 순간 구조화 불필요. 라이브 전달은 **PTT가 음성으로 직접**(매니저→기사) → 구조화 티켓 불필요. 견고 코어 = **블랙박스(삼성 녹음) + 번호(파일명) + PTT(활성 트랙)**, 권한 0·로컬 우선.

```
[기존 콜캐치]  통화 울림 → PHONE_STATE 가로채기 → 번호    ← READ_CALL_LOG (Play 차단, 사이드로드 강제)
[코어]         통화 끝(블랙박스 녹음) → 파일명서 번호 추출 → PTT 실시간 전달   ← READ_MEDIA_AUDIO (권한 우회, Play 자유)
[확장 레이어]  + STT → AI 파싱 → 14필드 (사후 검색·자동티켓·손님이력, 라이브 루프엔 불필요)
```

## 2.5 ★ 배포 차원 해제 — Play 정식 배포 가능성 (2026-06-03 정책 검증 GREEN)

본인 직감("웹페이지 APK 다운과 차원이 다른 문제"·"정식 앱서비스 가능") = **정책 텍스트가 받쳐주는 실재.** 진짜 무게는 입력 자동화가 아니라 **콜마당 안드로이드 앱을 사이드로드 감옥에서 꺼내는 것** (출처불명 경고·Play Protect 차단·자동업데이트 0·검색노출 0·비기술 사장님 신뢰적자 = 식당 4중 노드 보급의 첫 벽).

**Play Console 정책 실독 결과** (출처 하단):
| 장벽 | 정책 문구 | 우리 적용? |
|------|----------|-----------|
| 통화녹음 앱 금지(2022) | 접근성 API는 *"remote call audio recording"*(녹음 행위)에 사용 불가 | ❌ 우리는 녹음 안 함(삼성이 함)+접근성 안 씀. *기존 파일 읽기·재생은 정책이 안 다룸* |

→ **Play 두 주요 차단은 "전화 가로채기·직접 녹음 행위"를 겨냥. 우리 구조는 둘 다 안 함.**

**⚠️ 단 하나의 회색지대**: Call Log 정책 *"alternative methods로 Call Log 귀속 데이터 파생 금지"* 문구 → **파일명 번호 추출**을 까다로운 심사관이 우회파생으로 볼 *이론상* 여지. 회피책: 번호는 음성/대화에서 얻고 파일명은 보조로만, Data Safety 선언에 "통화기록 재구성 아님" 명시. 거부사유 X, 선언 설명 항목.

**iOS = 비이슈로 닫힘**(본인 6/3): 콜매니저 **안드로이드 전용**으로 감. iOS는 서드파티 통화녹음 접근 원천차단(폴더·API 없음) → 이 경로 본질적으로 안드로이드(사실상 한국삼성) 전용인데, 콜매니저는 매니저 단말이라 무관. 매니저 = 통화 당사자(당사자 녹음 합법) 재확인.

## 3. 아키텍처 골격 (제안, 코드 미진입)

```
통화 종료 → (FileObserver/MediaStore observe) 새 .m4a 감지
  → "새 통화 녹음 — 파싱?" 배너  ← 거의-자동 UX, 미디어 권한만
  → content URI 오디오 → Cloud Function 업로드
  → 한국어 STT(Clova/Whisper/VITO 등) + 양평 지명 phrase-hint
  → LLM 필드 추출(출발/목적/인원/요금/메모) → JSON
  → NewCallInputDialog 프리필 → 매니저 확인·수정 후 배차
```
- 파일명에서 **콜백 번호·시각 즉시 파싱**(STT 전, 권한 0).
- 지연: 통화 후 ~5~15초 프리필 준비(운영 흐름과 안 어긋남).
- 비용: STT 분당 수십원 + LLM 저렴 → 콜당 무시 가능.

## 7. 6/4 추가 — STT 실측 데모 / 비용 / 로컬우선 / 지연

**STT 실측 데모 (진짜 녹음 1건, 권한 우회 경로 end-to-end 입증)**:
- 본인 제공 파일 `CALL_6보람푸드…센트롤시티_20231101_214613.m4a`(21.5초, 663KB)를 PC로 가져와 faster-whisper 전사.
- ⚠️ HF 대용량 모델 다운로드 이 환경 throttle(tiny 75MB OK / medium·large 행). **small(484MB)로 성공.** large-v3·클라우드면 정확도 더↑.
- small **STT 실제 출력**(원문 그대로): "네 네. 맞죠 네. 그리고 하나는 부르지 말잖아요. 네 네. **센트럴시티**. … 저기 **주소지 한 번만 다시 불러주시겠습니까?** **아신길**. 네. **41.13**. 41.13. 알겠습니다." (거친 단편)
- AI 파싱(추론·보정 명시): 지명 후보 **센트롤시티**(STT "센트럴시티" 보정)·**아신길** 추출 + 주소번지 STT "41.13" → 파일명 이력 "아신길 41-3" 대조 시 **41-3 추정**. ⚠️ **출발/목적 어느 쪽인지·콜 종류(식당 대리호출인지)는 21초 단편으론 확정 불가 = 추정**. 요금·인원 미포착(정직한 불확실 표시).
- 입증된 것(과장 없이): ① **녹음→STT→텍스트 변환이 실데이터로 작동**(권한 우회 경로 end-to-end) ② 거친 STT에서도 AI가 지명 후보 추출·오인식 보정·모르는 건 모른다 표시. **규칙 파서(CallMemoParser)는 마커(에서/까지) 없는 이 날것 대화를 못 풂** — AI 파싱 우위. (단 large-v3/클라우드면 정확도·완성도 더↑. 이 터미널은 데모지 제품 아님.)

**구조 = 2단계 (본인 확인)**: 음성→[STT]→텍스트→[파싱]→필드. 각 단계 돌파구 1개씩: ① STT는 소스를 녹음파일로 → 권한 우회·Play 배포 / ② 파싱은 규칙 대신 AI → 날것 대화 처리.

**비용 (콜 1건 ≈ 1.5분 기준, 근사·빌드시 재확인)**:
- 녹음=0(삼성), STT 온디바이스=0 / 클라우드 12~35원, AI파싱(Haiku급)=3~10원.
- **온디바이스 STT+AI = 콜당 ~5원 / 클라우드 STT+AI = ~20~45원.** 사무실당 월 ~3,000~27,000원 → 구독료에 묻힘(콜당 과금 아닌 운영비).

**온디바이스 STT 경로 (파일→텍스트, 클라우드·whisper 다운로드 불필요)**:
- **Android 13+ `RecognizerIntent.EXTRA_AUDIO_SOURCE`**: SpeechRecognizer에 마이크 대신 *파일/스트림*을 입력하는 공식 API(이 폰들 Android 15라 가능). VoiceInputHelper에 몇 줄 추가하면 녹음 파일을 폰 STT로 직접 전사 — **whisper 모델 다운로드 자체가 불필요**. 단 인식기별 지원·포맷 제약 실측 필요.
- **OneUI 내장 통화녹음 텍스트 변환**: 최신 OneUI(Android 15)는 녹음 앱에서 통화 녹음을 자체 전사. 코드 0 옵션(검증 필요).
- (참고: 현 VoiceInputHelper는 마이크 전용 → 파일 못 먹임. 위 ①로 전환 또는 클라우드.)

**로컬 우선 (본인 지적 — 콜매니저 ★Local-First 정합)**:
- 폰 내장 STT 쓰면 클라우드 거칠 이유 0. AI 파싱도 온디바이스 소형 LLM(Qwen2.5-1.5/3B·EXAONE 번들) 가능 → **완전 로컬·콜당 0원·오프라인·사생활**.
- 권장 = **로컬 우선 + 저신뢰 콜만 클라우드 폴백(텍스트만 전송, 음성 X)**. 대부분 콜은 클라우드 미경유.
- ⚠️ 이 단말(S21+/S22)은 Gemini Nano/AICore 미지원(S24+/Pixel8+부터) → OS 내장 온디바이스 LLM 불가 → 앱에 소형 모델 번들(앱 ~1~2GB↑, 파싱 수 초). 매니저 1대 일 ~20콜이면 부담 0. **온디바이스 소형 모델 정확도 충분한지 실측 필요.**

**지연 (통화 후)**: 번호=파일명서 ~1~3초(★순간) → 즉시 PTT 전달. 텍스트화=통화 길이 비례(30초콜 ~2~5초 / 2분콜 ~10~30초 온디바이스). 파싱=수 초. **번호는 순간, 전체 파싱은 통화 끝+수 초~수십 초.** 라이브 중 텍스트화는 불가(녹음 본질=통화 후). 체감은 즉각(번호+PTT 즉시, 필드는 백그라운드 채움).

**연락처 권한 디테일**: 미지 발신자=파일명 raw 번호 ✓ / 저장연락처=이름(raw 번호는 `READ_CONTACTS`로 복구, 일반권한·Play 자유·근데 코어엔 불필요) / 번호숨김=어떤 방법도 불가(READ_CALL_LOG도 못 얻음). **최소권한(`READ_MEDIA_AUDIO`만) 출시 권장**, 필요 입증 시 READ_CONTACTS 추가.
