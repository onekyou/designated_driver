# 콜마당 손님앱 분리 — Claude Code 인수인계

> 작성일: 2026-04-23
> 목적: 손님앱을 두 개로 분리하는 결정의 배경·스펙·제약을 Claude Code에 인수인계

---

## 1. 결정 요약

**기존 손님앱을 두 개로 분리한다:**

| 앱 | 상태 | 주 사용자 | 현재 우선순위 |
|---|---|---|---|
| **업소용 앱** | 신규 개발 | 식당 관리자 | **최우선** |
| 일반 손님용 앱 | 기존 유지 | 일반 손님 | 유휴 (당분간 건드리지 않음) |

기존 4앱 아키텍처(콜디텍터·콜매니저·기사앱·손님앱)에서 손님앱만 둘로 분화 → 5앱 구조.

---

## 2. 분리 결정 근거

사용자 행동이 완전히 다름:

| 항목 | 업소용 | 일반 손님용 |
|---|---|---|
| 사용 순간 | 취객 발생 시 초 단위 조작 | 본인 이동 시점 |
| 위치 | 식당 고정 | 이동 중 |
| 목적지 | 불필요 (기사 현장 협의) | 필요 |
| 사용 빈도 | 영업일 반복 | 가끔 |
| UI 요구 | 극단적 단순성 | 기존 손님 플로우 |

같은 앱에 두 경로 공존시키면 업소용 UX가 반드시 타협됨. 식당 사장님(50-60대, 아날로그 성향)에게는 부담 0 UX가 작동 조건.

---

## 3. 업소용 앱 스펙

### 3.1 핵심 기능 (MVP 범위)

**① 단순호출 버튼 (유일한 핵심 기능)**
- 버튼 1회 클릭 → 현재 위치(식당 고정 좌표)만 전송
- 목적지 입력 **없음** — 기사가 식당 도착 후 손님과 현장 협의 (기존 전화호출 방식 그대로)
- 관리자 앱(콜매니저) 수신 → 기사앱으로 전달
- 실질 포지션: **기존 전화호출의 데이터판 대체**

**② 포인트 적립/차감**
- 기존 일반 손님앱의 포인트 차감 구조 **그대로 재사용**
- 호출 요금의 X% 적립 (비율은 업체 협의로 결정 예정)
- 사장님 본인이 대리 이용 시 포인트만큼 요금 차감
- 거리 차등(10,000원~50,000원)은 비율 기반이라 자동 흡수
- 포인트 부담 주체: **해당 호출을 받은 업체** (식당 전속 업체가 있으면 그 업체, 없으면 공유콜 수신 업체)

### 3.2 설계 원칙

- **극단적 단순성**: 버튼 하나가 전부. 추가 기능 요구 있어도 거부
- **속도 최우선**: 취객 발생 순간 2-3초 내 호출 발송 완료
- **식당 관리자 = 주 사용자**: 일반 손님 시나리오는 이 앱에 들어가지 않음
- **광고/추천/랭킹/비교 없음**: 기존 콜마당 원칙(플랫폼화 경로 차단) 유지

### 3.3 들어가지 않는 것 (명시적 제외)

- 목적지 입력 UI
- QR 스캔 귀속 로직 (이건 일반 손님앱 기능)
- 다른 식당 탐색/추천
- 이벤트/프로모션 푸시
- 랭킹/리뷰/비교
- 지도·거리순 매장 리스트
- 일반 손님용 시나리오 전부

## 4. 아키텍처

### 4.1 백엔드

- **Firebase/Firestore 기존 구조 그대로**
- 업소용 앱은 사실상 **일반 손님앱의 축소 복제**로 시작 가능
- 공통 백엔드 재사용, 프론트만 분기
- 귀속노드 구조 그대로 활용 (식당이 특정 업체에 귀속 가능, 귀속 없으면 공유콜 풀)

### 4.2 호출 분배 로직

업소용 앱 호출의 라우팅:
1. **1순위**: 식당이 귀속된 전속 업체 (있는 경우)
2. **2순위**: 전속 업체 미응답 또는 귀속 없음 → **공유콜 풀**로 자동 확장
3. **포인트 부담**: 그 호출을 실제 받은 업체가 짐

※ 기존 귀속노드 아키텍처로 대부분 커버될 가능성 높음. 재사용 가능 여부 확인 필요.

### 4.3 Play Store

- 업소용 앱은 **별도 Play Store 등록 필요**
- Google Play 비공개 앱 경로로 심사 (조직 계정 calllink.io.kr 이미 검증됨)
- 일반 손님앱 심사 통과 경험 있으므로 부담 낮음

## 5. 영업·전략 맥락 (참고용 — 설계 판단 시 고려)

Claude Code가 기능 제안할 때 전략과 충돌하지 않도록 참고만:

**전체 전략 구조:**
1. 대리업체들에 "콜마당 깔기만" 요청 (수수료 0, 약속 0) → 거절 논리 제거
2. 원규씨가 식당 영업 → 업소용 앱 설치 → "해보기만 하세요"
3. 식당 호출이 **공유콜 풀**로 흘러감 → 업체들이 "이게 되네" 체감
4. 업체들이 자발적으로 그 식당 전속 영업 → 식당-업체 귀속 발생
5. 포인트 부담이 전속 업체로 자연 이전 (원규씨 자금 부담 0)

업소용 앱은 이 전략의 **핵심 도구**. UX 복잡해지면 전략 전체가 무너짐.

---

## 6. 우선순위

1. **업소용 앱 MVP**: 단순호출 버튼 + 포인트 표시. 이거 하나.
2. 공유콜 → 전속 업체 라우팅 로직 재확인 (기존 구조로 커버되는지)
3. Play Store 등록 경로
4. 나머지는 현장 피드백 이후.

---

## 7. 현재 확정되지 않은 것 (Claude Code가 가정하지 말 것)

- 앱 공식 명칭 ("콜마당 업소" / "콜마당 Biz" 등 미정)
- 포인트 적립률 % (업체 협의 예정)
- 업소용 앱 내 포인트 UI 상세 (적립 현황 표시 방식 — 숫자? 시각화?)
- 관리자 앱(콜매니저) 쪽 UI 변경 여부

이 항목들은 원규씨 판단 영역. 질문으로 올라올 경우 임의 결정 금지.

## 8. 관련 기존 자산

- 콜마당 4앱 코드베이스 (Kotlin/Compose, Flutter 혼재)
- Firebase/Firestore 스키마
- 귀속노드 특허 출원 구조
- CLAUDE.md 컨텍스트 로더 (기존 세팅)
- Play Console 조직 계정 (calllink.io.kr)
