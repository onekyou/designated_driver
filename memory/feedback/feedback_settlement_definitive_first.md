# 기존 로직 영역 — 명문화 우선 원칙

## 규칙
정산·인증·결제·상태 머신처럼 *코드에 이미 살아있는 로직 영역*은 본인에게 *추측 질문 X*. 코드 전수 확인 → 명문화 파일 작성 → *명문화에서 답이 안 나오는 자리만* 본인에게 질문.

## Why
2026-05-25 §3 정산 이월 단순화 의사소통 중 본인 강한 지적:
- "포인트는 사무실 실손이라니까 기사를 건드리면 안돼. 이미 로직이 그렇게 돌아가고 있는데 왜 확인도 않하고 계속 물어보지?"
- "기존 로직부터 확인하고 차라리 모든 정산 로직을 명문화 해 파일로. 이런 식의 소모전은 힘들어."

문제 행동: 클코가 `calculateRealIncome`의 `- pointSum` 한 줄만 보고 본인에게 "기사 몫은?"이라고 *추측 질문* → 본인이 이미 코드로 다 들여다본 자리를 *다시 묻는* 소모전 발생.

## How to apply
1. 본인이 "현 [로직] 파악하고 질문해" 또는 비슷한 자리에서:
   - **즉시 코드 전수 읽기**. 추측 질문 X
   - 명문화 파일 1개에 *코드 그대로* 정리 (`memory/[도메인]/[topic]_definitive_YYYY-MM-DD.md`)
   - 명문화에서 *코드로 답이 안 나오는 자리*만 본인에게 질문
2. 1차 코드 읽기 후 "더 확인해도 될까요" 묻지 말 것 — *자명한 자리*는 직접 읽기
3. 명문화 작성은 *큰 단위 1개 파일*. 조각 메모리 X. 단일 출처 유지
4. 본인이 *기억으로 답*한 자리 (예: "영업일 오전 10시")는 코드와 *대조*해서 *정합/불일치* 명시. 본인 기억 *맹신 X*
