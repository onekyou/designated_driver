# 자기 모니터링 한계 — 확인 전 단정 금지 (근본 줄기)

## 규칙
코드·기능·변수를 특정 *트랙/시스템/원인에 귀속*하거나 line 번호·컴파일 상태·"무관 파일"을 *사실로 보고*하기 전 — **코드/데이터/diff로 1건 검증**. "추정"이 떠오르는 그 순간이 검증 트리거. 본인이 짚어주지 않아도 *자발 진입*.

## Why
2026-05-28 ~ 05-29 **두 세션 연속 재발** (단발 실수 X = 패턴):
- **5/28**: line 번호·무관 누적 파일을 git diff 확인 없이 사실처럼 보고 + 컴파일 "OK" 추정 + "자기 자기" 발화 누적. 본인이 *두 번* 짚어서야 도달.
- **5/29 (정산 재설계 commit 4 진입)**: `pointsUsed` 변수 하나만 보고 "5/4 P0 포인트 결제 풀 = 쿠폰 트랙"으로 *코드 확인 없이 트랙 귀속 단정*. 실측 = 기존 손님 리워드 포인트 결제(식당 4중 노드 포인트 + customer_app + functions/points.js 계열) — **쿠폰(할인권)앱과 다른 시스템**. 본인 "쿠폰트랙이 왜 나오지?" 지적으로 정정.

**근본 줄기**: 메모리 연상(변수명 → 기억 속 트랙/원인)이 *코드 검증을 우회*해 사실로 굳는다. plan 승인의 권위를 자기 추정으로 덮어쓰는 두 방향 — ① 매 turn "할까요?"로 승인 동의를 반복 부정 ② 검증 없이 단정해 plan 전제 자체를 오염. `feedback_grep_all_paths`(코드 경로)·`settlement_definitive_first`(코드 영역 추측 질문)의 *트랙·귀속 버전*. 발화 톤(자기 자기)·인계 line 추정·클로징 인터뷰 누락은 모두 이 한 줄기의 *표면 증상*.

## How to apply
1. **귀속 단정 전 코드 1건 검증** — "이건 X 트랙/기능/원인이다"라고 말하기 전, 그 코드가 *실제로 뭘 하는지* Read. 변수명 연상으로 귀속 X.
2. **"추정"/"~ 같음"/"~ 일 것" 자기 사용 시점 = 검증 트리거** — 그 자리에서 해당 자리 1건 diff/Read 확인 자동 진입.
3. **사실(검증함) vs 추정(미검증) 단어로 분리** — 보고 시 "실측"/"추정" 라벨. line 번호·컴파일·무관 파일은 검증 전엔 "추정".
4. **plan 권위 존중 ≠ 검증 생략** — Auto Mode plan 승인 후 매 turn "할까요?" 금지(진입 자체가 동의). 단 *허락*과 *검증*은 다름 — 검증은 허락 없이 자발.
5. **외부 짚음 없이 자발 자체 검증** — 토스/인계 시점 클로징 인터뷰(컴파일/line/무관 누적/누락 자리) 자가 점검 후에만 보고. 본인 지적 의존 X.
