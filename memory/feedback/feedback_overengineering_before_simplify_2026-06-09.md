# 단순화 신호 전 과설계 금지 — 기존 자산 둘 다 있는데 새 파이프라인 제시 (2026-06-09)

**유형**: feedback (작동 방식)
**관련**: CLAUDE.md §대화원칙 8(단순엔 단순)·§실행원칙 4(요구 이상 수정 금지)·§Claude 실행 규칙(선택지 나열 질문 금지)
**재발**: [[feedback_rabbithole_scope_2026-06-04]]의 *같은 패턴 반복* — 이번엔 다운로드/인프라 대신 "정교한 아키텍처 + 승인질문"으로 나타남.

**무엇**: "PTT 발화↔콜 연결" 작업에서, 클코가 온폰 SpeechRecognizer vs 서버 faster-whisper STT·기사명 매칭·빈카드 자동생성·헛예약0 안전장치까지 **정교한 파이프라인을 설계하고 AskUserQuestion 2회**(STT 아키텍처·배차 안전장치)로 끌고 감. 원규씨가 *"배차팝업에서 기사 지정 + PTT로 어디 가라 음성지시면 됨. 너무 어렵게 생각하는거 아닌가?"* 로 재중심시킴 → 두 부품(배차팝업 기사지정 / PTT 음성방송)은 **이미 둘 다 구현·작동**, 음성파싱은 통째로 불필요.

**Why (왜 문제)**:
- 탐색 단계에서 `assignCallToDriver`(필드 nullable=무타이핑 배차 가능)·`NewCallAssignmentDialog`·PTT 인프라(완성)를 *이미 봤으면서* 그걸로 행동0이 충족됨을 못 보고 새 파이프라인으로 감.
- "행동0 = 매니저 단순지시"라는 *목표*를, 이미 있는 수단으로 달성됨을 확인하기 전에 *새 구현수단*(음성명령)으로 점프.
- 승인질문 2회 = 헌장 "할까요/어느 쪽 금지" 경계. 단순 경로를 먼저 제시·검증했으면 질문 자체가 불필요.
- 그 과설계가 MEMORY/결정대장에 "다음 작업"으로 박혀 있어, 점검 안 했으면 다음 세션이 재드리프트할 뻔(결정대장 [폐기·과설계] 도장으로 차단).

**How to apply (다음에)**:
1. *목표*(행동0 등)를 들으면, 새 코드 짓기 전 **"기존 부품 조합으로 이미 되는가?"** 부터 답한다. grep으로 본 자산을 흘리지 말 것.
2. 정교한 아키텍처·승인질문으로 가기 전, **가장 단순한 가설을 1줄로 제시**해 원규씨가 깎을 기회를 먼저 준다.
3. 원규씨가 "단순/너무 어렵게"를 말하면 즉시 멈추고 *복잡함을 도로 끌어오지 말 것*(CLAUDE.md §8).
4. 과설계가 메모리에 "다음 작업"으로 남으면 walk-back을 **결정대장에 도장**(서사에 묻지 말 것) — 재드리프트 차단.
