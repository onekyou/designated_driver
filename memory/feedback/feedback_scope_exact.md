# "딱 거기까지만" 스코프 디시플린

사용자가 "여기까지만", "딱 거기까지만", "그 정도만" 같은 표현으로 스코프 경계를 명시하면 엄격히 지킬 것. 관련 영역이라도 명시 범위 밖은 건드리지 않음. 플랜 작성 시에도 "원안에 없던 확장" 은 반드시 투명 공개 + 제거/유지 선택권 제공.

**Why:** 2026-04-24 세션 — 픽업기사앱 Phase 2 아키텍처 전환 논의에서 사용자가 "맞아 정확해 현 구조를 **딱 거기까지만** 바꾸는거야" 확정.
- 적용: "내 담당" 탭만 신규 로컬 우선 구조, 기존 MVP 대시보드(calls listener) 는 건드리지 않음. 향후 이관 여부도 지금 결정 안 함.
- 플랜 검토 시 내가 임의 추가한 3건 모두 사용자가 제거 요청:
  - `cancelReason` 필드 ("스키마리스라 비용 없음" 논리) → 제거
  - FCM 메시지 타입 이름 3종 사전 합의 → 제거 (Step 2+ 에서 결정)
  - "참고 패턴" 섹션 Step 2~6 미리보기 → 유지 (아키텍처 방향 명시용)
- 기준: "현 Step 결정에 직접 필요한가" vs "미래 Step 에서 결정해도 되는가". 후자는 모두 제외.

**How to apply:**
- 플랜 작성 시 "원안에 없던 추가" 는 반드시 **투명 공개** + 사용자 선택권 제공
- "스키마리스라 비용 없음"·"어차피 나중에 필요" 같은 논리로 현재 스코프 확장 금지 — 비용 없음 ≠ 추가 근거 있음
- 아키텍처 전환 시 "기존 구조 건드리지 않음" 이 기본. 연관 영역 점진 이관은 사용자가 명시 요청할 때만
- 자기 점검 질문: "지금 추가하려는 이것, 현재 Step 의 의사결정에 **직접** 필요한가?" 아니라면 해당 Step 플랜에서 제거
- 사용자가 명시한 짧은 구절("딱 거기까지만" 등) 은 그대로 플랜 문서에 인용해 스코프 고정
