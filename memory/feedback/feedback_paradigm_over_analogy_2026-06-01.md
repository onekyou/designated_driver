# 프로젝트 패러다임 > 도메인 비유 (신규 기능 설계 순서)

**확정**: 2026-06-01 (본인 적발 — "처음부터 알림 기반으로 기획한 건데 너가 그걸 모르는 이유는? 다음부터 이런 사태 미연 방지")

## 사건

PTT 수신측 블랙아웃(Doze) 문제 설계 시, 클코가 **"수신측 상시 Foreground Service + 상시 채널 join"**을 메인 권장으로 올림. 본인 교정: "알림을 먼저 보내는 방식으로 정한 것 아냐? 알림이 상대방 깨우면 바로 연결되는 거잖아." → 콜마당은 *발화 시 high-priority FCM Data Push로 수신측 wake → RTC join* (Trigger Join). 상시 join은 콜마당 listener 최소화 철학 정면 위반.

## 원인 3겹

- **(a) 표면**: 메모리에 "PTT 음성 = FCM wake"가 콕 집힌 문장으로 없어, 빈자리를 외부 추론으로 채움
- **(b) 진짜**: 이미 박힌 피드백 [[listener_vs_fcm]](신규 기능 설계 시 리스너 vs FCM+로컬 트리거 자동 비교, **기본값 FCM**)을 *적용 못 함*. 메모리가 없어서가 아니라 *있는 메모리를 신규 설계에 자동 적용 실패*. 오히려 상시 listener/join을 기본값으로 올려 정면 위반
- **(c) 더 깊이**: 도메인 비유("무전기처럼")의 *UX 목표(이질감 0)*를 *구현 아키텍처(상시 켜진 수신기 = 상시 join)*로 직역. 비유가 프로젝트 패러다임을 덮어씀

**Why**: 프로젝트엔 확립된 아키텍처 철학(Data Push / listener 최소화 / 기본값 FCM)이 있다. 신규 기능은 이 철학의 *적용 사례*여야지, 외부 일반지식·도메인 비유에서 새로 끌어온 설계여서는 안 된다. 비유의 물리 속성을 구조로 직역하면 프로젝트 정체성과 어긋난 설계가 "본인 결정 자리"로 위장되어 올라간다.

**How to apply**:
1. 신규 기능 설계 = **프로젝트 패러다임 체크가 1번 단계**. 외부/도메인 지식보다 [[listener_vs_fcm]]·Data Push·listener 최소화를 먼저 적용. 외부 추론은 그 다음
2. **프로젝트 패러다임 위반 옵션을 "본인 결정 자리"로 올리지 말 것**. 배제하거나, 올리면 "이건 ○○ 원칙 위반"이라 명시. 위반 옵션을 동등 선택지로 펼치는 것 자체가 오염
3. **도메인 비유는 UX 목표로만 받고 구현은 패러다임으로 푼다**. "무전기처럼" → "이질감 0"으로 번역하고 멈춤. 물리 속성(상시 ON)을 구조로 끌어오지 않음
4. **메모리 미명시 대전제는 일반추론으로 메우지 말고 확인**. "문서에 없는데 기존 패러다임상 X로 보임 — 맞나?" (5/31 [[feedback-no-false-attribution]] 정합 — 빈자리를 추론으로 채워 사용자 결정으로 위장 금지)
