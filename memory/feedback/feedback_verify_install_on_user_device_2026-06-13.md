# 빌드 검증은 사용자 실사용 단말에 — 개발 연결 단말에만 깔고 "완료"라 하지 말 것 (2026-06-13)

픽업앱 알림음(ptt→기본음) 수정 후 **Z Flip4(R3CT80K78NP)에만** 설치하고 dumpsys로 채널 확인 →
"검증 완료"라 보고했다. 그런데 원규씨가 실제로 픽업앱을 쓰는 단말은 **S22(R5CT41TJZFP)**였고,
S22엔 새 빌드를 안 깔아 **옛 빌드(ptt음 채널) 그대로** → "픽업앱 ptt음이 계속 난다"는 혼선이 발생했다.
S22를 dumpsys로 보고서야 `pickup_call_changes_ptt`·`chat_messages_ptt`(옛 ptt 채널)가 남아있음을 확인,
새 빌드를 S22에 설치해서야 해결됐다.

**Why:** "개발 PC에 연결된 단말 중 하나에 깔고 채널 실측 = 검증"이라 착각했다. 검증의 목적은
*사용자가 실제 겪는 상태*를 보장하는 것인데, 사용자가 보는 단말과 내가 설치한 단말이 달랐다.
CLAUDE.md 기기표(어느 앱이 어느 폰)와 실사용은 다를 수 있고, 한 앱이 여러 폰에 깔려 있을 수 있다
(픽업=S22·Z Flip4 양쪽). 한 대만 검증하고 "전부 됨"으로 일반화한 것 = 부분 검증의 과대 보고.

**How to apply:**
1. 앱 수정·검증 시 **그 앱이 깔린 모든 단말**을 먼저 확인(`adb shell pm list packages`)하고 **전부 설치**한다.
2. 특히 사용자가 "특정 단말에서 증상"을 말하면 **그 단말을 직접** 조회/설치(다른 단말 결과로 갈음 금지).
3. "검증 완료"라 말하기 전, *어느 단말에서* 검증했는지와 *사용자 실사용 단말*이 일치하는지 명시.
4. 채널 사운드처럼 ID 박제/캐싱되는 것은 옛 빌드 단말에 잔존 → 단말별 dumpsys로 실상태 확인.
