# 검증된 자산을 두고 통념으로 드리프트하지 말 것 (2026-06-08)

콜매니저 통화예약 파일럿 STT 엔진 선택에서, **우리가 6/7에 직접 통과시킨 건 faster-whisper 하나뿐**
(.m4a 네이티브✅ / 한국어 정확 "옥천명→옥천면 복원"✅ / 무료·로컬·PII안전✅)인데,
**한 번도 안 돌려본 Google Cloud STT를 "표준이라 쉽다"는 통념으로 1순위에 올렸다.**
실제로 Google STT는 .m4a를 직접 못 먹고(변환 필요) 한국어 품질도 미검증 — 검증된 걸 두고 미검증을 기본값으로 민 것.

원규씨 정정: "왜 검증된 faster-whisper 두고 안 해본 구글로 샜냐. 기본은 faster-whisper. 서버 무게가 진짜 문제면 그때 따지자."

**Why:** "구글이 표준/관리형이라 쉽다", "whisper 서버에 올리면 무겁다" 같은 **일반 통념**에 끌려
*오늘 우리 손으로 통과시킨 사실*을 무시했다. [[feedback-overask-confirm-2026-06-08]]의 "이미 정해진 걸 되묻기"와
같은 뿌리 = **헌장·세션 맥락을 잊고 LLM 사전훈련 통념으로 회귀하는 병.** ("C vs W 끝났잖아"도 같은 결.)

**How to apply:**
1. 선택지 비교 시 **"우리가 이번에 직접 검증한 것"을 최우선 가중**. 검증된 자산 = 기본값.
2. "표준이라/쉽다/일반적으로" 같은 통념 근거가 검증된 사실을 *덮으려* 하면 멈추고, 검증 데이터를 먼저 본다.
3. 통념상 단점(예: "무겁다")은 **구현 디테일로 따로 처리**할 문제지, 검증 자산을 버리고 기본값을 바꿀 이유가 아니다.
4. 미검증 대안은 "fallback/교체지점"으로 격리(swap point)해 두되, *출발 기본값은 검증된 것*.
