# 배차 STT 메모 — 누가 말하는가

## 사실

`call_manager` 와 `call_detector` 의 **배차 팝업 정보카드 길게 누르기 → STT 녹음** 흐름은 **관리자(사용자, 박상준 사장님 류)** 가 손님 통화 후 정보 종합해서 입력하는 것. **손님이 직접 말하는 게 아님**.

세부:
- 사장님이 손님 콜 받음 (전화)
- 통화 끝나거나 통화 중 사장님이 정보 종합
- 사장님이 배차 팝업 길게 눌러 STT 시작
- 사장님이 "용문에서 시장까지 삼만원" 같은 정보 발화
- STT 결과 → CallMemoParser.parse → calls/{id}.memoText + 4 필드 저장

관련 파일:
- `call_manager/.../ui/dashboard/DashboardScreen.kt` 라인 1620~1640 (STT 발화 처리)
- `call_detector/.../ui/DispatchDialog.kt` 라인 160~170
- `memory/plan_dispatch_memo_2026-04-24.md` (구현 이력)

## 발화 패턴 차이

**관리자(사장님) 발화 적합** (실제 시나리오):
- 짧은 평서형/격식체 정보 전달
- "용문에서 시장까지 삼만원"
- "이만오천원입니다"
- "양평 거쳐 용문까지 사만원이에요"
- 종결어미: 입니다/이에요/예요/에요/습니다/거든요 (평서·격식)

**손님 발화 (이 시나리오엔 안 등장)**:
- "용문에서 시장까지 가주세요"
- "삼만원이에요"
- "부탁드립니다"
- 종결어미: 가요/갑니다/주세요/갑시다/오세요/부탁드립니다 등

## 룰 설계 가드

향후 Phase C/D 진행 시 다음을 따를 것:

1. **종결어미 룰 추가 시**: 사장님 발화에 등장 가능한 평서/격식체만. 손님 발화 전제(명령형/청유형/부탁형) 제외.
2. **테스트 케이스 발화 패턴**: 사장님이 정보를 메모하는 톤. "X에서 Y까지 Z원" 형태가 표준.
3. **외부 데이터 흡수 시**: AI Hub 콜센터 발화나 NIKL 구어 말뭉치 등의 데이터를 그대로 흡수하지 말 것 — 데이터의 화자가 사장님 시나리오와 맞는지 검증 후 흡수.

## 발견 경위

2026-04-26 Phase B-ext (Option 2 큐레이션 확장) 도중 사용자 지적:
> "출발지와 경유지 도착지 요금에 대한 손님의 말이 아니고 이를 들은 관리자가 전달하는 것이라는 것을 인식하고 지금 작업하는거야?"

이전엔 손님 발화 가정으로 종결어미 17개 추가했음. 사용자 정정 후 Option A 적용 — 사장님 발화 적합 8개만 보존, 9개 제거.

## 향후 활용

- AI Hub "한국어 콜센터 음성" 데이터셋은 손님 발화 위주일 가능성. 적용 시 화자 분리 필요.
- NIKL 모두의 말뭉치 구어 부분은 일상 대화 위주. 콜 메모와 직접 맞지 않음.
- **사장님 발화 데이터** 자체가 가장 정확한 ground truth. 박상준 사장님 영업 데이터(`offices/{o}/calls/{id}.memoText`) 가 1차 자료가 될 수 있음 — 표본 충분히 쌓이면 분석 가치.
