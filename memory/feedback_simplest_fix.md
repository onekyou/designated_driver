---
name: 최소 수정 우선 원칙
description: 복잡한 대안 제시 전에 최소 수정으로 해결 가능한지 먼저 확인할 것. 사용자 제안에 무조건 동의하지 말고 스스로 검증할 것.
type: feedback
---

복잡한 리팩토링이나 블록 제거를 제안하기 전에, 기존 코드의 조건문 한 줄 수정으로 해결 가능한지 먼저 확인할 것.

**Why:** presence #1 블록 즉시 복귀 문제에서 블록 제거, 경고 제거 등 여러 대안을 오가며 시간을 낭비함. 실제로는 `&& isTimedOut` 한 줄 추가가 정답이었음. 또한 사용자가 방향을 제시할 때 검증 없이 동의하는 패턴이 반복됨.

**How to apply:**
1. 문제 발견 시 가장 작은 수정부터 검토
2. 기존 코드의 조건문 변경으로 해결 가능한지 우선 확인
3. 사용자 제안이라도 기존 로직과의 영향을 스스로 분석한 후 의견 제시
