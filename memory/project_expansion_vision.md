## 확장 로드맵

1단계: **대리운전** (현재) — 2000개 사무실 목표
2단계: **식당 + 배달앱** — 동일 모델 적용 예정

## 식당/배달 확장 구체안

- 손님이 **식당에 직접 귀속** (QR로 연결, 대리운전과 동일)
- 앱 자체가 **키오스크 역할** (메뉴, 주문, 결제)
- **배달업체(배달대행) 연동** — 자체 배달이 아닌 외부 배달대행 연동
- 식당끼리 지역 내 공유 가능 (대리운전 shared_calls 개념)

## 핵심 철학 (모든 영역 공통)

**"내 손님은 내 것, 플랫폼에 빼앗기지 않는다"**

- 고객은 각 사업자(사무실/식당)에 귀속
- 사업자 독립 운영, 중앙 개입 없음
- 구독료만, 건당 수수료 없음

**Why:** 배민/쿠팡이츠(수수료 20~30%) 등 기존 배달 플랫폼도 로지소프트/콜마너와 동일한 문제 — 플랫폼 종속, 높은 수수료, 고객이 플랫폼에 귀속. 콜마당 모델이 동일하게 적용 가능.

## 확장 전략

- 수익 발생 시 전액 재투자 (개발팀 확장 포함)
- 아시아 진출 대상: 일본, 대만, 싱가포르 (소자영업 비중 높고 플랫폼 수수료 불만 큰 시장)
- 순서: 한국 대리운전 검증 → 수익 → 팀 확장 → 식당/배달 → 아시아

**How to apply:** 아키텍처 설계 시 "대리운전 전용"이 아닌 범용적 구조를 고려할 것. Firestore 구조의 offices → 향후 식당/배달 사업자로 확장 가능한 구조인지 염두. 다국어/다지역 지원 가능한 구조도 장기적으로 고려.
