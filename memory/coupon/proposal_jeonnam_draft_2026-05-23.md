## Executive Summary (한 페이지 요약)

**콜마당 = 지방 소상공인이 손님 자산을 *플랫폼이 아닌 자기 자신에게* 귀속시키는 동네 생활 OS.**

- 카카오·배민·쿠팡이 가져가는 수수료가 지방에서 분당·서울로 매년 빠져나가는 구조 → 콜마당은 그 돈을 *지역 안에 가두는* 인프라
- 핵심 무기 3종: ① 리퍼러 귀속(특허 출원 중) ② 콜 무수수료 ③ 본인 콜 등록

- 양평 1개 사무실 N=1 실증 운영 중 (6개월) · 다음 단계 쿠폰 모듈 → 이후 다른 지역 이식
- 협동조합·지역화폐·공공배달앱·당근·카카오 단골이 무너진 5가지 패턴 모두 *구조적 회피*

> *"다른 도전들은 좋은 의도를 약관에 적었다. 콜마당은 좋은 의도를 코드에 박았다."*

## 1. 문제 정의 — 지방 소멸은 *돈이 빠져나가는 것*

지방 소멸 담론은 인구 감소에 집중하지만, **선행 지표는 자본 유출**. 인구는 결과, 자본 유출이 원인.

### 1.1 출혈의 구조

| 채널 | 평균 수수료 | 자본 이동 방향 |
|------|------------|---------------|
| 배달앱 (배민·쿠팡이츠·요기요) | 매출의 6~12% + 배달료 + 광고비 | 지방 식당 → 서울/분당 본사 |
| 대리운전 콜센터 (카카오·로지) | 콜당 20~30% | 지방 기사 → 본사 |
| 카드 결제 (가맹점 수수료) | 0.5~2.5% | 지방 점주 → 카드사·VAN사 |
| 광고·플랫폼 노출 비용 | 월 수만~수십만원 | 지방 사장 → 플랫폼 |

**한 끼 1만원 결제 시 약 1,000~1,500원이 지역 외부로 즉시 빠져나감.** 이 자본 유출이 매년 누적되어 *지역 매출은 그대로*인데 *지역 잔류 자본은 감소*하는 상태가 지방 소멸의 핵심 동학.

### 1.2 전남 환산 (플레이스홀더 — 실제 수치로 교체 필요)

| 항목 | 추정치 | 비고 |
|------|--------|------|
| 전남 음식점 수 | 약 [4만] 개 | 통계청 사업체조사 |
| 평균 일매출 | [50만] 원 | 추정 |
| 외부 채널 비중 | [30]% | 배달앱 + 카드 + 광고 |
| 연간 자본 유출 | **약 [○○억] 원** | 산식: 식당수 × 일매출 × 365 × 비중 × 평균 수수료율 |

→ 이 자본을 *지역 안에 머무르게* 할 수 있다면 그 자체로 *지방소멸대응기금*과 동일한 효과.

## 2. 왜 기존 도전들은 다 무너졌는가 — 실패 패턴 5종

콜마당의 메시지는 새롭지 않다. 협동조합·지역화폐·공공배달앱·로컬 SNS·카카오 단골 등 비슷한 약속을 한 시도들이 모두 있었고, 대부분 무너졌다. **무너진 이유를 해부하면 콜마당의 차별점이 *말이 아닌 구조*임이 드러난다**.

| # | 실패 패턴 | 대표 사례 | 어떻게 무너졌나 | 콜마당 대응 (차별점) |
|---|-----------|----------|---------------|-------------------|
| **F1** | **의식 의존** | 협동조합 · 한살림 · 지역 ESG 모임 | 조합원 의식·자원봉사에 기댐 → 사람 바뀌면 무너짐 | **구조로 묶음** — 무수수료가 *코드·정관*에 박혀 의식 없이도 작동 |
| **F2** | **보조금 의존** | 지역사랑상품권 · 공공배달앱(배달의명수·먹깨비) | 지자체 지원금 끊기면 사용량 즉시 폭락 | **자생 수익** — 구독료가 유일 수입원, 외부 지원 0 가정 |
| **F3** | **약속의 구조 부재** | 위메프오·요기요·배민 ("수수료 인하" 약속) | 시장 점유 후 수수료 인상. 막을 장치가 *약관*뿐 | **자기무력화가 코드에 박힘** — 콜 수수료 함수 자체가 없음 (변경 시 OS 재설계 필요) |
| **F4** | **단일 노드 한계** | 당근(중고) · 배민(배달) · 카카오T(택시) | 노드 1개에 묶임 → 슈퍼앱에 흡수되거나 옆 노드 못 먹음 | **OS 모델** — 대리·택시·배달·쿠폰·식당이 *같은 OS 위*, 식당이 4중 노드 |
| **F5** | **손님 데이터 플랫폼 귀속** | 카카오 단골 · 네이버 스마트플레이스 · 배민 사장님 광고 | 손님 정보 = 플랫폼 자산. 식당은 *채널 임대인*으로 전락 | **리퍼러 귀속 (특허 출원)** — 손님 LTV가 식당으로 귀속, 플랫폼이 건드릴 수 없는 구조 |

**가장 강한 카드 — F2 지역사랑상품권 사례**: 전남 ○○사랑상품권도 동일 패턴. 지자체 충전 보조 100% 시점 사용액과 50%·0% 시점 사용액을 비교하면 *자생 능력 부재*가 데이터로 즉시 드러남.

## 3. 콜마당 = 소상공인 무장 인프라

### 3.1 정체성 한 줄

> **콜마당은 카카오·배민·쿠팡이 가져간 손님 자산을 지방 소상공인에게 되돌려주는 OS다.**

### 3.2 무기 3종 (세 개가 *동시에* 작동할 때만 무장 성립)

#### 무기 1 — 리퍼러 귀속 (특허 출원 중) ★ 핵심

- 손님이 *어느 식당의 QR을 통해 들어왔는지* 영구 귀속
- 그 손님이 이후 OS 안에서 발생시키는 모든 매출(대리·택시·배달·쿠폰)에서 *해당 식당*이 자동 인지·포인트 적립
- 손님 LTV가 *플랫폼이 아니라 식당의 자산*으로 귀속
- **지방에서 결정적인 이유**:
  - 도시는 plurality 시장 (선택지 무한 → 단골 귀속 약함)
  - 지방은 *생활권 좁음 + 단골 비율 높음 + 식당 = 손님 만남 빈도 1위 노드*
  - 한 번 귀속된 손님은 *평생 식당 채널을 통해 OS 전체* 소비
  - 결과: 식당이 OS의 *모세혈관*이자 *지분 보유자*

#### 무기 2 — 콜 무수수료

- 대리·택시·배달 콜에서 콜마당이 가져가는 수수료 = **0원**
- 구독료(월 정액)만이 유일 수입원
- 카카오/로지가 가져가던 콜당 20~30%가 *기사에게 그대로 귀속*

#### 무기 3 — 본인 콜 등록

- 식당 사장이 *직접* 단순호출 버튼으로 대리·택시 요청 가능
- 외부 영업·중개에 대한 의존도 0
- 식당이 *수동 사용자*가 아닌 *능동 노드*로 작동

### 3.3 식당의 4중 노드 역할

콜마당에서 식당은 단순 가맹점이 아니라 **OS의 핵심 노드 4중 역할**:

| 역할 | 내용 |
|------|------|
| ① 호출 노드 | 손님·사장이 단순호출 버튼으로 대리/택시 요청 |
| ② 포인트 적립 노드 | 식당 결제 → 포인트 적립 → 다른 노드(대리·택시·배달)에서 사용 |
| ③ 손님앱 거점 | 손님이 *식당 QR*을 통해 콜마당 OS 진입 (리퍼러 귀속) |
| ④ 쿠폰 발행 노드 | 식당이 손님에게 직접 쿠폰 발행 → 재방문·재구매 유도 |

→ 식당 1곳 = 4개의 가치 생성 노드. 식당이 *OS의 모세혈관*인 이유.

## 4. 자기무력화 약속 (Self-Disarming Pledge)

### 4.1 약속의 구조

콜마당은 *플랫폼이 영원히 소상공인의 경쟁자가 되지 않는다*는 약속을 **세 겹**으로 박는다:

| 겹 | 위치 | 내용 |
|----|------|------|
| **1겹** | 정관 | 콜·중개·광고·데이터 판매 수익 ❌ 명문화 |
| **2겹** | 약관 | 모든 사용자에게 동일 |
| **3겹** ★ | **코드** | 콜에서 수수료를 받는 *함수 자체가 부재*. 변경 시 OS 전체 재설계 필요 |

3겹째가 결정적. 약관은 바꿀 수 있지만, 코드는 *바꾸려면 회사의 정체성을 부정해야* 함. 이게 *위메프오·요기요·배민과의 결정적 차이*.

### 4.2 자본 진입 차단막

이 약속이 특허·정관·코드로 보호되는 순간, **대기업이 같은 모델로 진입해도 동일한 자기무력화 약속을 할 수 없음** — 그들의 비즈니스 모델이 그것을 허락하지 않기 때문. 결과적으로 콜마당의 *자기무력화 약속*은 *거대 자본의 진입 차단막* 역할.

## 6. 시간차 이식 모델 — 전국 동시 ❌, 지역 단위 N=1 ✅

### 6.1 모델

```
[양평 1개 사무실] → [N=1 인큐베이션] → [완성된 OS]
                                            ↓
                              [다른 지역 이식 — 시군 1곳씩]
                                            ↓
                              [그 지역 N=1 → 광역 확장]
```

### 6.2 왜 동시 진입을 안 하는가

- *한 곳에서 완성된 OS*가 이식 가능한 OS — *여러 곳에서 부분 작동하는 시스템*은 표준이 못 됨
- 사람·자본·운영 리스크 분산 ❌, *집중 후 검증 후 복제* ✅
- 검증 안 된 시스템을 광역 동시 깔면 = *부분 작동 = 사용자 신뢰 손상 = 시장 진입 자체 불가능*

### 6.3 전남 적용 시나리오 (가정)

| 단계 | 내용 | 예상 기간 |
|------|------|---------|
| **Phase 0** | 인사·관계 형성 · 현장 청취 | 현재 ~ + 6개월 |
| **Phase 1** | 시군 1곳 인큐베이션 사무실 1곳 선정 → 식당 협회·대리운전 협회 협력 | + 3개월 |
| **Phase 2** | 사무실 1곳 N=1 운영 검증 (양평 모델 이식) | + 6개월 |
| **Phase 3** | 시군 광역 확장 → 도 단위 검토 | + 12개월 이후 |

**핵심**: Phase 1 진입 시점 = *콜마당 측이 양평 검증과 쿠폰 모듈 완성 후* + *지역 측이 준비된 후*. 양쪽 조건 충족 전까지는 *관계 형성*만.

## 8. 파트너 자리 — 함께 가져갈 수 있는 자리 3개

콜마당은 *지분 분배·콜 수수료 분배* 구조가 없음 (코드가 막음). 그러나 *지역 파트너가 가져갈 자리*는 별도로 설계되어 있음:

| 자리 | 내용 | 효용 |
|------|------|------|
