## Executive Summary

**콜마당 = 지방 식당이 *플랫폼이 아닌 자기 자신에게* 손님 자산을 귀속시키는 동네 생활 OS.**

- 배민·쿠팡이츠·요기요가 가져가는 배달 수수료가 지방 식당의 영업이익을 출혈시키는 구조 → 콜마당은 **식당을 OS의 주인으로 되돌려놓는 인프라**
- 핵심 무기 3종: ① 리퍼러 귀속(특허 출원 중) ② 플랫폼 무수수료 ③ 본인 호출 등록
- *코드*에 박힌 자기무력화 약속 — 약관 아닌 구조로 보장
- 양평에서 **6개월 OS 작동 검증 완료** · 다음 단계 **쿠폰 모듈** → 첫 거대 응용 영역 **배달**
- 협동조합·지역화폐·공공배달앱·당근·카카오 단골이 무너진 5가지 패턴 모두 *구조적 회피*

> *"다른 도전들은 좋은 의도를 약관에 적었다. 콜마당은 좋은 의도를 코드에 박았다."*

## 1. 문제 정의 — 지방 식당의 출혈은 *배달부터 시작된다*

### 1.1 출혈의 구조

지방 소멸 담론은 인구 감소에 집중하지만, **선행 지표는 자본 유출**. 특히 **배달**이 가장 큰 출혈 채널.

| 채널 | 평균 수수료 | 자본 이동 방향 |
|------|------------|---------------|
| **배달앱 (배민·쿠팡이츠·요기요) ★** | **매출의 6~12% + 배달료 + 광고비** | **지방 식당 → 서울/분당 본사** |
| 카드 결제 (가맹점 수수료) | 0.5~2.5% | 지방 점주 → 카드사·VAN사 |
| 광고·플랫폼 노출 비용 | 월 수만~수십만원 | 지방 사장 → 플랫폼 |

**한 끼 1만원 배달 결제 시 약 1,500~2,500원이 지역 외부로 즉시 빠져나감.** 이 자본 유출이 매년 누적되어 *지역 매출은 그대로*인데 *지역 잔류 자본은 감소*하는 상태가 지방 소멸의 핵심 동학.

### 1.2 전남 환산 (플레이스홀더 — 실제 수치로 교체 필요)

| 항목 | 추정치 | 비고 |
|------|--------|------|
| 전남 음식점 수 | 약 [4만] 개 | 통계청 사업체조사 |
| 배달앱 사용 비중 | [40]% | 추정 |
| 평균 일배달 매출 | [20만] 원 | 추정 |
| 배달앱 평균 수수료율 | [15]% | 수수료 + 배달료 + 광고비 합산 |
| **연간 배달 채널 자본 유출** | **약 [○○억] 원** | 산식: 식당수 × 사용비중 × 일매출 × 365 × 수수료율 |

→ 이 자본을 *지역 안에 머무르게* 할 수 있다면 그 자체로 *지방소멸대응기금*과 동일한 효과.

## 2. 왜 기존 도전들은 다 무너졌는가 — 실패 패턴 5종

콜마당의 메시지는 새롭지 않다. 비슷한 약속을 한 시도들이 모두 있었고, 대부분 무너졌다. **무너진 이유를 해부하면 콜마당의 차별점이 *말이 아닌 구조*임이 드러난다**.

| # | 실패 패턴 | 대표 사례 | 어떻게 무너졌나 | 콜마당 대응 |
|---|-----------|----------|---------------|------------|
| **F1** | **의식 의존** | 협동조합 · 한살림 · 지역 ESG | 조합원 의식·자원봉사에 기댐 → 사람 바뀌면 무너짐 | **구조로 묶음** — 무수수료가 *코드·정관*에 박혀 의식 없이 작동 |
| **F2** | **보조금 의존** | 지역사랑상품권 · 공공배달앱(배달의명수·먹깨비) | 지자체 지원금 끊기면 사용량 즉시 폭락 | **자생 수익** — 구독료가 유일 수입원 |
| **F3** | **약속의 구조 부재** ★ | 위메프오 · 요기요 · **배민** ("수수료 인하" 약속) | 시장 점유 후 수수료 인상. 막을 장치가 *약관*뿐 | **자기무력화가 코드에 박힘** — 콜·배달 수수료 함수 자체가 부재 |
| **F4** | **단일 노드 한계** | 당근(중고) · **배민(배달)** · 카카오T(택시) | 노드 1개에 묶임 → 슈퍼앱에 흡수되거나 옆 노드 못 먹음 | **OS 모델** — 식당·배달·모빌리티·쿠폰이 *같은 OS 위* |
| **F5** | **손님 데이터 플랫폼 귀속** | 카카오 단골 · 네이버 스마트플레이스 · **배민 사장님 광고** | 손님 정보 = 플랫폼 자산. 식당은 *채널 임대인*으로 전락 | **리퍼러 귀속 (특허 출원)** — 손님 LTV가 식당으로 귀속 |

**가장 강한 대비 — F3 / F5**: 배민이 지방 식당의 *수수료 인상*과 *손님 정보 차단*을 동시에 진행한 지난 5년 = 콜마당이 *반대 방향*으로 가는 정확한 이유. 같은 약속(F3)을 했던 곳들은 막을 장치가 약관뿐이었음.

**F2 가장 강한 카드 — 지역사랑상품권 사례**: 전남 ○○사랑상품권도 동일 패턴. 지자체 충전 보조 100% 시점 사용액과 50%·0% 시점 사용액을 비교하면 *자생 능력 부재*가 데이터로 즉시 드러남.

## 3. 콜마당 = 식당이 OS의 주인이 되는 인프라

### 3.1 정체성 한 줄

> **콜마당은 배민·쿠팡이 가져간 손님 자산을 지방 식당에게 되돌려주는 OS다.**

### 3.2 무기 3종

#### 무기 1 — 리퍼러 귀속 (특허 출원 중) ★ 핵심

- 손님이 *어느 식당의 QR을 통해 들어왔는지* 영구 귀속
- 그 손님이 이후 OS 안에서 발생시키는 모든 매출(배달·모빌리티·쿠폰)에서 *해당 식당*이 자동 인지·포인트 적립
- 손님 LTV가 *플랫폼이 아니라 식당의 자산*으로 귀속
- **지방에서 결정적인 이유**:
  - 도시는 plurality 시장 (선택지 무한 → 단골 귀속 약함)
  - 지방은 *생활권 좁음 + 단골 비율 높음 + 식당 = 손님 만남 빈도 1위 노드*
  - 한 번 귀속된 손님은 *평생 식당 채널을 통해 OS 전체* 소비
  - 결과: 식당이 OS의 *모세혈관*이자 *지분 보유자*

#### 무기 2 — 플랫폼 무수수료

- 식당·기사·손님 사이의 거래에서 콜마당이 가져가는 수수료 = **0원**
- 구독료(월 정액)만이 유일 수입원
- 배민이 가져가던 매출의 6~12%, 카드사가 가져가던 0.5~2.5%, 콜센터가 가져가던 20~30%가 *그대로 지방에 잔류*

#### 무기 3 — 본인 호출 등록

- 식당 사장이 *직접* 단순호출 버튼으로 배달·모빌리티·쿠폰 발행 가능
- 외부 영업·중개에 대한 의존도 0
- 식당이 *수동 사용자*가 아닌 *능동 노드*로 작동

### 3.3 식당 = OS의 4중 노드

콜마당에서 식당은 단순 가맹점이 아니라 **OS의 핵심 노드 4중 역할**:

| 역할 | 내용 |
|------|------|
| ① **호출 노드** | 손님·사장이 단순호출로 배달·모빌리티 요청 |
| ② **포인트 적립 노드** | 식당 결제 → 포인트 적립 → 다른 노드에서 사용 |
| ③ **손님앱 거점** | 손님이 *식당 QR*을 통해 콜마당 OS 진입 (리퍼러 귀속) |
| ④ **쿠폰 발행 노드** | 식당이 손님에게 직접 쿠폰 발행 → 재방문·재구매 유도 |

→ 식당 1곳 = 4개의 가치 생성 노드. 식당이 *OS의 모세혈관*이자 *주인*인 이유.

## 4. 자기무력화 약속 (Self-Disarming Pledge)

콜마당은 *플랫폼이 영원히 식당의 경쟁자가 되지 않는다*는 약속을 **세 겹**으로 박는다:

| 겹 | 위치 | 내용 |
|----|------|------|
| **1겹** | 정관 | 거래 수수료·광고·데이터 판매 수익 ❌ 명문화 |
| **2겹** | 약관 | 모든 사용자에게 동일 |
| **3겹** ★ | **코드** | 거래에서 수수료를 받는 *함수 자체가 부재*. 변경 시 OS 전체 재설계 필요 |

3겹째가 결정적. 약관은 바꿀 수 있지만, 코드는 *바꾸려면 회사의 정체성을 부정해야* 함. 이게 *위메프오·요기요·배민과의 결정적 차이*.

## 6. 응용 영역 — OS는 어디에 적용되는가

콜마당 OS는 *플랫폼*이 아니라 *인프라*. 그 위에 여러 응용 영역이 올라간다.

### 6.1 ★ 배달 — 첫 거대 응용 영역

**왜 배달이 첫 거대 응용 영역인가**:

| 이유 | 내용 |
|------|------|
| **출혈 최대 채널** | §1 표에서 확인 — 배달앱이 지방 식당의 가장 큰 출혈 |
| **식당 4중 노드와 직접 연결** | 식당 = 호출 노드 + 손님앱 거점 + 쿠폰 발행 → 배달과 모두 결합 |
| **리퍼러 귀속 가치 극대화** | 배달 손님 = 재주문 가능성 높음 = LTV가 식당 자산화될 때 가치 가장 큼 |
| **정부 정책 정합** | 공공배달앱 정책 + 소상공인 디지털 전환 + 지방소멸대응 모두 매칭 |

**콜마당 배달의 차별점 (vs 배민·쿠팡이츠·공공배달앱)**:

| 항목 | 배민·쿠팡 | 공공배달앱 | **콜마당** |
|------|----------|-----------|----------|
| 수수료 | 6~12% + 배달료 + 광고비 | 1~2% (지자체 보조) | **0% (구독료만)** |
| 손님 정보 귀속 | 플랫폼 | 플랫폼 | **식당** |
| 자생 지속성 | ✅ | ❌ (보조금 끊기면 무너짐 — F2) | ✅ (구독료) |
| 호출·결제·재방문 통합 | 부분 | 부분 | **OS 단일 통합** |
| 자기무력화 약속 구조 | ❌ | 약관 | **코드** |

**진행 단계**: 쿠폰 모듈 완성 → 양평 N=1 배달 노드 결합 검증 → 시군 단위 이식.

### 6.2 모빌리티 — 검증된 운영 영역

대리·택시·픽업을 묶은 **모빌리티** 카테고리는 양평에서 6개월 운영을 통해 OS 작동의 *증명 영역*. 카카오모빌리티·로지가 가져가던 콜당 20~30% 수수료가 *지방 기사에게 그대로 귀속*.

→ 본 제안서에서는 *OS 작동 검증의 증거*로만 언급. 상세 운영 데이터는 별도 자료로 분리.

### 6.3 쿠폰 모듈 — 다음 단계

식당이 손님에게 *직접* 쿠폰을 발행하고, OS 안에서 결제까지 이어지는 자리. 리퍼러 귀속과 결합하여 식당의 *재방문 LTV 자본화*를 완성하는 핵심 모듈.

### 6.4 향후 응용 영역 (장기)

- 지역 마트·상점 통합 (4중 노드 모델 일반화)
- 지역 행사·관광 연계
- 지역 자치 화폐와의 결합 가능성

## 7. 시간차 이식 모델

### 7.1 모델

```
[양평 1개 사무실] → [N=1 OS 검증 완료] → [쿠폰·배달 모듈 결합]
                                                ↓
                                  [다른 지역 이식 — 시군 1곳씩]
                                                ↓
                                  [그 지역 N=1 → 광역 확장]
```

### 7.2 왜 동시 진입을 안 하는가

- *한 곳에서 완성된 OS*가 이식 가능한 OS — *여러 곳에서 부분 작동하는 시스템*은 표준이 못 됨
- 사람·자본·운영 리스크 분산 ❌, *집중 후 검증 후 복제* ✅
- 검증 안 된 시스템을 광역 동시 깔면 = *부분 작동 = 사용자 신뢰 손상 = 시장 진입 자체 불가능*

## 8. 정부 지원사업·정책 매칭 가능성

콜마당 OS의 구조가 매칭 가능한 정부·지자체 사업:

| 사업명 | 매칭 포인트 |
|--------|------------|
| **지방소멸대응기금** | 자본 유출 → 자본 잔류 전환 (§1.2 환산 데이터) |
| **소상공인 디지털 전환 사업** | 식당의 4중 노드화 = 디지털 인프라 |
| **공공배달앱 대체·보완 사업** | 자생 가능한 무수수료 배달 모델 (F2 회피) |
| **지역특화 ICT 융합 사업** | 리퍼러 귀속 특허 + 동네 생활 OS |
| **고향사랑기부제 연계** | 지역 자본 잔류 메커니즘 |

→ 시군 1곳 시범 지정 + 6개월 운영 + 보고서·언론 노출 = 도지사·시장 라인의 가시적 성과.
