## Executive Summary

**지방 정부가 직접 운영하는 *지방 균형 발전형* 모빌리티·소상공인 디지털 인프라.** 카카오·배민 등 중앙 플랫폼이 지방 영세 상인의 손님·데이터·수수료를 *서울로 빨아올리는* 구조에 대해, 지자체가 *직접* 대안 인프라를 운영하여 *지역 자본을 지역에 가두는* 모델.

- **검증**: 양평 1개 대리운전 사무실 6개월 실운영, MVP 4종 안정 작동, 특허 출원 완료
- **모델 전환**: 경기도 *배달특급* / 공공배달앱(배달의명수·먹깨비) 모델 벤치마킹 — 지자체 *직접 발주·운영* 방식
- **차별점 (vs 공공배달앱 F2 실패 패턴 회피)**: 보조금 의존이 아닌 *자생 가능 구조* — 월 1만원 미만 실비 구독료로 자생, 보조금 0에서도 유지 가능
- **3대 핵심 기술** (특허 청구항):
  - ① **노드 귀속 아키텍처** — 손님 데이터가 *Firebase Security Rules로 코드 강제* 가게 자산화 (플랫폼 관리자도 접근 차단)
  - ② **Call-to-Digital** — 전화 받기만 하면 자동 CRM 구축 (50대 이상 사장님 학습 비용 0)
  - ③ **Offline-First** — 산간·통신음영 지역에서도 작동
- **전남 적용**: 시·군 1곳 시범 → 22개 시·군 단계적 확산. 전남 잠재 노드 약 [환산 필요]개

**지방 정부에 드리는 명백한 제안**: 시·군 1곳 시범사업 (저비용·저위험·재현성 ✅). 6개월 운영 검증 → 광역 확장. 지방소멸대응기금·소상공인 디지털 전환·공공배달앱 보완 등 5종 정부 사업 매칭 가능.

## 1. 문제 인식 — 지방 영세 상인이 *플랫폼 종속*에서 벗어날 수 없는 이유

### 1.1 중앙 플랫폼의 3중 착취 구조

| 채널 | 수수료·구조 | 자본 이동 |
|------|-----------|---------|
| **카카오·배민·쿠팡** | 매출의 6~25% + 광고비 + 데이터 독점 | 지방 → 서울 |
| **카드사·VAN사** | 0.5~2.5% | 지방 → 카드사 |
| **결과** | 영세 상인 영업이익의 30~50% 외부 유출 | 지방 잔류 자본 매년 감소 |

### 1.2 지방 영세 상인의 진짜 위기 — *데이터 종속*

수수료보다 더 결정적인 문제는 **데이터 종속**:
- 손님 정보를 가게가 *볼 수도 없음*
- 플랫폼이 가게를 *채널 임대인*으로 전락시킴
- 해지 시 *손님 데이터 소실* → 사실상 Lock-in
- 윤리적 선언만으로는 보호 불가 — *배달앱 수수료 변동 사례 (6.8% → 9.8%)*: 약관은 언제든 바뀜

### 1.3 지방 정부의 딜레마

| 정부가 원하는 것 | 현실의 벽 |
|----------------|---------|
| 지방소멸 대응 | 인구 감소가 결과, *자본 유출이 원인*인데 막을 도구 없음 |
| 영세 상인 보호 | 영세 상인 3만원 직접 지원 = 태도 안 나고 받는 사람도 부담 |
| 공공배달앱 (배달의명수·먹깨비) | *보조금 끊기면 사용량 폭락* (F2 실패 패턴) |
| 지역사랑상품권 | 충전 보조 없으면 자생 ❌ |
| 카카오·배민에 대한 대안 | 지자체 단독 개발 = 외주비 3억+ / 자체 운영 인력 없음 |

→ **지자체가 *효과적이고 자생 가능한 도구*를 갖지 못함**. 콜마당이 그 도구.

## 2. 해결 — *코드*로 강제된 데이터 주권 + B2G 공공 인프라

### 2.1 정체성 한 줄

> **콜마당은 동네 가게에게 *프랜차이즈 본부의 무기*를 *본부 없이* 갖게 한다.
> 그리고 그 시스템을 *지자체가 직접 운영*한다.**

### 2.2 3대 핵심 기술 (특허 청구항)

#### ① 노드 귀속 아키텍처 — *코드*가 강제하는 데이터 주권 (청구항 11)

```
/offices/{사무실ID}/customers/{손님ID}
→ Firebase Security Rules: 해당 사무실 사장님만 읽기/쓰기
→ 플랫폼 관리자도 접근 차단
```

| 보호층 | 내용 |
|-------|------|
| 기술적 | Firebase Security Rules — 접근 시도 자동 차단 |
| 법적 | 약관 — 위반 시 손해배상 |
| 감사 | Audit Log — 사장님이 직접 열람 |

**해지 시에도 사장님이 손님 데이터 그대로 보유.** 약관이 아닌 *코드가 강제*. 시스템을 바꾸려면 전체 재설계 필요.

#### ② Call-to-Digital — 전화 받으면 자동 CRM (청구항 4)

- Android Telephony API → 발신번호 자동 감지 → Firestore 0.5초 조회 → 단골 즉시 인식 + 이용 이력·포인트 자동 표시
- *50대 이상 사장님이 평소처럼 전화만 받으면 CRM 자동 구축*. 학습 비용 0.

#### ③ Offline-First — 산간·통신음영 작동 보장 (청구항 5)

- Room DB(SQLite) 로컬 우선 저장 → 통신 음영에서도 작동 → 복구 시 Firestore 자동 동기화
- 산간 농촌·터널·지하 등 *기존 클라우드 앱이 작동 못 하는 환경*에서 보장

### 2.3 프랜차이즈 본부 vs 콜마당 — 무엇을 주고, 무엇을 안 가져가는가

| 항목 | **프랜차이즈 본부** | **콜마당** |
|------|-------------------|----------|
| 고객 데이터·재방문·포인트 | 본부 시스템 | ✅ **가게 자산** |
| 가맹비·로열티·종속 | ✅ 있음 (수천만원 + 매출의 N%) | ❌ **없음** |
| 본부 망하면 | 같이 망함 | **가게 무관 (OS는 도구일 뿐)** |
| 가게가 콜마당에 내는 것 | — | **월 1만원 미만 실비** |

### 2.4 양평 6개월 실증 — 운영 중인 4개 MVP

| # | 모듈 | 기능 | 운영 상태 |
|---|------|------|---------|
| 1 | **콜 디텍터** | 수신 전화 자동 감지 + 단골 즉시 인식 | ✅ 양평 운영 중 |
| 2 | **콜 매니저** | 호출·서비스 제공자·정산 종합 관리 | ✅ 양평 운영 중 |
| 3 | **기사 앱** | 호출 수신·운행·정산 | ✅ 양평 운영 중 |
| 4 | **손님 앱** | QR 진입·포인트·이용 내역 | 코드 완성, 배포 대기 |
| (백엔드) | Cloud Functions 41개 | 배차·알림·정산 자동화 | ✅ 운영 중 |

**검증된 효과 (현장 실측)**:
- 배차 프로세스: 운전 중 6번 클릭 → **1번 터치 자동 배정**
- 정산 분쟁: 매주 발생 → **0건**
- 단골 관리: 종이 장부 → **완전 디지털화**
- 운영 비용: 월 ~$414 절감 실측

## 3. ★ B2G 공공 인프라 모델 — *지자체가 직접 운영*

### 3.1 모델의 핵심

**경기도 *배달특급* + 공공배달앱(배달의명수·먹깨비) 벤치마킹**, 단 *F2 실패 패턴(보조금 의존) 회피*.

| 항목 | 기존 공공배달앱 (F2 실패) | **콜마당 B2G 모델** |
|------|------------------------|------------------|
| 지자체 부담 | 매년 충전 보조금 | **인프라 1회 도입비만** |
| 자생 능력 | 보조금 끊기면 사용량 폭락 | **월 1만원 미만 실비로 자생** |
| 손님 데이터 | 플랫폼 보유 | **가게 자산 (코드 강제)** |
| 단일 영역 | 배달만 | **모빌리티·식당·숙박·생활 OS** |
| 효과 측정 | 사용 건수만 | **자본 잔류 환산 + 영세 상인 디지털 전환율 + 안전 사고 감소** |

### 3.2 지자체 ↔ 콜마당 역할 분담

| 지자체 | **콜마당** |
|--------|----------|
| 인프라 도입비 1회 부담 | 시스템 제공·교육·운영 지원 |
| 마케팅·홍보 협력 | 가게 등록·교육·온보딩 |
| 정부 지원사업 매칭 동행 | 양평 6개월 검증 데이터 공유 |
| 시범 시·군 선정 | 6개월 시범 결과 정직한 공개 (성공·실패 모두) |

### 3.3 지자체가 얻는 것 — 명백한 매칭 10가지

| # | 지자체 needs | **콜마당이 해드릴 수 있는 것** |
|---|------------|----------------------------|
| N1 | 지방 소멸 대응 가시적 성과 | 자본 유출 → 잔류 전환. 시·군 단위 *연 ○○억 자본 잔류* 환산 가능 |
| N2 | 정부 예산 매칭 | 지방소멸대응기금·소상공인 디지털 전환 등 5종 매칭 (§4) |
| N3 | 저비용 진입 | 시·군 1곳 시범 — 인프라 1회 도입 |
| N4 | 재현성 (다른 시군 이식) | 양평 검증된 *표준 OS*. 시군 1곳 → 광역 복제 |
| N5 | 자생 모델 | 보조금 0 가정. F2 회피 |
| N6 | 영세 상인 표심 | 시·군당 가게 100+ + 종사자 + 가족 + 군민 수천 명 |
| N7 | 언론·홍보 거리 | *전국 최초 자생형 무수수료 공공 OS* 헤드라인 |
| N8 | 위험 회피 | N=1 시범 = 실패 시 정치적 손해 최소 |
| N9 | 지역 일자리 | 모빌리티 서비스 제공자 + 가게 운영 인력 + 향후 식당·배달 확장 |
| N10 | 지자체와 영구 충돌 0 | *자기무력화 약속이 코드에 박힘* — 지자체가 통제권 잃을 걱정 0 |

> **지방 정부가 원하는 10가지가 콜마당이 해드릴 수 있는 10가지와 정확히 일치한다.**
> 이는 우연이 아니라 *지방 정부 needs를 역설계해서 만든 OS*이기 때문이다.

## 4. 전남 시범사업 제안 — 시·군 1곳 N=1 인큐베이션

### 4.1 시장 환산 (전남 22개 시·군)

양평 N=1 모델을 전남 시·군 단위로 환산 시 (강원도 잠재 노드 48,250개 기반 추정):

| 단계 | 타겟 업종 | 전남 환산 규모 | 전략 |
|------|---------|--------------|------|
| 1단계 (진입) | 대리운전 | 시·군 1곳당 약 10~20개소 | 양평 모델 직접 이식 — *6개월 검증 완료* |
| 2단계 (확장) | 요식업 | 전남 약 [4만]개 | QR 귀속 + 쿠폰 모듈 — *대리 손님 = 식당 손님 동선 활용* |
| 3단계 (고도화) | 숙박/펜션 | 전남 약 [추정]개 | 직거래 예약 + 관광 패키지 — *수수료 0* |
| 4단계 (생활) | 미용·부동산·이용업 | 전남 약 [추정]개 | 지역 생활 동선 장악 |

**대리 → 식당 동선 핵심**: 손님 1명 = 식당에서 식사·음주 → 대리운전 호출 → 귀가. *같은 사람*. 대리에서 확보한 손님앱 사용자가 그대로 식당 노드의 초기 사용자 (Cold Start 해소).

### 4.2 시범사업 명백한 제안

| 항목 | 내용 |
|------|------|
| **규모** | 시·군 1곳 · 사무실 1곳 · 가게 50~100곳 · 서비스 제공자 10~20명 |
| **기간** | 6개월 시범 → 6개월 확장 검토 → 1년 후 광역 결정 |
| **지자체 부담** | 인프라 도입비 1회 + 마케팅 협력 (정부 사업 매칭으로 보전 가능) |
| **콜마당 부담** | 시스템 제공 + 양평 검증 데이터 공유 + 교육·온보딩 동행 |
| **시작 가능 시점** | 양평 검증 완료 + 쿠폰앱 완성 후 (2027년 상반기) |
| **검증 지표** | ① 가게 등록 수 ② 거래 트랜잭션 ③ 자본 잔류 환산액 ④ 정산 분쟁 감소 ⑤ 안전사고 감소 |
| **종료 조건** | 6개월 후 지표 미달 시 콜마당 측 철수, 지자체 측 손실 최소 |

### 4.3 정부 지원사업 매칭 5종

| 사업명 | 매칭 포인트 | 진행 방식 |
|--------|------------|---------|
| **지방소멸대응기금** | 자본 유출 → 잔류 전환 환산 | 시군 시범 단위 |
| **소상공인 디지털 전환 사업** | 가게 4중 노드화 | 가게 단위 |
