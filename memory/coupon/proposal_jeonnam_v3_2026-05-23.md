## Executive Summary

**콜마당은 동네 가게에게 *프랜차이즈 본부의 무기*를 *본부 없이* 갖게 하는 동네 생활 OS다.**

- 카카오·배민·쿠팡은 손님·데이터·수수료를 *위로 빨아올린다*. 콜마당은 그것을 *가게로 내려보낸다*.
- 핵심 메커니즘: **QR 귀속 노드** — 손님이 어느 가게를 통해 들어왔는지 영구 귀속. 이후 OS 내 모든 거래가 그 가게의 자산.
- 양평에서 **6개월 OS 작동 검증 완료** (4개 MVP 운영 중) · 다음 단계 **쿠폰앱** (개발 진행 중) · 확장 가능 영역 **배달**
- **수수료 0** — 콜·중개·광고 수익 0. 구독료만이 유일 수입원. *약관이 아닌 코드에 박힌 약속*
- 협동조합·지역화폐·공공배달앱·당근·카카오 단골이 무너진 5가지 실패 패턴 모두 *구조적 회피*

**지방 정부와의 명백한 제안**:
- 시군 1곳 N=1 인큐베이션 시범사업 (저비용·저위험·재현성 ✅)
- 양평 검증 완료 + 쿠폰앱 완성 후 진입 가능 (약 6개월 후)
- 지방소멸대응기금·소상공인 디지털 전환·공공배달앱 보완 등 5종 정부 사업 매칭 가능

## 1. 우리는 *중앙 플랫폼*의 반대편이다

### 1.1 한 줄 정체성

> **카카오·배민·쿠팡은 손님·데이터·수수료를 위로 빨아올린다.
> 콜마당은 그것을 가게로 내려보낸다.**

### 1.2 자본 이동 방향의 반전

| 항목 | 중앙 플랫폼 (배민·쿠팡·카카오) | **콜마당** |
|------|-----------------------------|----------|
| **손님 정보** | 플랫폼 보유, 가게 비공개 | **가게에 귀속** |
| **재방문 데이터** | 플랫폼 자산 | **가게 자산** |
| **포인트·멤버십** | 플랫폼 통합 | **OS 통합, 가게 노드별 적립** |
| **거래 수수료** | 매출의 6~30% | **0** |
| **광고 비용** | 가게 부담 (월 수만~수십만 원) | **0** |
| **자본 흐름** | 지방 → 서울/분당 | **지방 → 지방** |
| **플랫폼 망하면** | 가게 매출 단절 | **가게는 OS 도구일 뿐, 무관** |

→ 같은 비즈니스가 두 가지 다른 자본 흐름을 만든다. 중앙 플랫폼 모델은 *지방 자본을 빨아올리는 펌프*, 콜마당은 *지방 안에 자본을 가두는 댐*.

## 2. QR 귀속 노드 — OS의 심장

### 2.1 작동 메커니즘

```
[가게가 손님에게 QR 제공]
         ↓
[손님이 QR 스캔 → 콜마당 앱 설치]
         ↓
[Install Referrer = 그 가게]  ← 영구 귀속
         ↓
[손님이 이후 OS 내에서 발생시키는 모든 거래]
   → 식당 결제 / 호출 서비스 / 쿠폰 / 향후 배달 등
         ↓
[모든 거래에 그 가게가 자동 인지·포인트 적립]
         ↓
[손님의 평생가치(LTV) = 그 가게의 자산]
```

### 2.2 귀속 노드가 가져오는 구체적 장점

1. **가게가 손님 데이터를 *자기 자산*으로 보유** — 누가·언제·얼마나·무엇을 소비했는지
2. **재방문 유도 도구를 가게가 직접 운용** — 쿠폰·포인트·할인 가게가 직접 발행
3. **다른 노드의 거래도 가게에 귀속** — 손님이 다른 식당·호출 서비스 이용 시에도 *최초 진입 가게*에 포인트 일부 적립
4. **광고비 0** — 손님이 *한 번* 가게 QR로 진입하면, 이후 모든 거래가 자동 추적. 가게는 광고 안 함
5. **플랫폼 의존성 0** — 콜마당이 망해도 가게의 손님 데이터는 가게가 보유
6. **지역 OS 내 손님 회유 효과** — 손님이 가게 단골이 되면, 그 가게가 추천하는 다른 노드(다른 가게·서비스)로 자연스럽게 유입

### 2.3 왜 지방에서 결정적인가

- **도시는 plurality 시장** — 선택지 무한 → 단골 귀속 약함 → 귀속 효과 희석
- **지방은 생활권 좁음 + 단골 비율 높음 + 가게 = 손님 만남 빈도 1위 노드**
- 한 번 귀속된 손님은 *평생 가게 채널을 통해 OS 전체* 소비
- 결과: *가게가 OS의 모세혈관*이자 *지분 보유자*

## 3. ★ 그래서 — 소상공인의 *프랜차이즈화*

### 3.1 비전 한 줄

> **콜마당은 동네 가게에게 *프랜차이즈 본부의 무기*를 *본부 없이* 갖게 한다.**

지난 30년간 자영업이 살아남는 길은 두 가지였다 — **프랜차이즈 가맹점이 되거나** (본부 무기 받되 종속) **혼자 버티거나** (무기 없이 자유). 콜마당은 *세 번째 길*을 제공한다 — **본부 종속 없이 본부 무기를 갖는다**.

### 3.2 프랜차이즈 본부 vs 콜마당 — 무엇을 주고, 무엇을 안 가져가는가

| 항목 | **프랜차이즈 본부** | **콜마당** |
|------|-------------------|----------|
| **고객 데이터** | 본부 제공 → 가맹점 활용 | ✅ **가게 자산 (귀속노드)** |
| **재방문 관리 시스템** | 본부 시스템 사용 | ✅ **가게가 직접 운용 (쿠폰·포인트)** |
| **포인트·멤버십** | 본부 통합 | ✅ **OS 통합, 가게에 귀속** |
| **브랜드 충성도 자산화** | 본부 브랜드에 충성 | ✅ ***가게 브랜드*에 충성** |
| **광고·홍보 인프라** | 본부 통합 광고 | ✅ **OS 내 자동 노출** |
| **운영 표준화 도구** | 본부 매뉴얼 | ✅ **OS 표준 워크플로우** |
| **가맹비** | ✅ 있음 (수천만 원~) | ❌ **없음** |
| **로열티 (매출의 N%)** | ✅ 있음 (3~10%) | ❌ **없음** |
| **본부 종속 (메뉴·가격·운영)** | ✅ 있음 | ❌ **없음 — 가게 자율성 100%** |
| **본부가 망하면** | 같이 망함 | **가게는 무관 (OS는 도구일 뿐)** |
| **수익은** | 가게 매출 일부가 본부로 | **가게 매출 전액이 가게로** |
| **콜마당이 가져가는 것** | — | **월 정액 구독료만** |

→ 이게 *중앙 플랫폼과 반대편*이라는 §1 한 줄의 **구체적 작동 메커니즘**.

### 3.3 무엇이 가능해지는가

- 동네 식당이 *대형 프랜차이즈와 동일한 무기*로 경쟁할 수 있음
- 가게가 손님을 *자기 자산*으로 인식 → 사장이 *능동 노드*로 작동 (영업·이벤트·쿠폰 발행)
- 지방 자영업 생태계 전체가 *동시에* 무장 → **수백~수천 가게가 같은 OS 위에서 협력**

## 4. 무수수료 — 약관이 아닌 *코드*에 박힌 약속

콜마당의 자기무력화 약속은 **세 겹**:

| 겹 | 위치 | 내용 |
|----|------|------|
| **1겹** | 정관 | 거래 수수료·광고·데이터 판매 수익 ❌ 명문화 |
| **2겹** | 약관 | 모든 사용자에게 동일 |
| **3겹** ★ | **코드** | 거래에서 수수료를 받는 *함수 자체가 부재*. 변경 시 OS 전체 재설계 필요 |

3겹째가 결정적. **약관은 바꿀 수 있지만, 코드는 회사의 정체성을 부정해야 바꿀 수 있다.** 위메프오·요기요·배민이 "수수료 인하" 약속하고 시장 점유 후 수수료 인상한 패턴을 *구조적으로* 막는다.

### 자본 진입 차단막

이 약속이 정관·코드로 보호되는 순간, **대기업이 같은 모델로 진입해도 동일한 자기무력화 약속을 못 한다** — 그들의 비즈니스가 그것을 허락하지 않기 때문. 콜마당의 자기무력화 약속 자체가 *거대 자본의 진입 차단막*.

## 6. 다음 단계 — 쿠폰앱 + 손님앱 + 배달 확장

### 6.1 쿠폰앱 (개발 진행 중)

- **귀속 노드를 *가게가 실제로 쓰는 도구*** — 가게가 직접 쿠폰 발행, 손님 휴대폰 안에서 결제까지 한 번에
- 양평 4개 MVP 위에 결합되는 다음 모듈
- 완성 예정: 약 6개월 내

### 6.2 손님앱 (코드 완성·배포 대기)

- QR 귀속 노드의 *손님 측 진입점*
- 가게 QR 스캔 → 앱 설치 → 영구 귀속
- 쿠폰앱과 결합하여 배포 예정

### 6.3 배달 — 확장 가능한 다음 응용 영역

- *현재 운영 ❌ / 코드 ❌ / 방향 ✅*
- 양평 4개 MVP가 검증한 OS 위에 *얹힐 수 있는* 영역
- 왜 배달이 첫 확장 영역인가:

| 이유 | 내용 |
|------|------|
| **출혈 최대 채널** | 지방 가게의 가장 큰 수수료 출혈 (매출의 6~12% + 배달료 + 광고비) |
| **가게 노드와 직접 연결** | 가게 = 호출 노드 + 쿠폰 발행 + 손님앱 거점 → 배달과 자연 결합 |
| **귀속 노드 가치 극대화** | 배달 손님 = 재주문 가능성 높음 = LTV 가게 자산화 가치 가장 큼 |
| **정부 정책 정합** | 공공배달앱 정책 + 소상공인 디지털 전환 + 지방소멸대응 모두 매칭 |

## 7. 왜 기존 도전들은 다 무너졌는가 — 실패 패턴 5종

| # | 실패 패턴 | 대표 사례 | 어떻게 무너졌나 | **콜마당 대응** |
|---|-----------|----------|---------------|--------------|
| **F1** | 의식 의존 | 협동조합 · 한살림 | 조합원 의식 의존 → 사람 바뀌면 무너짐 | 구조로 묶음 (코드·정관) |
| **F2** ★ | **보조금 의존** | 지역사랑상품권 · 공공배달앱(배달의명수·먹깨비) | 지자체 지원금 끊기면 사용량 즉시 폭락 | **구독료 = 자생 수익** |
| **F3** | 약속의 구조 부재 | 위메프오 · 요기요 · 배민 | 시장 점유 후 수수료 인상. 막을 장치가 *약관*뿐 | **자기무력화가 코드에 박힘** |
| **F4** | 단일 노드 한계 | 당근(중고) · 배민(배달) · 카카오T(택시) | 노드 1개에 묶임 → 슈퍼앱에 흡수 | **OS 모델** (다중 노드) |
| **F5** | 손님 데이터 플랫폼 귀속 | 카카오 단골 · 네이버 스마트플레이스 · 배민 사장님 광고 | 가게가 *채널 임대인*으로 전락 | **QR 귀속 노드** |

**가장 강한 대비 — F2 지역사랑상품권**: 전남 ○○사랑상품권도 동일 패턴. 지자체 충전 보조 100%·50%·0% 시점 사용액 비교 시 *자생 능력 부재*가 데이터로 즉시 드러남. 콜마당은 보조금 0에서도 6개월 운영 유지.

| # | 지방 정부가 원하는 것 | **콜마당이 해드릴 수 있는 것** |
|---|--------------------|----------------------------|
| **N1** | **지방 소멸 대응 가시적 성과** | 자본 유출 → 자본 잔류 전환. 시군 단위 *연 ○○억 지역 잔류* 데이터 산출 가능 |
| **N2** | **정부 예산 매칭 사업** | 지방소멸대응기금·소상공인 디지털 전환 등 5종 사업 매칭 (§10) |
| **N3** | **저비용 진입** | 시군 1곳 인큐베이션 모델. 시범사업 단위 예산 작게 진입 가능 |
| **N4** | **재현성 (다른 시군 이식)** | 양평에서 검증된 *표준 OS*. 시군 1곳 → 광역 복제 가능 |
| **N5** | **자생 모델 (보조금 없어도 유지)** | 구독료 = 유일 수입원. 보조금 0 가정 모델 (F2 회피) |
| **N6** | **소상공인 표심 / 지지 기반** | *수백~수천 가게가 동시에 무장* = 정치적 지지 기반 자연 형성 |
| **N7** | **언론·홍보 거리** | *전국 최초 무수수료 OS 시범 도입* 헤드라인 제공 |
| **N8** | **위험 회피 (실패해도 정치적 손해 없음)** | N=1 인큐베이션 = 작은 시범. 실패해도 작은 규모, 성공하면 큰 성과 |
| **N9** | **지역 일자리** | 모빌리티 서비스 제공자 + 가게 운영 인력 + 향후 배달 노드 |
| **N10** | **지자체와 영구 충돌 0** | 자기무력화 약속이 코드에 박힘 → 지자체가 *통제권 잃을 걱정 0* |

### 8.2 핵심 메시지

> **지방 정부가 원하는 10가지가 콜마당이 해드릴 수 있는 10가지와 정확히 일치한다.**
>
> 이는 우연이 아니라 *지방 정부의 needs를 역설계해서 만든 OS*이기 때문이다.

## 9. ★ 명백한 제안 — 시군 1곳 N=1 인큐베이션 시범사업

### 9.1 시범사업 개요

| 항목 | 내용 |
|------|------|
| **규모** | 시군 1곳 · 사무실 1곳 · 가게 50~100곳 · 서비스 제공자 10~20명 |
| **기간** | 6개월 시범 → 6개월 확장 검토 → 1년 후 광역 결정 |
| **지자체 부담** | 인프라 도입비 0 (콜마당 측 제공) · 마케팅 협력 (지자체 측) · 정부 사업 매칭 (양측 협력) |
| **시작 가능 시점** | 양평 검증 완료 + 쿠폰앱 완성 후 약 6개월 후 |
| **검증 지표** | ① 가게 등록 수 ② 거래 트랜잭션 ③ 자본 잔류 환산액 ④ 손님 LTV 귀속 데이터 |
| **종료 조건 (실패 시)** | 6개월 후 지표 미달 시 지자체 측 책임 0, 콜마당 측 철수 |

### 9.2 시범사업의 정치적 효과 (지자체 입장)

- **6개월 후 성과 보고**: *전국 최초 무수수료 동네 생활 OS 시범 도입* — 도지사·시장 임기 내 가시적 성과
- **언론 노출**: 우수사례 등재 가능 (지방소멸대응 모범사례 / 소상공인 디지털 전환 모범사례)
- **표심 기반**: 시범 시군 가게 100곳 + 가족 + 손님 = 즉각적 지지 기반 형성
- **실패 시**: 작은 규모 시범이라 정치적 손해 최소

### 9.3 콜마당 측이 약속하는 것 (명백히)

| ✅ 약속하는 것 | ❌ 약속하지 않는 것 |
|--------------|-----------------|
| 양평 6개월 검증 데이터 공유 | 시범사업 *즉시* 시작 (양평 완성 + 쿠폰앱 완성 후) |
| 양평 모델 표준 이식 | 광역 동시 진입 |
| 가게·서비스 제공자 교육 동행 | 지자체 보조금 의존 모델 |
| 정부 지원사업 매칭 컨설팅 | 지자체 측 큰 예산 부담 |
| 6개월 시범 데이터 정직한 공개 (성공·실패 모두) | 과장된 효과 약속 |
| 실패 시 철수 및 책임 명확화 | 영구 종속 모델 |

## 12. 마지막 — 우리가 약속하는 것 / 약속 안 하는 것

### ✅ 우리가 약속하는 것

1. **양평 6개월 검증 데이터의 정직한 공개** (성공·실패 모두)
2. **시범사업 진입 시점의 명백화** — 양평 + 쿠폰앱 완성 후 (~ 2027-05)
3. **시범사업 실패 시 철수와 책임 명확화** — 지자체 측 손실 최소화
4. **무수수료 약속의 코드 박힘** — 영원히 변하지 않음
5. **지자체와 영구 충돌 0** — 우리가 통제권을 잃게 만들지 않음

### ❌ 우리가 약속 안 하는 것

1. **즉시 시작** — 양평 완성 + 쿠폰앱 완성 후가 출발선
2. **광역 동시 진입** — 시군 1곳 N=1 인큐베이션부터
3. **과장된 효과 수치** — 시범사업 전까지는 모두 *가정·추정*
4. **정부 사업 *확정* 매칭** — 매칭 *가능성*만, 확정은 양측 협력 + 정부 심사
5. **지자체 큰 예산 부담** — 인프라 도입비 우리 측 부담 모델
6. **종속 모델** — 가게도, 서비스 제공자도, 지자체도 종속 0
