# PTT screen-off 송신 + 콜드스타트 — 결정 정리 (2026-06-02, 커밋 f52d0f56 이후 대화)

**관련**: [[ptt_implementation_2026-06-02]], [[ptt_volume_button_principle]]
**상태**: screen-off 송신 = **보류(데이터로 판단)**. 콜드스타트 = Doze 내재 특성, 배터리 예외가 레버.

## 1. screen-off 송신 — 어떤 트리거? → 보류

### 스코프 정정 (본인, 결정적)
- **일반기사 = 수신만** → 이미 화면 off에서 FCM wake로 작동, **설정 0**. PTT 가치의 대부분 이미 완성.
- **송수신 = 콜매니저(매니저) + 픽업기사 = 내부 직원 소수** → screen-off 송신은 *이들만* 필요.
- 내부 직원은 **개인 폰 + 내비 켜고 운전 중** 사용 (거치 전용폰 아님).
- → "수백 기사 보급 마찰"이 아니라 "내부 직원 몇 대"의 문제. 단 그래도 설정 부담은 남음.

### 트리거 옵션 (전부 흠 있음 — 공짜+확실+screen-off+명확한 건 없음)
| 옵션 | screen-off | 신뢰성(운전 중) | 설정 | 판정 |
|------|-----------|----------------|------|------|
| dispatchKeyEvent(현재) | ❌ foreground만 | — | 0 | 운전 중 무용 |
| **Accessibility**(볼륨키) | ✅ 전역 | 높음(내비 무관, 시스템 입력 후크) | **무거움**: Android13+ 사이드로드 "제한된 설정"+경고+배터리예외+삼성 재비활성. 본인도 헛갈림 | 확실하나 부담 |
| MediaSession(볼륨키) | △ | **낮음**: 내비/음악이 세션 뺏음 | 0 | 개인폰+내비라 **탈락** |
| 일반 BT 이어폰 버튼 | △ | 낮음·모호 | 페어링 | 볼륨→AVRCP→MediaSession 불안정 / 재생·통화 버튼→음악·전화·비서 충돌, 기종마다 다름 → **모호** |
| 전용 BT PTT 버튼(핸들 거치) | ✅ | 높음 | 페어링만 | 확실·무Accessibility, 단 **하드웨어 ~2~3만원/직원** |

### 결정: 보류 + 데이터로 판단
- **지금 Accessibility로 확정 안 함**(본인 의구심 타당: 소수라도 설정 부담 + 삼성 재비활성으로 조용히 고장 위험).
- 현재 빌드 = 수신 완성 + **foreground 볼륨키 송신**(정차·신호·대기 시 작동)으로 양평 실사용.
- **"달리는 중 송신이 정말 자주 막히나"를 데이터로 확인** → 송신이 주로 *정차·픽업지점·대기*에서면 현재로 충분. 막히는 게 실증되면 그때 **전용 BT 버튼 vs Accessibility(온보딩 1회 사무실 셋업)** 결정.
- 추론으로 어려운 길 미리 파지 않기.

## 2. 콜드스타트 — "잠긴 시간 길수록 연결 늘어남" 정체 + 대안

### 정체 = 수신측 Android Doze (함수 콜드 아님)
- 함수 콜드스타트는 **minInstances:1로 이미 제거**(웜 호출 ~0.4초).
- "잠긴 시간 길수록 늘어남"의 실체 = **수신측 Doze**: 폰이 오래 잠길수록 깊은 Doze → high-priority FCM wake + 프로세스 resume + Agora 재join 지연 증가.

### 대안
- **🔴 배터리 최적화 예외 허용** (`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 이미 *선언*됨, **허용은 1탭 시스템 다이얼로그** — Accessibility보다 훨씬 가벼움): 화이트리스트면 Doze에서도 high-priority FCM 지연↓. **가장 실효 레버.**
- 포그라운드 서비스(이미 가동): 프로세스 콜드 회피(Doze FCM 지연과는 별개 레이어).
- 워밍창 연장: 재-wake 자체 제거하나 always-in-channel **비용↑**(본인이 거부한 트레이드).

### ★ 이미 가려져 있음 (고장 아님)
- 2비프 설계상 매니저는 **항상 2차 비프(연결 완료) 후 발화** → 콜드가 늘어도 *비프가 조금 늦을 뿐 단어 유실 0*. 즉 **느림 체감이지 실패 아님.**
- 결론: **배터리 예외 허용**(가벼운 1탭)이 실효 대안. 완전 제거는 워밍=비용 트레이드. listener 최소화/Trigger Join 모델의 내재 특성.

## 3. 2비프 모델 (시간끌기 vs 확인용) + WiFi 관찰 + 음성 버퍼링 카드

### 2비프 — 두 모델 (본인 지적)
- **과거 의도 = 시간끌기(고정 박자)**: "삑—삑—(말해)" 고정 리듬으로 그 사이 연결 정상화. *예측 가능·근육기억*(안 듣고도). 단 연결이 박자보다 느리면 **첫 음절 유실**.
- **현재 = 확인용(가변)**: 2차 비프 = 실제 연결 완료(onUserJoined/즉시/타임아웃) 시점. **무유실**(진짜 준비 후만 발화). 단 **타이밍 들쭉**(웜 ~0.45초 / 콜드 ~1.4초 / Doze 더). "일정하게 안 울림"의 정체.
- 트레이드: 운전 UX엔 *예측 가능(고정)*이 유리하나, **현장 변동성(셀룰러+Doze)이 커서 고정은 더 자주 깨짐**(첫 음절 유실) → 현재 *무유실 확인 모델이 현장 안전*.

### WiFi 관찰 (본인) — 지금 빠른 건 best-case
- 테스트가 **같은 WiFi**라 빠름. 단 **Agora 음성은 P2P/LAN 직통이 아니라 클라우드 엣지 릴레이** → LAN 단축이 아니라 *양쪽 회선이 좋아서*(FCM·함수·Agora 도달 전부 신속).
- **현장 = 셀룰러+이동+다른 기지국+Doze** → FCM wake 등 더 느리고 *변동↑*. 지금 "굉장히 빠름"은 낙관치. → **비프 모델을 벤치 느낌으로 확정하지 말 것. 양평 셀룰러 데이터가 진짜 기준.**

### 3 옵션
1. **최소 바닥값**(1줄): 2차 비프에 floor(예 0.8초) → 웜 들쭉 제거·일관 바닥, 무유실 유지. 콜드만 늘어남.
2. **고정 박자 복원**: 변동성 잡은 뒤(배터리 예외+워밍) 고정 ~1초. 예측 최고, 단 드문 깊은 콜드 첫 메시지 잔여 유실.
3. **음성 버퍼링(완성형)**: 누르는 순간부터 마이크 로컬 버퍼 → 연결되면 흘려보냄. *talk-anytime + 무유실 + 일관*.

### 음성 버퍼링 — 비용·빌드·리스크 (본인 관심)
- **비용 = 거의 0**: 순전히 단말 로컬 버퍼. Agora 사용량 동일(언제 스트림 넣느냐만 바뀜).
- **빌드 = 중간(며칠)**: 현재 `publishMicrophoneTrack=true` 한 줄을 → 직접 마이크 캡처(`AudioRecord`)+링버퍼 + Agora **외부 오디오 소스**(`setExternalAudioSource`/`pushExternalAudioFrame`) + 상태머신(캡처→버퍼링→연결 후 비우기→실시간) + 포맷 정합(16kHz mono 등). 알려진 패턴이나 한 줄 아님.
- **★ 진짜 리스크 = AEC/노이즈억제**: Agora 내장 에코제거·노이즈억제는 *Agora 자기 마이크 캡처*에 적용. 외부 소스로 바꾸면 *그 처리를 잃을 수 있어* 운전 중 차소음·에코로 음질↓ → 외부 소스에 처리 켜기/자체 처리 + **음질 검증이 핵심**(버퍼링 자체보다 이게 일).
- **이득 영역 = 느린 콜드뿐**: 웜은 이미 즉시라 버퍼링 미미. 유휴 후 첫 메시지(콜드/Doze)에서만 빛남 — 근데 그건 현재 확인 비프가 *기다림으로 이미 무유실 처리*.

### 결정 (본인 2026-06-02): 현재 빌드로 써보고 판단
- 음성 버퍼링 = **좋은 완성형·비용0·빌드중간·AEC리스크. 단 이득영역 좁고 현재도 무유실 → 선제 빌드는 과투자.**
- **우선 현재 빌드(확인 모델) 그대로 양평 실사용** → ① 비프 들쭉/콜드 대기가 *실제로 거슬리나* ② 배터리 예외로 Doze 줄면 충분한가 데이터 확인.
- 거슬리는 게 실증되면 → **① 최소 바닥값(즉시·1줄) → 부족하면 ③ 음성 버퍼링(며칠·저비용·AEC 검증)**. 고정 박자(②)는 현장 변동성 때문에 비권장.
