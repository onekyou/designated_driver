# 사용자 행동 최소 = 콜마당 OS 제1원칙

**확정**: 2026-05-25 (본인 명시 결정)
**적용 범위**: 콜마당 OS 전체 (쿠폰앱·콜마당 대리·콜마당 픽업·식당앱·미래 모듈)

## 한 줄

모든 트랙·모든 사용자 그룹의 *행동 단위*를 0에 수렴시킨다. 이 원칙을 통과하지 못한 기능은 진입 금지.

## 사용자 그룹별 행동 한계 (위반선)

| 트랙 | 사용자 그룹 | 행동 한계 | 위반 예시 |
|------|------------|----------|----------|
| 쿠폰앱 | 손님 | 0클릭 (QR → 자동 적용) | 가입·약관·로그인 화면 |
| 콜마당 | **매니저** | 클릭 1 + 발화 ≤2단어 | 콜 카드 수기 입력, STT 화면 검토 |
| 콜마당 | 기사 | 운전 중 0액션 (음성 수신만) | 잠금화면 수동 해제 후 조작 |
| 콜마당 | 손님 | 전화 1회 (기존 행동 그대로) | 앱 설치 강요, 위치 입력 |
| 식당앱 | 식당 사장 | 콜 단발 버튼 1클릭 | 다이얼로그 다단계 |
| 픽업 | 픽업기사 | 콜 카드 1클릭 | 다단계 입력 |

## 결정 도구 (매 기능 진입 전 통과 질문 4개)

1. 이 기능이 *어느 사용자 그룹의 행동*을 늘리는가?
2. 그 그룹의 행동 한계(위 표)를 넘는가?
3. 넘는다면 *대체 자리*가 있는가? — 시스템 자동 / 다른 그룹 위임 / 발화 1단계로 압축
4. 통과 못 하면 **기능 자체 폐기** 또는 재설계 (다듬기 X)

## 위반 처리 우선순위

기능을 다듬어 행동을 줄이는 것 (재설계)보다 **기능 자체 폐기 + 다른 그룹에 위임**이 우선.
콜마당 매니저 콜 카드 작성 → 폐기 후 기사에게 위임이 본 패턴.

## 위반 신호 (회피 트리거)

다음 발화·행동이 관측되면 본 원칙 위반 확정:
- 사용자가 "어렵다" / "익숙해지는데 시간 걸린다" / "기존 시스템으로 회귀했다"
- 신규 도구 제공해도 *안 쓰려고 함* (양평 매니저 STT 거부 사례)
- 신규 도구 도입 후 *옛 도구 병행 사용* (단순화 실패 신호)

## 결정 트레일 (본 원칙이 좁힌 자리)

- **2026-05-25 콜마당 PTT 진입 검토** — 매니저 콜 카드 수기 입력이 원칙 위반 → 회귀 원인 확정 → STT 부분 위반(화면 검토 요구) → **PTT(Trigger Join) 유일한 정합 도구**로 좁혀짐. 발신번호 자동 매칭 시 발화 ≤1단어("가") 압축 가능
- **2026-05-25 콜 카드 작성자 매니저→기사 전환** — 매니저 콜 카드 미터치, 기사가 손님 통화로 직접 채움. 공유콜·손님콜과 동일 구조
- **2026-05-19 쿠폰앱 우선 결정** — 쿠폰앱이 손님 0클릭 설계로 이미 본 원칙 정합 (그래서 우선)
- **2026-05-25 콜 브로커 식당 영업 협상 카드 재정의** — 식당 사장 1클릭 콜 단발이 영업 멘트 1단의 핵심

## 본 원칙이 차단해야 하는 사고 패턴

- "기능 추가하면 사용자가 익숙해질 거야" — 사용자는 *익숙해지지 않음*. 회귀 데이터로 입증
- "UI 다듬으면 행동 줄어들 거야" — 행동 단위가 변하지 않으면 같은 회귀
- "교육·매뉴얼·튜토리얼로 해결" — 본 원칙이 정의상 *교육 0*
