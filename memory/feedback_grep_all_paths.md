# 수정 전 필수 절차 (반복 실수 방지)

**규칙**: 기능 수정 시 해당 기능의 모든 진입 경로를 Grep으로 먼저 찾을 것. 각 경로의 코드를 읽은 후에만 수정 계획을 세울 것.

**Why**:
- 한 경로만 보고 "이게 원인이다"라고 단정하면 반드시 빠뜨리는 경로가 생김
- 예: 같은 팝업을 여러 FCM 핸들러/리스너/showDialog 호출이 모두 트리거할 수 있음
- 추측 기반 수정은 엣지 케이스에서 실패하고, 사용자가 재보고해야 함

**How to apply**:
- 기능 수정 요청을 받으면 우선 해당 기능을 트리거하는 **모든 StateFlow/변수/함수**를 Grep
- 예시 1: 팝업 수정 → `_showNewCallPopup.value = true`를 전체 Grep → 리스너, FCM 핸들러, showCallDialog 등 모든 경로 확인
- 예시 2: 상태 변경 수정 → 해당 StateFlow를 설정하는 모든 위치 Grep
- 각 경로를 `Read`로 확인한 뒤에 비로소 수정 계획 수립
- 플랜모드에서 Grep 결과와 읽은 코드를 사용자에게 보고하고 승인 받기
